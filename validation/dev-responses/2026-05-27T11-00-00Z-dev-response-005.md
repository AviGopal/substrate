## F-111 closure (ias-executor-ts local commit `b6b58a2`)

**Audit's framing (recurring):**

> dist/ is the runtime artifact, NOT src/. Container's src/ files may be stale. Always audit via `docker exec substrate-live grep ... /vessels/ias-executor-ts/dist/...`.

The substrate-live container at `/vessels/ias-executor-ts/dist/` is what runs the engine. Devs edit `repos/ias-executor-ts/src/` in the workspace. After each src change, the dist needs to be rebuilt AND deployed via `docker cp`. Forget that step → container drifts from src → auditor reads stale dist → audit findings reference behavior that no longer matches the committed code.

**The script (`scripts/verify-dist-fresh.ts`):**

1. Runs `bun run build` locally → fresh dist/ from current src/
2. Computes sha256 of every `dist/**.{js,d.ts}` file
3. Reads `/vessels/ias-executor-ts/dist/` from the substrate container via `docker exec cat`, hashes the same files there
4. Diffs. STALE / MISSING reported with exit code 1 + remediation command

**Exit semantics:**
- `0` — container dist matches local build (audit-clean)
- `1` — drift detected (operator runs `docker cp dist/. substrate-live:/vessels/ias-executor-ts/dist/` then restarts goal-host-vessel)
- `2` — script error (build failed, container unreachable)

**Env-var overrides** for non-default substrates:
- `IAS_CONTAINER` (default `substrate-live`)
- `IAS_CONTAINER_PATH` (default `/vessels/ias-executor-ts/dist`)

**Self-test during development of this script:**

The script detected real drift in two passes:
1. First pass: local dist had a stray `dist/src/` nested directory from an earlier botched rebuild. The script reported 160+ MISSING files — confirming the detector works.
2. After cleanup + clean rebuild: container also had small diffs from the engine.js I'd deployed earlier (poll-and-wait change from iter 11) with test-marker residue. Cleaned src + rebuilt + re-verified: **OK — container substrate-live dist/ matches local src/**.

Now wired into `package.json` as `dist:check`:
```

```
