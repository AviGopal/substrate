## Implementation

Followed inv-030's design with one simplification: the projection logic is implemented **inline** in the existing `/v2/activities/templates/:id/promote` endpoint rather than as a separate 6-task activity. The audit's §5 design described the activity-template form as "load-bearing artifact" but the deterministic logic compiles to a few in-process operations. A future iteration can lift the inline logic into the formal activity template if calibration or observability needs warrant it.

### Pipeline (in `/promote` handler, after the iter-14 hallucinated-resolver check)

1. Read proposed template's `input_shapes` + `output_shapes` (already fetched).
2. Two parallel SurrealDB queries:
   - `activity` rows with `proposed=false AND retired=false` for shapes
   - `variant_performance_metrics` rows with `total_executions > 0` for posteriors
   Join in app code by template id (SurrealDB v3 grammar doesn't support multi-table aliased FROM).
3. Compute Jaccard similarity per candidate against probe shapes; drop similarity=0 or sample_count=0; sort desc; take K=5.
4. Weighted Beta-Binomial projection with Jeffreys-baseline stripping:
   ```
   α̂ = 1 + Σᵢ wᵢ(αᵢ-1) / Σᵢ wᵢ
   β̂ = 1 + Σᵢ wᵢ(βᵢ-1) / Σᵢ wᵢ
   ```
   weighted by similarity. The −1 strips the per-template Beta(1,1) prior (averaging evidence, not double-counted priors); the +1 re-introduces a single Jeffreys baseline.
5. Decide:
   - K=0 → refuse with `reason: "cold_start_no_similar"`
   - `total_samples < 10` → refuse `insufficient_neighbor_evidence`
   - `mean < 0.6` → refuse `projected_mean_below_threshold`
   - otherwise → proceed with existing promotion path
6. Refusal hits both bus (`intervention.refused`) and durable store (`refusal_events`) reusing iter 8 + iter 13 infrastructure.

### Configurable (audit defaults)

| Env var | Default | Audit recommendation |
|---|---|---|
| `PROMOTE_GATE_K` | 5 | §2 K=5 highest-similarity templates |
| `PROMOTE_GATE_THRESHOLD_MEAN` | 0.6 | §4 (not ribosome's 0.7 — gates measure different things) |
| `PROMOTE_GATE_THRESHOLD_SAMPLES` | 10 | §4 prevents promoting on K templates each at Beta(1,1) |
| `PROMOTE_GATE_DISABLED` | false | Shadow-mode tuning (§calibration) — when "true", gate bypasses but emits decision impulses for post-hoc evaluation |
