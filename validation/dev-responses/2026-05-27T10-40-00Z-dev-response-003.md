## Implementation (concept-db commit `c5065cf`)

**Audit's framing:**

> `repos/concept-db/src/lifecycle/dispatcher.ts:34-97` is an in-process EventEmitter with no broadcast transport. Events fire and reach in-process subscribers only. By the neutral-emitter principle, every vessel that emits a domain event should put it on a channel any other vessel can subscribe to. Today these events are trapped.

**Fix shipped:**

1. **New module `src/lifecycle/bus.ts`**: `publishConceptEvent()` helper. Fire-and-forget HTTP POST to `${ACTIVITY_API_*}/v2/events/publish`. 2-second timeout. One-log-per-outage suppression. Reads env at each call (so tests can override at runtime).

2. **Event-name mapping** — 3-segment form so subscribers can filter on `concept_db.*` prefix:
   ```
   concept:created   → concept_db.concept.created
   concept:resolved  → concept_db.concept.resolved
   concept:updated   → concept_db.concept.updated
   concept:deleted   → concept_db.concept.deleted
   edge:created      → concept_db.edge.created
   edge:updated      → concept_db.edge.updated
   edge:deleted      → concept_db.edge.deleted
   impulse:created   → concept_db.impulse.created
   impulse:resolved  → concept_db.impulse.resolved
   impulse:expired   → concept_db.impulse.expired
   ```

3. **`dispatcher.ts:emit()` extended** — bus publish always runs (even when no in-process handlers registered), then dispatches to in-process handlers. The neutral-emitter principle: a substrate subscriber may be listening even when no in-process handler is.

4. **Env-var handling**: accepts both `ACTIVITY_API_ENDPOINT` (other substrate vessels) and `ACTIVITY_API_URL` (concept-db's own systemd unit). Same target either way.

5. **Tests**: 4/4 pass. Event-type mapping correctness + integration test with mocked fetch showing both in-process AND bus dispatch fire on `emit()` with and without in-process handlers registered.
