| Iter | Change | Gate kept |

Each iteration made the `/promote` endpoint smarter. None of them removed the requirement that an operator actually call it. The substrate could not promote its own templates regardless of how much evidence it accumulated — that is the operator gate.

For lift (S2→S3), the substrate must demonstrate template usefulness without operator involvement. That means:

1. Substrate writes a proposed template (ribosome / make-activity)
2. Substrate selects it for real execution and accumulates real evidence
3. Substrate promotes it based on its own empirical evidence
4. Operator never touches the loop

Step 2 was blocked (proposed=true excluded from Thompson). Step 3 was blocked (only `/promote` endpoint existed).

## What shipped (commit `d258ffe` on metabob-activity-api)

**Change 1 — recommend: proposed templates enter the exploration pool.**

```diff
- if (template.proposed === true) {
-   ... return false;  // selection-invisible until operator promotes
- }
+ // Proposed templates flow into the EXPLORATION pool only — never
+ // exploitation regardless of sample count.
```

The exploitationPool partition now excludes `_proposed === true` explicitly:
```typescript
explorationPool: c._proposed === true || c._total_executions < min_observations_threshold
exploitationPool: c._proposed !== true && c._total_executions >= min_observations_threshold
```

Surfaces `selection_metadata.proposed_template: true` on traces of proposed-template selections so consumers know.

**Change 2 — POST /v2/activities/templates/auto-promote** (substrate-internal).

Body: `{ min_samples?: 20, min_success_rate?: 0.6, dry_run?: false }`

Pipeline:
1. SELECT all `proposed=true AND retired=false` activity rows
2. JOIN with `variant_performance_metrics` by template_id (one batch query, app-side merge)
3. For each: strip Beta(1,1) prior → `empirical_samples = (α-1) + (β-1)`, `empirical_mean = (α-1)/empirical_samples`
4. Promote if `empirical_samples ≥ min_samples AND empirical_mean ≥ min_success_rate`
5. Emit `template.auto_promoted` event + write `promote_gate_evaluations` row (reason=`auto_promote`)

This endpoint is designed to be called by the substrate itself (boredom-vessel goal rotation or substrate cron — follow-up). The operator does not need to invoke it.

**The manual `/promote` endpoint stays** as a safety surface for operator-authored templates with no execution history (where the projection from neighbors is the only available signal). The autonomous lift loop does not depend on it.

## What this doesn't (yet) do

1. **The auto-promote endpoint isn't auto-called yet.** It exists, it works on demand. Wiring boredom-vessel or systemd to invoke it periodically is a small follow-up. Until then, the operator (or any client) calling it once produces deterministic results — but that's not the lift property; the lift property is having a substrate-side scheduler invoke it.

2. **Real proposed templates aren't accumulating evidence yet** because ribosome's `applyExtraction` is `false` by default (per inv-027). The 6 existing proposed templates are operator-authored test artifacts. The end-to-end demonstration of substrate-authored usefulness requires either flipping ribosome to apply or accepting that make-activity's outputs (when they land) will be the input to this loop.

These are both small follow-ups. The structural gate is removed.
