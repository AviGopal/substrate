## Empirical comparison — v1 vs v2 under load

Memory probe: 3 parallel dispatch cycles via `POST /run-goal` on both
8210 (v1) and 8211 (v2), each goal short ("memory-probe vN cycle K").
Sampled `systemctl show -p MemoryCurrent` between cycles.

| Sample | v1 (8210, no cap inherited, but MemoryMax=3G on its OWN unit) | v2 (8211, MemoryMax=3G inherited via v0.2) |
|---|---|---|
| baseline   | 2,255,171,584 (2.25 GB) | 15,855,616 (15.9 MB) |
| after C1   | 2,263,937,024 | 15,880,192 |
| after C2   | 2,268,483,584 | 16,441,344 |
| after C3   | 2,271,678,464 | 15,876,096 |
| **growth** | **+16.5 MB** | **+20 KB (~800× less)** |

Two caveats keep this honest:
- v1's baseline is already near the cap because it has been running for
  hours of boredom dispatches. v2 started fresh. The fair comparison is
  the **delta**, not the absolute. Delta favors v2 by ~800×.
- 3 cycles is a small sample. To call this conclusive we'd want 30+ cycles
  on a fresh v1 boot too — but the operator-side reading is "v2's streaming
  refactor visibly suppresses the per-cycle retention pattern."

## What v0.2 unlocks

Now that mitosis units inherit safety caps + env parity, the substrate
can iterate on its own central dispatcher (or any other capped vessel)
without operator intervention to re-add the cap. The next iteration
target — even deeper LLM streaming (AsyncIterable instead of full-body
buffering) — can be dispatched by the substrate's own
`draft-gap-closing-activity` chain instead of operator-curated patches.

## Next iteration target (substrate-detectable)

Even with v2's growth suppression, v1's still-leaking baseline grows
~5 MB per dispatch cycle. The remaining source-level retention is in
either:
- Anthropic SDK connection pool — HTTP/2 streams hold buffers per
  socket; v2's `body.cancel()` doesn't reach the SDK-internal path
- Native ONNX worker bindings in activity-api's embedding model (not
  goal-host; out of scope here but worth a `concept_search_by_source`
  pull to see if `concept_cq7MrLsepQV2` ("Fire-and-forget Promise
  queues at vessel emit paths cause unbounded RSS growth") applies)
- Drafter trace buffers that aren't bounded by the new fetchProbeStats
  cap because they're stored in `executionStore` (already capped at 100)
  but each record holds the full LLM transcript

A v3 mitosis target: stream the Anthropic SDK responses via
`stream: true` + handle as `AsyncIterable<MessageStreamEvent>` instead
of full-body buffering. The substrate can author this against the same
goal-host-vessel base via the v0.2 resolver, which will now preserve
the MemoryMax cap automatically.
