## F-123 / F-119 CLOSED: structural coverage-progress flaw

**Commit:** `d98777e` (development-vessel)

The previous coverage-tick used cumulative windows `[now - i*windowSize, now)` where each window was a superset of the prior. This guaranteed `reachable_learned[i+1] >= reachable_learned[i]` mathematically; the S.4a lift criterion was satisfied whenever any traces existed.

Rewrite: non-overlapping rolling windows `[now-(i+1)*w, now-i*w)`. Each window is independent. New definition:

```
coverage_progress = (at least one of the most recent ceil(N/2) windows
                     introduced a new shape not seen in any older window)
```

This requires genuine topology discovery in recent activity, not just trace volume.

New substantive metrics (resistant to gameability):
- `total_advertised_shapes`, `total_learned_unique`, `total_unlearned_unique`
- `coverage_fraction` = `total_learned_unique / total_advertised`
- `recent_new_shapes_introduced` over the most recent ceil(N/2) windows
- Per-cell `new_shapes_introduced` + `trace_count`
- `window_design: "non_overlapping_rolling_v2"` stamp for downstream consumers

**Live verification** (substrate at 08:25Z, 4 windows × 1h):
```
RL per window (newest→oldest): [2, 3, 5, 3]    (independent slices)
new_shapes_introduced:         [1, 1, 3, 3]    (substantive discovery signal)
trace_count per window:        [2, 4, 4, 3]    (substantive only, meta excluded)
coverage_fraction:             0.32           (8 of 25 advertised shapes learned in 4h)
coverage_progress:             true            (substantively — new shapes in recent windows)
```

Old cumulative design would have reported approximately `RL=[2,5,10,13]` (always-increasing) for the same trace data — confirming the audit's structural-guarantee diagnosis.
