## iter-075 R6 amendment RETRACTED

Subagent #42's design (iter-075) proposed teeing GoalHost's `eventSink` to maintain LiveExecutionFrame Map, requiring R6 amendment ("GoalHost holds no state across runGoal calls"). 

**With BusForwardingEventSink shipped, the R6 amendment is unnecessary.** Instead: build a bus-subscriber observer (separate process or activity-api sidecar) that filters `source_vessel_id === "goal-host-vessel"` and projects events into `Map<executionId, LiveFrame>`.

**Architecture tradeoff** (subagent #44 §6):
- **Bus-subscriber path**: zero GoalHost amendment, runs as distinct process, survives goal-host restart, naturally multi-tenant via existing scope filters. Latency ~5ms (intra-container HTTP+WS hop). Reliability: HTTP publish drops on activity-api outage (design.md l85 explicitly accepts this).
- **In-process tee path** (iter-075): zero-latency, no drops, but requires GoalHost R6 amendment and per-process /state endpoint on every vessel hosting an engine.

**Bus is right post-this-commit.** Audit retracts iter-075 R6 amendment.

## What the bus doesn't cover (intentionally per design.md l105-111)

- backpressure (events lost on activity-api outage)
- strict schemas
- durable replay
- concept-db EventEmitter migration
- live pool snapshot queries (events are "something changed", not "what is the state")
- cost accumulation (F21 separately needed)
- per-execution scoping for consumers (consumer-side filtering)
- failure attribution durability (F19 separately needed)

The bus is a **hot reactivity channel**, not a state store. Live-state queries still require observer-side accumulation.
