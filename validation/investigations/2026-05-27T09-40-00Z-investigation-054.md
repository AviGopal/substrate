## Implementation

### `BusForwardingEventSink` (`ias-executor-ts` commit `161eede`)

EventSink adapter that wraps an inner sink:
- Inner sink called first, synchronously — preserves all existing in-process subscribers
- HTTP forwarding to `POST {activityApi}/v2/events/publish` fire-and-forget (no `await`)
- 2-second `AbortSignal` timeout
- Errors logged via `console.warn` once per outage window (suppressed thereafter)

**Event-name mapping** (replace `:` with `.`, camelCase → snake_case):
```
lifecycle:task:preBinding       → lifecycle.task.pre_binding
lifecycle:task:completed        → lifecycle.task.completed
lifecycle:execution:succeeded   → lifecycle.execution.succeeded
lifecycle:execution:failed      → lifecycle.execution.failed
lifecycle:gap:classified        → lifecycle.gap.classified
lifecycle:llm:dispatched        → lifecycle.llm.dispatched
```

Published payload preserves `original_event_type` and `emitted_at_ms` in `data` so subscribers can correlate to in-process logs.

**Tests:** 10/10 pass — mapping rules (lifecycle:task:preBinding → lifecycle.task.pre_binding, already-dotted preservation, dotted-camelCase, single-segment), inner-sink-first ordering, fire-and-forget failure semantics, inner-throw propagation (terminal per EventSink contract), outage suppression (3 emits during outage = 1 log), auth header inclusion.
