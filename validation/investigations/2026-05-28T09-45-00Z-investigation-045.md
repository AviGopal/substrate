## The pattern

Every operator-floor primitive in this stack is a **new sensory channel** — a way for the substrate to see something currently invisible:
- semantic-mismatch (iter-042)
- signature-drift (Finding 8)
- silent-UPDATE-failure (Finding 9)
- discipline-violation (Finding 10)
- resolver-validity (Finding 11a)

In each case, once the observability is shipped, the corrective activity is **substrate-authorable** through existing primitives (lifecycle bus, `activityTemplate_write`, impulse-resolve dispatch). The substrate has the hands; it lacks the eyes.

This re-frames iter-039's "structural floor" claim. The floor isn't "operator-authored behaviors." It's **operator-defined invariants + their detectors**. Once invariants are nameable and observable, the substrate handles correction.

## The abstraction question

Should there be a single `policyViolation` / `invariantBreach` impulse shape that any operator-defined invariant emits into?

Sketch:
```
shape: invariantBreach
body: {
  invariant_id: string,           // e.g. "iter-028-a/proposed-on-substrate-authored"
  observed_violation: { ... },    // shape-specific evidence
  detected_at: timestamp,
  detector_activity_id: string,   // which activity observed it
  recommended_fix_shape: string,  // shape the corrective activity should produce
  severity: "low" | "medium" | "high"
}
```

Operator's work per new invariant: **(1) name the invariant + (2) author a detector activity that emits `invariantBreach`**. Everything downstream — gap-closer dispatch, corrective-template authoring, V_X verification — is substrate-handled.

Today's stack collapses:
- Finding 10 → operator authors `discipline-violation-detector` emitting `invariantBreach{invariant_id: "iter-028-a/..."}`. Substrate authors enforcer activity via existing make-activity chain.
- Finding 8 → operator authors `signature-presence-detector` emitting `invariantBreach{invariant_id: "phase-24/signature-on-success-traces"}`. Substrate cannot author the FIX (TranslatingTraceSink is across the operator-floor) but it can author **escalation activities** that notify operator of the breach pattern.
- iter-042 mismatch-detect → IS an invariantBreach detector for invariant "operator-goal-text should route to a template with overlapping output_shapes."

The pattern unifies: detectors emit `invariantBreach`; corrective activities consume it. Some breaches are substrate-fixable (Finding 10), some are not (Finding 8). The shape is the same; the corrective-authoring-feasibility varies.
