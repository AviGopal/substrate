## F-129 (NEW, MEDIUM): goal-host proxy registration race on vessel restart

**Discovered during F-126 deployment verification.**

When `development-vessel` restarts, `goal-host-vessel` does not automatically re-register its proxy resolvers. The proxy registration only runs at goal-host startup (`repos/goal-host-vessel/src/index.ts:190` — fetch `/shapes` once and register N resolvers). If goal-host happens to restart while dev-vessel is still coming up, the registration fails silently with:

```
[goal-host-vessel] failed to register dev-vessel proxies: Unable to connect.
```

Result: **zero proxy resolvers registered**. All goals routing to dev-vessel shapes fail. Workaround during this iteration: manually restart goal-host after dev-vessel comes up.

**Recommended fixes** (in increasing rigor):
1. systemd `After=development-vessel.service` + `Wants=development-vessel.service` on goal-host unit
2. goal-host retry-with-backoff on initial proxy registration failure
3. goal-host re-registers proxies periodically (every 60s) OR subscribes to discovery-vessel registration changes (the right answer per neutral-emitter principle, ties to iter008 finding)

This is exactly the kind of brittle coupling the iter008 audit's neutral-emitter principle would prevent: if `discovery-vessel` broadcast registration-change events on a neutral bus, goal-host would re-register proxies reactively without any restart sequencing.

**Status: OPEN MEDIUM**

## iter008 audit (investigation-026) ACK: neutral-emitter principle

The audit's correction-grade finding stands: every lifecycle event in the substrate should be on a neutral broadcast channel. Today:
- `concept-db` internal lifecycle events trap inside an in-process EventEmitter
- `lifecycle:task:preBinding/completed/execution:succeeded` flow on a workbench-coupled channel; concept-db cannot subscribe

This is a substrate-spanning architectural change that warrants its own openspec change. Not addressed this iteration; logged as a substrate-direction item.

The F-129 finding above is concrete evidence of the same architectural defect: goal-host's proxy registration is a one-shot fetch from dev-vessel, not a reactive subscription to a discovery-vessel event channel. The neutral-emitter fix would dissolve both the iter008 finding AND F-129.

**Recommendation:** spec proposal `openspec/changes/2026-05-27-neutral-emitter-lifecycle-bus/` to consolidate every lifecycle event onto a single broadcast channel any vessel can subscribe to. Deferred to next operator-prioritized iteration since it's architectural rather than fix-a-bug.
