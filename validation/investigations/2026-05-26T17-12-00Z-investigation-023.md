## Detection rule sketch (executor-local, before dispatch)

```
1. task.resolver in runtime.resolvers?
   no  → in attachedVessels?
           yes → missing-vessel-attachment, retry via passthrough (NOT a gap escalation)
           no  → missing-resolver, ESCALATE
   yes → continue

2. declared input shapes ⊆ pool.shapes?
   no  → backward-producer query for missing shape:
           ≥1 hit → missing-shape-in-pool (compositional)
           0 hits → primitive-shape
   yes → continue

3. ≥2 producers AND Thompson margin < ε?
   yes → shape-ambiguity, defer to slot-binding (NOT a gap escalation)
   no  → run resolver

4. After resolver returns:
   empty output OR verifier_negative → synthesis-failure (post-hoc gap)
   ok                                → continue task loop

ORTHOGONAL: at every step, if compositionChain.length ≥ cap → scope-exhaustion
```

## Forge-vs-dispatch-vs-HITL — sharpened decision rule

My hypothesis from the brief ("repeated `create-shape-provider-goal` failure → escalate to forge") was *direction-correct but blunt*. The subagent's sharper formulation: **the *type* of failure in the sub-goal cascade is the signal, not the count.**

| Sub-goal cascade failure type | Right next step | Why |
|------------------------------|-----------------|-----|
| `primitive-shape` (cascade bottoms out, no producer anywhere) | **Forge** | Registry is genuinely incomplete; sub-goal can't compose what isn't there |
| `missing-resolver` (same resolver, repeatedly absent) | **Forge** | Registry-incompleteness on a resolver named in a template |
| `synthesis-failure` (LLM/validator refuses with adequate inputs) | **HITL or single re-prompt with richer context** | Forge gives new capability, not better judgment — wrong tool |
| `missing-shape-in-pool` (producers exist, sequence is novel) | **Dispatch `create-shape-provider-goal`** with candidate set as hint | This is the in-band path it was built for |
| `shape-ambiguity` | **Slot-binding / Thompson** | Not a gap; producer-selection problem |

**Forge gating conditions** (all required):

- `primitive-shape` (no producer in registry)
- Shape requested ≥k times across recent traces (default k=3; filters typos and one-shot probes)
- Within per-day forge budget AND per-shape limit of 1 (don't forge same primitive twice)
- Concept-db has *some* prior on this shape: `description_of` or partial `resolver_pattern` (a documented-but-unimplemented capability). If concept-db is fully empty for this shape, **HITL is safer** — forging blindly grows surface area without prior.
- Originating goal's `endpoint_output_shapes` covers the proposed forge output (CC1 sub-goal scope narrowing applies to forge identically to dispatch).

**The S2→S3 push-away in this domain:** the substrate refuses to forge for itself with cited evidence (e.g., "shape requested once by a single boredom tick, no concept-db prior; declining"). The refusal IS the gap-closing decision — not a failure.

## Concept-db as conditioning gate

Concept-db role on the forge decision:
- `resolver_pattern` returning a sequence → **dispatch with that sequence as a hint** (the playbook *is* the answer; retrieve, don't author).
- `description_of` covering the shape but no `resolver_pattern` → **strong forge signal** (documented capability, unimplemented).
- Both empty → **HITL safer than forge** (no prior to ground the new vessel's design).

This is the operationalization of subagent #2's "concept-db as conditioning layer" framing on a specific, in-time decision.

## Cheapest distinguishing experiment

The subagent's closing recommendation, which I endorse as the next concrete audit observation: **emit a `gap.classified` lifecycle event for every detected gap, classifying into the seven types — but keep the executor's response unchanged.**

- **If `missing-shape-in-pool` (compositional) dominates** → richer in-band detection (better dispatch hints, Thompson conditioning on candidate set) is the load-bearing lever. Forge stays cold.

The experiment is free of new resolvers, free of new shapes, free of new vessels — pure classification on signals the executor *already* computes for `preBinding`.
