## §1 — What already exists vs what's missing

**Closest existing primitive**: `regression_vs_previous` inside `heldOutEvalReport` (`openspec/changes/2026-05-23-lift-criterion-hardening/design.md:34`). This is a single scalar diff (`pass_rate − previous_pass_rate`) computed inline by `held-out-eval-tick`. Plus `ciAgreementReport` (`:131`) and `adversarialProbeReport` (`:76`) — both carry counters but no cross-cycle deltas.

**None of these is a general per-cycle comparator for the three boredom tops.** They are tick-emitted reports that bake one delta scalar into one field of one body. The three boredom-top resolvers themselves (`coverage-tick.ts`, `substrate-health-tick.ts`, the matrix-score path) are **stateless w.r.t. prior cycles** — each tick emits a fresh report independent of the prior emission.

`coverage-tick.ts:8-37`'s `num_windows` parameter is intra-tick temporal slicing, not cycle-to-cycle. `registry-change-observer.ts:60-67` fires aggregators on `lifecycle:execution:succeeded` with debounce but does not correlate consecutive emissions. `validation/results/` accumulates harness JSONs per day (line 26) with no comparator.

**Conclusion**: the design is best framed as **generalization of the existing `regression_vs_previous` scalar** + extension of iter-031's "gap-catalog subscriber" pattern — not novel authoring.

## §2 — Three sibling activities, not one branching

The three output schemas (`coverageReport`, `substrateHealthReport`, harness-matrix JSON) share zero structure. A unified activity would dispatch into three branches that share zero code. Three siblings:

- `narrate-matrix-cycle-delta` — subscribes to `lifecycle:execution:succeeded` filtered to `harness-run-matrix`
- `narrate-health-cycle-delta` — filtered to `substrate-health-tick`
- `narrate-scenario-cycle-delta` — filtered to `harness-check-scenario`

Each sibling: 3 tasks — `fetch_prior_execution` (activity-api query for limit=2), `compute_delta` (typed resolver per template), `emit_narration` (`cycleDeltaNarration` write). Observer hook reuses `registry-change-observer.ts:316-365` pattern.

**Why siblings**: lets promote-gate (iter-030) admit them one at a time; Thompson posterior tunes per-template (matrix narrations may be silent for weeks while health narrations fire every cycle — different α/β trajectories).

## §3 — The `cycleDeltaNarration` shape contract

```
{
  template_id: string
  current_execution_id: string
  prior_execution_id: string
  delta_summary: string                          // human/LLM-consumable
  changed_fields: Array<{
    field: string
    prior: any
    current: any
    threshold_source?: "static_config" | "learned_v1"
  }>
  significance: "noise" | "expected_drift" | "regression" | "progress"
  composability: array<string>                   // refs to substrateGap/memoryNote
}
```

**`significance` is the load-bearing field.** Four-value enum, each meaningfully distinct:
- `noise` — sub-threshold; activity emits but downstream ignores
- `expected_drift` — operator-anticipated motion (harness rotated probes, metric ticks naturally)
- `regression` — triggers iter-031's gap-detector path
- `progress` — positive narration that promote-gate (iter-030) can use as evidence

Without this enum, the activity emits a per-cycle stream of "something changed" with no filter, defeating its own purpose.

**No new shape beyond `cycleDeltaNarration`.** All resolvers used exist in `goal-host.ts:598-673`.

## §6 — Adversarial considerations

| Surface | Failure mode | Mitigation in V0 |
|---------|--------------|-----------------|
| False-positive | Time-monotonic fields (`generated_at`, `created_at`, `execution_id`) trivially differ every cycle | `ignored_fields` set per template, declared in template config; without this, every narration reports motion |
| False-negative | Structurally-identical outputs with semantic divergence (e.g., `reachable_learned=42` two cycles but the *set* of learned templates rotated by 5) | Compare *sets* not *counts* where shape carries set fields; spec comparator at field-level granularity |
| Goodhart | LLM-summary learns to overclaim regressions because narration α increases on regression emissions | Closer must verify the regression; if its memoryNote gets pruned by promote-gate, narration's α decreases. **Credit loop terminates in operator-validated value, not narration-emission count.** |

## §7 — Threshold learning path

## The single most likely failure mode to adversarially test once V0 ships

**`significance=expected_drift` monoculture.** Threshold table initially conservative → activity emits `expected_drift` for everything that isn't a literal field-equality flip → activity runs silently for cycles while real regressions accumulate under the noise floor → **false-negative monoculture, invisible by construction.**

**Adversarial test**: synthesize a synthetic `substrate-health-tick` output where one numeric metric crosses the failing threshold by exactly `threshold × 0.99`. Confirm narration emits `regression`, not `expected_drift`. If it emits `expected_drift`, the threshold's hysteresis is overcalibrated and the activity is structurally invisible to real regressions.

This test is runnable as part of the V0 promote-gate evaluation — the gate can refuse promotion if the activity fails the synthetic-threshold-edge case. **Promotes the audit's adversarial probe into a structural admission criterion.**
