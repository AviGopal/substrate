### 71feaeff — boredom TimeoutStartSec=300

**Effect observed:** Before the fix, topology goals would be killed by systemd SIGTERM after 90s (prior logs showed `code=killed, status=15/TERM`). We have traded a 90-second SIGTERM for a 300-second HTTP timeout. The topology goal still fails.

This is **new finding F-061.**

### 4bb6ca7e — submodule pointer update (Thompson fix + migration 138)

**Migration 138:** `DEFINE FIELD OVERWRITE created_at ON execution_trace_content TYPE option<datetime> VALUE $value OR time::now()`. This fixes "Found NONE for field created_at" on every trace write. Mirrors migration 133 which fixed the same problem on `stored_at`. Non-fatal but reduces log noise. **Unambiguously correct.**

**Thompson normalizeActivityId fix:** In `repos/metabob-activity-api/src/lib/posterior-update.ts` line 437:
```typescript
const activityId = normalizeActivityId(rawActivityId);
```
This strips the `activity:⟨⟩` wrapper from incoming activity IDs before the `WHERE variant_id = $activity_id` clause. The fix addresses the root cause of F-037 (Thompson posteriors flat across 100+ executions): if the stored `variant_id` is `coverage-tick` but the incoming ID is `activity:⟨coverage-tick⟩`, the UPDATE matched zero rows and posteriors never moved.

**Critical gap: is the fix running?** The submodule pointer update changes what the *source* looks like. Whether the running container has this code depends on when `substrate-restart-metabob-activity-api` was last executed to rebuild the image. In this investigation window (9 minutes post-restart), coverage-tick shows execs=3 unchanged from iter-009. Zero new execution traces landed. I cannot confirm the fix is live in the running container, because there are no new traces to observe.

This is **new finding F-062.**
