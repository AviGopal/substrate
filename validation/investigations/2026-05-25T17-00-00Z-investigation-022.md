## Interaction analysis

Cα and Cβ compose cleanly in the common case — Cβ reroutes `validation_result`-producing tasks; Cα governs `compose_goal`'s LLM prompt for `goal`-producing tasks. Disjoint output shapes, no overlap.

**One adversarial scenario:** a future variant of `create-shape-provider-goal` whose `compose_goal` task is re-classified to emit `validation_result` (e.g. a self-checking variant) would have Cβ intercept the task and route it to `validator-dispatch`, **silently bypassing Cα's directive entirely** — losing cold-start narrowing.

**Mitigation:** Cβ's `pointer.match_existing_task_resolver` already constrains to `["impulse-resolve", "llm", "llm-prompt"]`, but does not exclude by `task.id`. Until schema supports `templateId_exclude` natively, the safer consumer-side default is to require `task.id != 'compose_goal'` in the intersection predicate. Document this exclusion in Cβ's content body so future operators see it.
