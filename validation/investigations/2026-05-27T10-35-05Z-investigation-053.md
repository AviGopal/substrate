### F-129 (HIGH) — §27.S.6 push-away measurement surface absent
**Status: PARTIALLY RESOLVED**

Commit `361c629a` adds `intervention.refused` event emission to the WS bus. Verified live:

```
POST /v2/activities/recommend
  task_description: "test task"
  expected_output_shapes: ["shape_that_does_not_exist_xyz123"]

→ HTTP 200
  refusal.type: "no_producer_for_expected_shapes"
  refusal.candidates_examined: 9
  refusal.reason: "No template in the full candidate pool emits any of the requested output_shapes..."
```

The source code at `/vessels/activity-api/src/routes/activities.ts` confirms the async bus emit is deployed (grep count=2). The event carries `source_vessel_id`, `refusal_type`, `expected_output_shapes`, `candidates_examined`, `task_description`, `reason`, `org_id`.

**Why only partially resolved:** §27.S.6 requires measurement over "sustained adversarial exposure" with substrate gates refusing interventions "over a sustained window." The WS bus is ephemeral — events not received by a subscriber at emission time are lost. No SurrealDB write path was found to durably accumulate refusal counts. Without a durable store, the §27.S.6 sustained-window assessment cannot be performed post-hoc; it requires a subscriber to be live during every refusal. This is a measurement architecture gap, not just a surface gap.

**Recommendation:** Add a thin SurrealDB write (or increment a counter table) for each `intervention.refused` event so refusal rate over time is queryable without requiring live WS subscription.
