## Subagent #41 design decisions

1. **Scoping**: (a) put-time `executionId` metadata stamping. Cheapest end-to-end. Alternatives (per-execution store, snapshot-on-write) require larger refactors.
2. **Delivery**: HTTP polling, NOT WebSocket. Existing `task.completed`/`impulse.resolved` events signal "something changed"; /state is read-after-event.
3. **Post-completion**: 1h archive in goal-host-vessel memory (`Map<executionId, {snapshot, completedAt}>`, 5-min reaper). SurrealDB persistence deferred to iter-060 territory.
4. **Auth**: ApiKey matching `/run-goal`.
5. **No impulse-resolvable `stateSpace` shape** — would create feedback loops; /state is operator-only HTTP.
6. **`producedBy` dual-keyed**: taskId + resolverId (cheap; answers "where in plan" + "via what tier").
7. **Cost-to-date via LiveExecutionFrame**: ~8 LOC for in-flight cost summation.
8. **No template task graph in response** — couples /state to registry; operator can GET /v2/activities/templates/:id separately.
