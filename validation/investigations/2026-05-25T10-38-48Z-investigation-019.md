## Posterior Reset Mechanism (F-079)

The commit message says "posterior reset" but the actual change is the opposite:

**Before (old code):**
```sql
UPSERT variant_performance_metrics:`${id}` CONTENT {
  thompson_alpha: 1.0,   -- OVERWRITES on every re-registration
  thompson_beta: 1.0,    -- DESTROYS accumulated state
  total_executions: 0,
  ...
}
```

**After (c1364e4 fix):**
```sql
UPSERT variant_performance_metrics:`${id}` SET
  thompson_alpha = thompson_alpha ?? 1.0,   -- PRESERVES if exists
  thompson_beta  = thompson_beta  ?? 1.0,   -- only initializes for NEW rows
  total_executions = total_executions ?? 0,
  ...
```

The `??` nullish coalescing means: "use the existing value if it exists, otherwise default to 1.0." This is a PRESERVATION fix, not a reset.
