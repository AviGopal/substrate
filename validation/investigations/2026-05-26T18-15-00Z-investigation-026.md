# Investigation 026 — Foundation-alignment correction: iter-024 misdiagnosed, iter-025 partially wrong, response-side belongs as impulses

Subagent #8 (transcript: `/tmp/.../a5d45d0129b4b6404.output`) ran an adversarial check on iter-025's envelope design against the impulse-activity foundation (`docs/architecture/IMPULSE_ACTIVITY_FOUNDATION.md`). The result corrects both prior investigations on substantive points.

## The diagnosis iter-024 missed

Iter-024 framed the LLM resolver's narrow context as "the LLM sees only `task.prompt.template` + `context.variables`; everything else in `ResolverContext` is dropped." The diagnosis is observationally correct but causally wrong. **`inputImpulses` already exists on `ResolverContext` (`engine.ts:154`).** The `llm-prompt` resolver simply *ignores it* and reads only `task.prompt.template` + `context.variables`. The narrowness is a resolver-side bug, not an executor capability gap.

This re-frames the whole conditioning question. The proper foundation-native path is already wired up to one task boundary back — the executor resolves declared `inputShapes` into `inputImpulses` correctly; the resolver just doesn't honor them.

## Foundation lines that bear on this

The subagent ground-truthed against canonical lines:

- **L43** — "Shapes are not declared in a global registry; they are *learned types* — observed when vessels advertise resolvers, refined when traces show co-occurrence patterns, and pruned when no resolver claims them."
- **L124** — "The metadata allows reasoners (LLM or otherwise) to understand the current state without loading all the raw data. The reasoner sees the shape, decides what to do, and lets the resolver do the actual data work."
- **L65–67** — gaps that "force REST endpoints, hardcoded routing, or non-impulse state shared between subsystems" are evidence the four-primitive minimum is wrong. **The wire envelope is precisely "non-impulse state shared between subsystems."**
- **L267–275** — implicit vessels and side channels: "evidence about the minimum set," not sins, but flagged as architectural debt.

The envelope in iter-025 is at minimum *evidence about a missing primitive*. Building on it ossifies that evidence into a wire contract.

## Position taken: hybrid (C), with a deliberate tilt toward "everything-is-an-impulse" (B)

The subagent's verdict, which I endorse: the envelope is the right *transitional* shape but only if **framing fields stay envelope** (`goal_class`, `composition_depth`, `budget_remaining` tier — iter-025's required fields, ~30% of the design) and **content fields become impulses** (`concept_directives`, `gap_context`, `parent_goal_text` — iter-025's optional fields, the load-bearing 70%).

### Why pure-envelope (Position A) is wrong

The "envelope is HTTP headers" analogy collapses on inspection of L43 and L124. `concept_directives` is the most learning-fertile field in iter-025's design — it's the substrate's accumulated knowledge about how to condition this exact `(template_id, goal_class)` pair. Putting it in a wire envelope strips it of: (a) a pointer addressable by other resolvers, (b) co-occurrence signal in traces, (c) Thompson posteriors over directive effectiveness, (d) impulse-relevance feedback. The whole concept-db machinery (Cα/Cβ from iter-022) is built around concepts-as-impulses with usage counts. **Wire-channeling that data routes it around the channel where the learning happens.**

The "impulse-as-input explodes surface area" claim is also wrong: `task.inputShapes` is already a list of shape names; adding `gapClassificationImpulse` costs one string. Compose_goal already declares `forward_chain_producers_result` and friends.

### Why pure-impulse (Position B) is right but premature

Three operational failures today:

1. **The executor cannot write impulses pre-dispatch.** Engine has `traceSink`, not an in-execution impulse-pool-writer addressable by other resolvers. Building gap-classification on `gapClassificationImpulse` requires the executor to write into the pool before resolver dispatch. The infrastructure doesn't exist yet.

2. **Some envelope content is genuinely non-substantive.** `goal_class` is metadata *about the dispatch*, not data the goal carries. The goal already has a `goal`-shape impulse with text. Promoting `goal_class` to `goalClassImpulse` is a category error — what would a Thompson posterior over `goalClassImpulse` even mean? Per HTTP analogy: the goal is the URL; `goal_class` is the Accept header.

3. **Downstream consumers for `synthesisOutcomeImpulse`/`unmetRequirementsImpulse` aren't wired.** The ribosome, validator-dispatch, concept-extractor all consume impulses today, but none subscribe to a synthesis-outcome shape because the shape doesn't exist. Shipping pure-B means shipping consumer-side too.

## The split corrects iter-025

| iter-025 field | iter-025 placement | iter-026 correction |
|----------------|-------------------|---------------------|
| `goal_class`, `goal_class_chain` | envelope required | **stays in envelope** (dispatch framing, not data) |
| `composition_depth` | envelope required | **stays in envelope** (structural, executor-enforced cap) |
| `budget_remaining` (tier enum) | envelope optional | **stays in envelope** (framing tier) |
| `gap_context.gap_type` (proximate) | envelope optional | **envelope** (framing; the executor's classification of WHY this dispatch) |
| `gap_context.missing_shapes` | envelope optional | **becomes `gapClassificationImpulse`** (data, addressable, learnable) |
| `parent_goal_text` | envelope optional (≤500 chars) | **becomes impulse** with full text + truncation marker (existing `goal` shape works) |
| `concept_directives` | envelope optional (5×200 chars) | **stays as concept-db impulses** declared in `task.inputShapes`; envelope carries reference IDs only |
| `variant_maturity.sample_count` | envelope optional | **stays in envelope** (framing) — Thompson posteriors are still REST per foundation L883 |

The transition is: envelope is for *framing about the dispatch*; impulses carry *data the resolver consumes*. iter-025's required/optional split lines up almost exactly with this principle.

## The response-side is the highest-value, lowest-cost piece — and iter-025 got it wrong

This is the load-bearing correction. **The `LLMInvocationResponse` wire envelope from iter-025 is the wrong abstraction.** The `llm-prompt` resolver already returns `Impulse[]` (`llm-prompt.ts:90`). Switching from a single `llmText` impulse to multi-impulse emission is one-line additive:

```
[ { shape: "synthesisOutcome", body: { outcome: "synthesized" } },
  { shape: "synthesisBody",    body: { ... } },   // optional, when synthesized
  { shape: "unmetRequirements", body: { reason, missing_shapes, conflicting_directives } }  // optional, when outcome != synthesized
]
```

Why this matters:
- **Trace sink** already accumulates impulses — no new plumbing.
- **Validator-dispatch** already keys on shape — it can natively subscribe to `synthesisOutcome` shape.
- **Ribosome** already reads trace impulses — can extract patterns over `unmetRequirements` body.
- **Concept-extractor** (Cβ) can write a `playbook` concept when the same `(shape, unmet_requirements.reason)` recurs.
- **Failure-mode attribution** for synthesis-failure (the corruption pattern iter-024 named) routes correctly: the trace sink reads `outcome=insufficient_signal` from an impulse, classifies the trace's `failure_mode` accordingly, chain-credit propagation debits the variant that should have produced the impulse.

**Iter-025's response envelope is foundation-incorrect.** The wire-field response can be dropped entirely; impulses do the same job natively, with co-occurrence and learning attached for free.

## The real bug iter-024 misdiagnosed

Iter-024 framed the LLM resolver's narrow context as "no envelope channel." The actual bug is **the `llm-prompt` resolver doesn't read its declared `context.inputImpulses`**. The fix is:

1. Fix `llm-prompt.ts` to read `context.inputImpulses` and interpolate impulse bodies by shape name (the foundation-native path).
2. Templates declare `concept_directives`, `gapClassification`, `parentGoal`, etc. in `task.inputShapes`; the executor resolves them; the resolver consumes them.
3. The envelope remains for the small set of genuinely-framing fields (`goal_class`, `composition_depth`, `budget_remaining` tier, `variant_maturity.sample_count`).

This is a smaller, more surgical fix than iter-025's full envelope design.

## The most uncomfortable concession

Letting the executor's missing pre-dispatch impulse-write capability dictate architecture. Strict foundation reading (L65–67) says: "non-impulse state shared between subsystems is evidence the minimum is wrong." Shipping the envelope at all *as a band-aid* risks ossifying it. **Concept-db's REST surface ossified for two years before becoming the impulse-shape it should always have been.** The hybrid risks the same trajectory.

**Position B would have been right outright if:** (a) the executor gains pre-dispatch impulse-write within one development cycle AND (b) the llm-prompt resolver is fixed to read `context.inputImpulses` before iter-024's 24h confabulation experiment runs. If both land first, the envelope never needs to exist — forward-side conditioning flows as impulses, response side emits impulses, and iter-025 collapses into "the llm-prompt resolver now honors its declared inputs."

The reason for the hybrid is timing, not principle. If dev can land the resolver-fix + impulse-pool-write fast, Position B should ship. If not, the transitional envelope is acceptable *only* with an explicit migration ticket: "envelope `concept_directives` → impulse `relatedConcepts`-shape input" the moment concept-db wire-up matures.
