## Implementation detail

**Refactored** `registerDevVesselProxies()` from one-shot into idempotent diff-based:
- Tracks `registeredProxyShapes: Set<string>` at module scope
- On each call, fetches `/shapes`, diffs against current set, registers proxies only for new shapes
- Logs the diff (`+N new shapes (now M total)`) so operator can verify reactivity
- Factored `buildProxyResolver(shape)` into a named function for reuse

**New WebSocket subscriber** in goal-host-vessel:
- Connects to `ws://activity-api/ws` at startup
- Handshakes via `{type:"authenticate",token:METABOB_API_KEY}`
- Filters `vessel.registered` events whose `data.vessel_id` matches `/^development-vessel(-|$)/`
- 500ms debounce on rapid successive events
- Exponential backoff 1s → 30s on reconnect
- On reconnect, immediately re-runs `registerDevVesselProxies()` for catch-up

**Connection topology now event-driven:**
```
dev-vessel restart
  ↓ register
discovery-vessel registry mutation
  ↓ publishVesselEvent("vessel.registered", ...)
activity-api POST /v2/events/publish
  ↓ broadcaster.emit
WebSocket fan-out
  ↓
goal-host subscriber → debounce → diff-and-register
```

Same pattern any future proxy-hosting vessel can adopt without writing new bus infrastructure.
