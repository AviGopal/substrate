2. **Write path** — POST /templates UPSERT plumbs `proposed: validated.proposed ?? false` into `activityRecord`.

3. **Migration 139** — `DEFINE FIELD OVERWRITE proposed ON activity TYPE bool VALUE $value OR false`. Required because the activity table is SCHEMAFULL; undefined fields silently dropped on upsert (verified live before migration: my first test showed `proposed: null` in DB despite `proposed: true` in request).

4. **Recommend filter** — extends the `validTemplates` filter step alongside `retired`:
   ```typescript
   if (template.proposed === true) {
     logger.debug('Filtering out proposed (unpromoted) template', ...);
     return false;
   ```

   This works alongside the prior refusal guard: if the only producer for an expected shape is proposed, the refusal guard fires correctly (no candidate template in the pool intersects).

5. **Promote endpoint** — `POST /templates/:templateId/promote` flips `proposed: false`. Idempotent: returns `{action: "promoted"}` on first call, `{action: "already_promoted"}` thereafter. Bus emit on success via `broadcaster.emit({type: "activity_template.promoted", ...})` rides the neutral-emitter bus from iteration 4.
