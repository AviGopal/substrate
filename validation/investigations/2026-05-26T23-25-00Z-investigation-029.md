### The recursion is lattice-shaped, not tree-shaped

A child subscriber's execution itself emits `lifecycle:task:preBinding` and `lifecycle:task:completed` events as its tasks run. The trace records parent-child as a tree (`compositionChain`), but the **data flow is a lattice through the shared pool**. A slot-binding child can `put` a `goal` impulse; a validator-dispatch child can read it on the parent's `task:completed`; a concept-db observer can index it — all without any of these templates referencing each other.

### Three concrete emergent behaviors

1. **Implicit gap-escalation chains**: slot-binding on preBinding → emits `create-shape-provider-goal` → child execution emits `goal` impulse → fires `lifecycle:execution:succeeded` → validator-dispatch reads it → emits `validation_result`. The composite "if shape missing, recurse, validate the recursion" is in no template; it falls out of three independently-subscribed templates plus the shared pool.
2. **Cross-template Thompson conditioning shifts**: when slot-binding adds an impulse, the `state_space_signature` changes, and the *next* subscriber's recommendation distribution shifts. Emergent ranking sensitive to the prior subscriber's effect.
3. **Concept formation via passive observer**: concept-db's `ExecutionObserver` is purely passive WebSocket. Concepts form without any template explicitly invoking concept-db.

### PSS vs ISS — specialization, not duplication

- PSS *content* lives as `goal`-shape impulses in the pool (so slot-binding can read via `parentGoalText`).
- PSS *structure* lives outside the pool — `parentExecutionId` / `compositionChain` on traces (`engine.ts:301-315`).

Pool-encoding lets subscribers *reason* about the goal; trace-encoding lets the recommender *condition* on depth without paying the lookup cost. ISS mutation does NOT automatically mutate PSS; only subscribers that emit a `goal`-shaped impulse OR dispatch a nested execution (which writes `parentExecutionId`) extend the PSS.

### Are the existing guards sufficient?

`emittingTemplateId` self-block (`lifecycle-subscriptions.ts:315`) + `auditDepthCap` (`:424-449`, default 2, hard cap 4) cover two failure modes. They do NOT cover:

- **A→B→A cycles** through different templates that subscribe to each other's emitted shapes. Depth-cap is the actual safety net; `emittingTemplateId` is just optimization.
- **Pool-mediated cycles**: A emits shape X on task:completed, B subscribes when X is present and emits Y, C subscribes on Y and re-emits X. Invisible to `emittingTemplateId`. Depth-cap terminates eventually but only after `cap` levels of churn — at ~$0.10/LLM-call this is non-trivial.

iter-028 Finding A5 (validator-dispatch burning LLM budget producing null parent failure_mode) is consistent with this class of unintended cascade.

**Operational implication 1:** The lifecycle layer is the substrate's primary self-modification channel — load-bearing for slot-binding and ribosome-extract today; should be load-bearing for self-debugging tomorrow. The depth-cap is the safety net most subscribers actually depend on; a single misconfigured filter can spend the budget.

## Part 2 — Validation activities as closed-loop feedback

### The closed-loop signal, one trip around

Task runs (`engine.ts:204-226`) → outputs land in store (`:228-233`) → `lifecycle:task:completed` fires (`:274-297`) → validator-dispatch subscribed → runs as nested execution → emits `validation_result` impulse → learning-signal writer computes Thompson α/β deltas keyed on `(activity_template_id, state_space_signature)` → POSTs to activity-api → next recommendation reads the same posterior.

**Round-trip latency:** ~5-15s, dominated by validator's LLM call.

**Signals preserved:** outcome, confidence, `failure_mode.type`.

**Signals LOST:**
- Per-task tool calls that produced the failed output (only `output_impulse_ids` survives, not the bash command that wrote them).
- Resolver tier of intermediate tasks (only the validator's tier is logged).
- The *evidence* the validator considered (some validators emit `Evidence[]` in `failure_mode.context` but most don't).

### Validation as debugging — failure_mode taxonomy → repair affordance

| failure_mode | Diagnostic ground truth | Repair affordance |
|--------------|------------------------|-------------------|
| `verifier_negative.context.validator_id + failed_evidence` | which contract was breached | adjust producing template output schema OR add missing task |
| `budget_exhausted.context.budget_type` | which resource ran out | decompose template OR hoist work upstream |
| `safety_breach.context.breach_type=depth\|cycle` | lifecycle layer itself in runaway | tighten depth-cap OR fix subscriber filter |
| `cascading.context.upstream_task_id + upstream_failure_mode` | walk backward across composition chain | upstream repair |
| `user_abort.context.abort_source` | human intervention vs system failure | critical for S2→S3 push-away signal |

### Iter-028 Finding A5 explained

validator-dispatch fires, burns LLM budget, but the parent trace's `failure_mode` stays null because **the validator's `validation_result` impulse is emitted into the *child's* trace, never written back to the parent's `failureMode` field at `engine.ts:361-374`**. The catch block only sets `failureMode` on thrown errors; validators that *report* failure without throwing leave the parent labeled `completed`.

**The fix is wireable from existing primitives:** a parent-level subscriber on `lifecycle:execution:succeeded` reads any `validation_result` impulses with `pass=false` from the pool and rewrites the trace's status/failure_mode. No new mechanism required.

### Gap discovery via validator-emission signatures

Each gap-type from iter-023 (+ Type 8 from iter-028) has a distinct validator signature:

- **Type 3 (missing-shape-in-pool)**: caught at `engine.ts:110-124` *before* a validator runs — `lifecycle:gap:classified` with `gapType=missing_input_shapes` is the validator-equivalent. No LLM needed.
- **Type 6 (synthesis-failure)**: producer ran, emitted right-shaped impulse, content is wrong. Only a content-reading validator (verify-goal-alignment) catches this — `validation_result.pass=false` with `failed_evidence`.
- **Type 8 (stub-masked content absence)**: shape present, body is a 50-byte stub. validate-template-compliance catches the structural case; a body-length validator catches the general case. **No shape-agnostic body-presence validator runs today** — that's the gap iter-028 surfaced.

### Recursive validation has a natural foundation

`audit-resolver-divergence` (iter-028) emits `expectationGap` + `resolverDivergenceReport`. Both are normal impulses → any template subscribed to `lifecycle:task:completed` with `output_shapes_contains expectationGap` can consume them. A `validate-validator-divergence` template subscribed on `lifecycle:execution:succeeded` filtered to `templateId=audit-resolver-divergence` would emit a second-order `validation_result`. **Termination guard:** the same audit depth-cap (4). **Cycle prevention:** `expectationGap` is a sink shape that no validator emits except as a *result* of analysis. **Foundation:** validators are pure functions of the pool + the trace; they consume but don't perturb upstream state, so the lattice has no feedback edges except via Thompson posteriors, which are bounded learning-rate updates.

**Operational implication 2:** Today validators produce failure signals that don't reach the parent trace's `failure_mode` field — which is why iter-028 Finding A5 looks like "expensive null". The fix is parent-side reconciliation on `lifecycle:execution:succeeded`, not new validators.

## THE most underused property of the lifecycle system today

**`lifecycle:gap:classified` is emitted by the engine itself at `engine.ts:111-124` and `:161-172`, covering both missing-shape gaps AND unregistered-resolver gaps. The emit is self-contained (no LLM, no subscriber required for it to fire). The engine is broadcasting "here is exactly which gap I just hit, with the shapes present and missing, the depth, and the goal context" on every miss. NO EMBEDDED TEMPLATE SUBSCRIBES TO IT.**

A one-template subscriber that writes each `gap:classified` event to a `substrateGap` impulse indexed by `(gapType, missingShapes, parentDepth)` would:

1. **Convert the substrate's gap-discovery from manual to continuous.** Currently human-driven (29 numbered investigations and counting). After: continuously-maintained gap catalog.
2. **Feed `escalate-unknown-shape` and `create-shape-provider-goal` without LLM in the detection step.** Pure deterministic dispatch — the same primitives that already exist, now wired to a live gap stream.
3. **Compose with iter-027's `lifecycle:llm:dispatched`** — both events are currently emit-without-listener. The structural pattern: dev ships emits, listeners stay unwired.

Wiring it up is **one template file** plus `subscription.shape="lifecycle:gap:classified"`. The channel is fully built; nothing consumes it.

## The structural pattern this investigation surfaces

Two of the most consequential lifecycle channels shipped in the last 24h have the same defect:

| Channel | Emit shipped by commit | Subscriber count today | Audit-channel finding |
|---------|------------------------|------------------------|----------------------|
| `lifecycle:llm:dispatched` | `41382521` | **0** (lands in NoopEventSink) | Finding 3 in audit.md |
| `lifecycle:gap:classified` | `31eeeb2f` | **0** (no template subscribes) | this investigation |

**The substrate's self-debugging capability is gated on a missing pattern: every new lifecycle emit needs at least one default subscriber to make the event observable.** Without it, the emit ships and the observability promise is half-kept. This is auditable: `grep -r "lifecycle:" repos/.../templates/` should always return at least one subscriber per emit type.

Worth proposing as a coding convention: **no lifecycle:X:Y emit ships without a paired default subscriber template** (even if the subscriber's only action is to write the event payload to a queryable impulse).
