## F-084: analysis-vessel registration — RESOLVED

**Status: RESOLVED** (was open in investigation-020)

The root cause was a startup race: analysis-vessel started before identity-vessel was ready to validate API keys, so the initial `POST /register` call returned 401. The vessel then entered heartbeat mode with no registered slot, causing all subsequent heartbeats to return 404.

The fix in commit 2fcf735c adds two lines to the systemd unit:
```
After=discovery-vessel.service identity-vessel.service
Wants=discovery-vessel.service identity-vessel.service
```

After the hot-patch restart at 11:25:36Z, the registration log shows:

11:25:36 [analysis-vessel] listening on http://127.0.0.1:8250
