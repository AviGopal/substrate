narrator snapshot file is named `snapshot-2026-05-24T02-26-20`
with file mtime `2026-05-23 19:26:20 -0700` (= 02:26:20Z UTC) —
consistent with the later `date -u` value. The substrate's clock
is fine; the auditor's first `date -u` reading was stale or
captured from a different point in time.

Provenance impact for this report: I used the later, substrate-
consistent timestamp (`02:28:30Z`) for `generated_at`. The
discrepancy is recorded for future iterations to be aware of —
the auditor's clock view should be re-verified, not trusted
blindly.

Future investigations should run `date -u` at the start AND end
of each iteration. If the delta exceeds 60 seconds, prefer the
later value but record both. The auditor's whole credibility on
provenance depends on its own clock being trustworthy.

## Self-correction on F-016

In iter-004 I reported `ps ax | grep -c "substrate-narrator"`
returned `4` and surmised multiple narrator instances. This
iteration used `ps -eo pid,lstart,cmd | grep substrate-narrator |
grep -v grep` and found exactly ONE process (PID 3604730, uptime
~2h57m). The earlier "4" was the count of lines `grep -c`
returned, which included grep matching its own command line and
possibly subshell artifacts.

This is the auditor catching its own counting error. F-016
remains resolved (narrator running) but the iter-004 framing was
imprecise. Future investigations should use `grep -v grep` or
process-tree inspection rather than `-c` for counting matches.

## What this iteration proves about the loop's discipline

Self-correction matters. In iter-004 I trusted `ps ax | grep -c`
output and reported a count of 4 narrator processes. That was
wrong. This iteration found the right answer (1 process) by
using a more rigorous command. The pattern is worth naming:

> **The auditor must not trust counter-shaped commands without
> verifying their semantics.** `grep -c` includes self-matches;
> `wc -l` counts trailing newlines; `find | wc` doesn't handle
> filenames with newlines. Each iteration should produce its
> own evidence with commands whose semantics are well-defined.

F-022 is the same pattern applied to time. The auditor's
`generated_at` is supposed to be trustworthy; if `date -u`
returns inconsistent values within a single iteration, the
auditor needs to know.
