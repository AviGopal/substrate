## Human-terminal resolver — distinct from LLM in three ways

Prior passes treated them as symmetric peers (same retrieval, different render). This pass: they are not. The human-terminal is a concept-*author* surface in a way the LLM is not.

### Read path additions for human-terminal (LLM should NOT have these)

- Operator-scoped concepts (`scope=operator, operator_id=$current, specificity_class=directive`). LLM has no business reading "this operator prefers TypeScript over Python in fixtures."
- Prior corrections on the same shape (`source_type=human_input, priority≥0.8`). If operator already corrected this, render the correction before asking again.
- Open questions (`source_type=goal, shape=open_question`, unresolved). Terminal session is the moment to clear the queue; LLM should never *answer* these because operator answers carry higher specificity by construction.

### Write path — every terminal turn is candidate concept

Default: `source_type=human_input, priority=0.5, specificity_class=hypothesis` until confirmation. Promotion to 0.8 via `/confirm 1,3,4` slash command OR three successful downstream traces (C5 mechanism). UX in prose: terminal session ends with `concept-db candidates from this session: 7`; operator confirms a subset; rest persist as hypotheses.

### Override frontier — when operator concepts get demoted

Operator concepts get retrieval-rank priority over LLM-derived at equal specificity. But priority ≠ immutability:
- **Drift detection**: ≥10 traces in a row succeed *against* an operator concept → raise `override_pending`, surface to operator next session for re-confirm or revoke.
- **Hard floor**: operator-authored `priority=0.8` concepts cannot auto-demote below 0.6 without operator input. Below 0.6 can be de-prioritized; only operator-action deletes. Protects against confidently-wrong trace mass overwriting deliberate directives — exactly the failure mode S2→S3 push-away criterion exists to prevent.

### Multi-turn dialogue uses existing edge taxonomy

`derived_from` (turn 3 refines turn 1), `contradicts` (turn 5 reverses turn 2), `sequence_next/prev` (within-session order). **No schema change needed.** The missing piece is retrieval-side: when chain `A→B→C` exists with same operator+shape and no `contradicts`, only `C` (latest refinement) is injected. With a contradicts edge mid-chain, surface the divergence point. This lives in the human-terminal resolver, not the LLM resolver — LLM treats latest as authoritative; terminal renders the chain so the operator can see their own evolution.
