# Investigation 031 — Gap-closing activity: `close-gap-via-memory-note`

Subagent #13 (transcript: `/tmp/.../a2b4491e83132a6a0.output`) returned a concrete design for the first activity the substrate would author *to expand its own knowledge surface*. ## Design summary

### 1. Gap sources, single shape

Two distinct sources for `substrateGap` impulses, both flowing through one shape with `body.source ∈ {"operator_narration", "substrate_detected"}`:

- **Operator-filed**: `validation/gaps/<gap_id>.yaml` records (per Narration Protocol §C). Inert until ingested.
- **Substrate-detected**: lifecycle subscriber on `lifecycle:gap:classified` (iter-023 emit, post-bus closure).

**Critical filter — activity claims ONLY `body.category ∈ {"conversation_only", "training_knowledge"}`.** Other categories (`missing_concept` → ribosome; `missing_idiom` → idiom extraction) route to existing pipelines. The activity emits `failure_mode.type=verifier_negative, reason="bridge_path_mismatch"` on uncategorizable input. Doesn't poach work that belongs to other bridge paths.

### 2. Ingestion bridge

- **Operator-filed**: one-shot script reads `validation/gaps/INDEX.md`, emits `substrateGap_write` impulses (idempotency key = `gap_id`). Manual lift; not substrate autonomy.
- **Substrate-detected**: lifecycle subscriber activity calls `substrateGap_write` directly. Embedded in development-vessel seeds.

**`substrateGap` and `memoryNote` are distinct shapes** — gap is *problem statement*; memoryNote is *candidate answer*. Conflating them makes the activity's I/O incoherent (consume and produce same shape). Two shapes; activity transforms one to the other.

Surface area: one new case in `impulses.ts` switch (`substrateGap_write`). `memoryNote_write` already specced.

### 3. The six-task template (only one LLM)

```
input_shapes: ["substrateGap"]   output_shapes: ["memoryNote"]
```

| # | id | resolver | tier | notes |
|---|---|---|---|---|
| 1 | `validate_gap_eligible` | `validation` | det | hard-filter category; refuse with `bridge_path_mismatch` |
| 2 | `retrieve_related_concepts` | `impulse-resolve` (concept-db) | det | **explicit retrieval, compensates iter-027 Correction A** — doesn't rely on `llm-prompt.ts:85` autonomous lookup |
| 3 | `retrieve_prior_memory_notes` | `impulse-resolve` (activity-api) | det | BM25 against title+summary; feeds Task 4 prompt + Task 5 gate |
| 4 | `synthesize_candidate` | `llm` | llm | **load-bearing task**; prompt cites Task 2 + Task 3; "refuse" explicitly allowed as valid output |
| 5 | `mark_proposed_and_emit` | `impulse-resolve` (write) | det | wraps as `memoryNote` with `proposed=true, metadata.gap_id=<gap_id>`, calls `memoryNote_write` |
| 6 | `verify_query_now_resolves` | `impulse-resolve` (activity-api) | det | replay-query that would have surfaced the gap; check if just-written memoryNote appears |

All resolvers exist at `repos/ias-executor-ts/src/hosts/goal-host.ts:598-673`. No new engine primitives. No new resolvers.

### 4. Promote-gate composition

iter-030's gate uses Jaccard on `inputShapes ∪ outputShapes` — doesn't transfer to memoryNotes (no shape-to-shape mapping; only content).

**Recommendation: same gate, parametrized by shape with per-shape similarity functions.** Jaccard for templates (existing), BM25-cosine for memoryNotes (new strategy). Single gate, two strategies.

**Refusal conditions for memoryNotes:**
- BM25 cosine > 0.85 against existing non-`proposed` memoryNote → semantic duplication, refuse.
- Zero substrate-resident concept citations AND zero trace citations → groundedness floor failed, refuse.
- Otherwise accept.

Refuse-with-citation pattern from iter-030 carries over — rejection itself is a `gate_decision` impulse.

### 5. Two-tier learning signal (fast + slow)

**Fast (per-execution, Task 6).** `verify_query_now_resolves` either finds the just-written memoryNote in a replay or doesn't. Pass → α+=1; fail → β+=1. Catches indexing/title-summary-mismatch failures. **Limitation**: measures findability, not correctness.

**Slow (cross-narration, lifecycle).** A later narration that WOULD have hit `gap_id=X` finds the memoryNote and resolves without re-filing. Narrator emits `gap_closed_in_replay` event referencing original `gap_id`. Pass → α+=1.

**Use BOTH.** Fast for per-trace Thompson; slow as periodic correction (weekly aggregator activity re-credits α/β). Mirrors chain-credit propagation pattern (CLAUDE.md "Composition-chain credit propagation"): immediate posterior + delayed correction.

### 6. What ships first — gap-detector before gap-closer

**Subagent argues a substrate-side gap-DETECTOR is structurally prior.** A `lifecycle:gap:classified` subscriber that auto-files `substrateGap` impulses is cheaper (one subscriber, deterministic) and produces inputs for THIS activity for free. Without auto-detection, the gap-closing activity is starved of substrate-detected input and depends entirely on operator ingestion — making it operator-loop, not autonomy.

**Counter:** detector-only-indefinitely is observation without action — the failure mode iter-022 warned about. They ship together or detector ships first by a few days max.

### 7. Fail-closed defaults across all failure axes

- **concept-db unavailable (Task 2)**: mark `degraded=true`, don't abort. Promote-gate's groundedness floor catches uncited claims downstream.
- **LLM confabulates (Task 4)**: groundedness floor in promote-gate catches. Prompt explicitly allows "refuse".
- **No relevant concepts retrieved**: valid for `conversation_only`; suspicious for `training_knowledge` (signals mis-categorization — refuse + flag for re-routing).
- **promote-gate refuses**: stays `proposed=true`. β+=1. No partial acceptance.
- **`verify_query_now_resolves` fails (Task 6)**: β+=1; memoryNote stays written but flagged `verification.replay_passed=false` so slow signal can still credit later.

Every axis defaults to refuse-or-mark-degraded. Nothing writes "approved" memoryNotes without both gate-pass AND verification-pass.

### 8. Cheapest pre-implementation experiment

**Operator runs the loop manually for ONE gap.** Steps:
1. Write `substrateGap` impulse by hand via `/v2/impulses/resolve`.
2. Hand-author a `memoryNote` with `proposed=true`.
3. Submit to promote-gate; observe sensible refuse-or-accept.
4. Run the original gap's query; observe whether memoryNote appears.

If (3) gives nonsense (gate refuses for unrelated reason, accepts garbage), fix the gate before automating. If (4) doesn't fire (memoryNote written but unfindable), activity-api's memoryNote search is the bug — fix that. If both pass, the activity is just automation of a working manual loop — high-confidence ship.

Cost: ~1 operator hour. Surfaces §7 failure modes fastest.

## The most controversial design choice + adversarial argument

**Task 6's self-credit-on-own-replay is Goodhart's-law-shaped.** The LLM in Task 4, under Thompson pressure, may learn to author memoryNotes whose `title`+`summary` exactly match the keywords the replay-query uses — optimizing for *findability* rather than *correctness*. The activity's α grows while the substrate accumulates indexed-but-wrong notes that pass replay but fail any real downstream consumer.

The slow signal (§5) is supposed to catch this, but if it lags by weeks and the fast signal updates per-trace, the activity converges to keyword-stuffing long before the slow signal corrects.

**The adversarial test the audit should run after V0 ships:** force the activity through 20+ executions on *synthetic* gaps, then check whether the memoryNotes are queryable by **paraphrased forms** of the original gap-question (not the literal replay-query). If paraphrase-recall drops while replay-recall stays high, **the design is broken and Task 6 must be replaced with a held-out-question evaluator** (e.g., generate the replay-query AFTER Task 4 synthesis using a separate LLM call against the gap's `attempted_description`, never seeing Task 4's output).
