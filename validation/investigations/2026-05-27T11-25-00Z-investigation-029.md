## Critique of the shipped contract (subagent's load-bearing finding)

The shape works, but the response shape has four observability gaps:

1. **Cardinality default is "aggregate" with no inspectability.** When `shape_signature` is omitted, the resolver aggregates across signatures — but the response doesn't tell the caller this happened. Caller cannot distinguish "this template has α=42 under one signature" from "α=42 averaged over twelve signatures." Fix: add `signatures_aggregated: number` and `signature: null | string` to the response body. Backward-compat (no breaking change).

2. **No array form for "all signatures."** A caller wanting to choose among signatures must enumerate externally via `contextThompsonScores` (`routes/impulses.ts:3403`). Clean fix: pointer carries either `(variant_id, signature)` → one row, or `(variant_id, signature: "*")` → array. Add as Phase 9.6 follow-up; do not break scalar contract.

3. **`signature_version` absent.** Today's resolver implicitly assumes v1. When v2 lands (state_space_signature spec), the resolver must read it from a config the caller cannot override. Fix: explicit `signature_version` pointer field with default=1.

4. **No `scope` discriminator in response.** Phase 5.2 ordering (org/account → global fallback) is correct but invisible. Caller cannot tell "I'm reading my org's posterior" from "I'm reading the global prior." Fix: add `scope: "org" | "account" | "global"` to response.

These are all additive — none require breaking the shipped contract.
