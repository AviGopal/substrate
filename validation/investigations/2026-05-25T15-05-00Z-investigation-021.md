## What the fix reveals about substrate-self-description

The substrate just demonstrated a non-obvious self-description property: **it can succeed at an activity whose template includes a retrieval task (`impulse_cooccurrence`) that returns empty results, because downstream consumers handle empty defensively.** This means concept-db's emptiness is not a hard blocker for any current activity — it is a soft conditioning input. Activities don't refuse on empty retrieval; they *synthesize without that signal*.

This re-prioritizes the resolver-POV question. The earlier framing was: *what would concept-db enable that's currently impossible?* The corrected framing is: *what would concept-db enable that's currently invisible?* The substrate is operating, just without the conditioning that concept-db would provide. The cold-start experiment must measure a *quality* delta in the synthesized output, not a *success-rate* delta in activity completion.

This is harder to measure. It needs A/B on the *content* of `compose_goal`'s LLM output before and after concept-db population — same goal, same activity, different prompt context. Audit cannot do that from trace observation alone; it needs the operator to compare two synthesized goals and judge which is better-aligned with intent.
