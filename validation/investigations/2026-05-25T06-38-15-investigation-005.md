## F-049 NEW: Bootstrap-Seeder Ordering Race

The self-bootstrapping commit introduced a structural ordering problem. Bootstrap-seeder
fires early in the startup sequence, but the substrate-org (the organization record that
gives templates their `org_id`) is created by `seed-identity.ts` — which runs later. All
13 template writes fail with:

```
Query failed in activity-system.learning_loop: 
Found NONE for field `org_id`, with record `activity:⟨slot-binding⟩`, 
but expected a string
```

The bootstrap-seeder completed its `Type=oneshot` execution and exited with status 1.
It will not retry automatically. The substrate has 0 SHARED_TEMPLATES from ias-executor-ts.

The discovery-vessel's development-vessel seed templates (substrate-health-tick,
harness-run-matrix, coverage-tick, and others) appear to be written by a different path —
they show up in the total=15 count but only 2 are returned in the default template list
query (suggesting scope or org filtering differences).

**Quick fix**: `docker exec substrate-live systemctl restart bootstrap-seeder.service`
after seed-identity completes. **Structural fix**: add `Requires=` + `After=` dependency
in bootstrap-seeder.service pointing to a seed-identity-complete signal unit.
