# Investigation 025 — `LLMInvocationEnvelope` + `LLMInvocationResponse`: concrete shape contracts

Subagent #7 (transcript: `/tmp/.../aca42e8bf149e35d3.output`) returned a concrete design for the metadata envelope identified as load-bearing in iter-024. Reproduced in compressed form with the load-bearing choices preserved verbatim.

## Forward envelope: `LLMInvocationEnvelope`

Wire becomes `{type:"llm_completion", prompt, model, max_tokens, system?, envelope?}` — envelope is sibling to `prompt`, not nested. Omission = legacy behavior; presence = activated.

**Required fields:**
- `goal_class`: enum `{top_level_goal, boredom_probe, composed_subgoal, lifecycle_decision, self_reflection}`. **Proximate cause** semantics — what spawned this specific LLM call, not the lineage.
- `goal_class_chain` (O, array, root-first, ≤4 deep): the lineage when the five classes overlap (e.g. boredom-fired lifecycle-routed).
- `composition_depth` (integer): actual depth; executor enforces hard cap (16) by refusing dispatch — LLM never sees a value above cap.

**Optional fields:**
- `gap_context` (O, present only when executor classified a gap pre-dispatch per iter-023): `{gap_type: <enum of 7>, missing_shapes: string[], is_compositional: boolean}`. **Cut the backward-producer candidate list** — 10+ template ids worth of tokens, LLM cannot meaningfully act on ids it cannot invoke. Keep `is_compositional` as the summary boolean.
- `parent_goal_text` (O, R when `composition_depth > 0`): hard truncate at 500 chars with `...`. Full text in the trace, not the envelope. Beyond 500 chars marginal grounding value is negative (LLM starts pattern-matching the parent instead of the immediate task).
- `variant_maturity` (O): `{sample_count: number}` only. **Drop α/β** — LLMs cannot reason about posteriors but can use `sample_count < 3` as a gate on willingness to refuse. Cheap, single integer.
- `concept_directives` (O): array of `{directive_text: string (≤200 chars), source_concept_id: string, confidence: number}`. Hard cap **5 directives, 1KB total**. Confidence-descending. Conflicts NOT resolved server-side — LLM follows highest-confidence and reports the conflict in response.
- `budget_remaining` (O): tier indicator `{healthy, constrained, critical}`. **Not numbers** — LLMs cannot reason about "237ms remaining" but can reason about "critical → respond minimally." Executor OR's cost/time/depth budgets to tightest tier.

**Cut list (explicit, each justified):**
- `parent_execution_id`, `variant_id`, `trace_id`: opaque ids are noise to the LLM; provenance belongs in trace metadata, not the prompt-rendering side.
- Full Thompson α/β: LLM has no counterfactual access; α/β alone unactionable.
- Raw budget numbers: tier enum is the actionable form.
- Backward-producer candidate list: LLM cannot invoke templates directly; listing them costs tokens without changing behavior.

Each cut field fails the "what does the LLM actually do with this" test.

## Rendering: system prompt (default), with XML fencing

**Choose (a) system prompt.** Anthropic-native; the substrate already passes `system?` on the wire — surface absorbs the change without a new field. Serialized as `<envelope>...</envelope>` XML-style fencing followed by brief natural-language framing.

**Against (b) prompt prefix:** indistinguishable from user content; existing templates already inject arbitrary prefixes; prompt-injection becomes envelope-injection.

**Against (c) tool call:** latency cost per call; envelope is small (<2KB worst case). Tools shine for large/conditional payloads.

**Hybrid (rejected):** put `concept_directives` in system, rest in prefix. Rejected because directives are *part of* the context that includes `goal_class`, not a separate channel.

`llm-resolver-vessel:src/index.ts:94-99` becomes the rendering authority: accepts `envelope` on the wire, deterministically serializes to `system` field (concatenating with caller-supplied system text). Templates and goal-host-vessel never see the rendered form.

## Reciprocal response: `LLMInvocationResponse`

The load-bearing half. Today: LLM returns a string; the executor's interpretation is "parsed/looks-reasonable → success." This is where confabulation-as-success becomes addressable.

**Required:**
- `outcome` (R): enum `{synthesized, insufficient_signal, contradictory_signal, out_of_scope}`. Four is right; `partial` collapses into `synthesized` with low confidence OR `insufficient_signal` with partial body — splitting it adds a class LLMs cannot reliably self-classify into. The four are distinguishable:
  - `synthesized`: "I produced what was asked."
  - `insufficient_signal`: "Inputs don't contain enough information." ← the iter-024 synthesis-failure case
  - `contradictory_signal`: "Inputs mutually exclusive; cannot pick."
  - `out_of_scope`: "Need a different resolver or decomposition." ← compositional-gap case
- `body` (R when `outcome=synthesized`, O otherwise): the existing free-form/JSON output. When `outcome != synthesized`, `body` MAY contain a best-effort partial — trace sink does NOT treat non-empty body as success when outcome differs.
- `unmet_requirements` (R when `outcome != synthesized`): `{reason: string (≤300 chars), missing_shapes?: string[], conflicting_directives?: string[]}`. Crucially, `missing_shapes` can name shapes the executor's gap classifier (iter-023) missed.

**Optional:**
- `confidence`: three-bucket enum `{low, medium, high}`. Not float — LLMs cannot calibrate floats but can calibrate three buckets reliably. **Stratified Thompson update**: `synthesized + confidence=low` → Δα = 0.5 instead of 1 (extends the activity-api stratified-update pattern from CLAUDE.md: verifier_negative → full β, budget_exhausted → half β).

### Trace-sink attribution fix

When `outcome != synthesized`, the trace's `failure_mode` becomes:
```
{type: "synthesis_failure", reason: response.unmet_requirements.reason,
 context: {missing_shapes, conflicting_directives}}
```
This attributes the failure to the synthesis step itself, not the downstream validator that detected the missing output or the child task that couldn't proceed. The existing chain-credit propagation (F-V56/F-V57 in CLAUDE.md) then correctly debits the variant that *should* have produced the output, not the variant that detected its absence. **Closes the Thompson-posterior corruption pattern named in iter-024.**

### What stops the LLM from always returning `outcome=synthesized`?

Two safeguards: (i) the envelope's `goal_class` + `gap_context` give the LLM permission to refuse — current confabulation leans on absence of a socially-acceptable "I can't" channel; (ii) validator dispatch still runs downstream, so confabulated `synthesized` bodies that fail validation still get caught — and the comparison signal (validator-caught confabulation rate vs self-reported `insufficient_signal` rate) is itself the diagnostic for whether the envelope is helping.

## Backward compatibility: hard-opt-out, conditional on iter-024 experiment

**Default: (b) hard-opt-out.** Envelope ON by default for every llm-prompt task; templates set `prompt.envelope: false` to suppress.

Argument: confabulation rate is the bug being fixed. Opting in template-by-template guarantees the bug persists in every untouched template, which is most of them. (a) hard-opt-in is safe but doesn't fix anything at scale. (c) soft injection ships the envelope without the response-discriminant gain — the LLM still has no canonical place to say `outcome=insufficient_signal`.

**Gating:** the iter-024 24-hour experiment decides direction:
- Confabulation rate < 5% → ship opt-in (broad-rollout cost > benefit).
- Confabulation rate > 15% → ship opt-out and accept measurable regression on confused legacy prompts.
- 5–15% → second experiment on randomized template subset.

**Kill-switches:** `prompt.envelope: false` per-template; `ENVELOPE_DISABLED=1` env var on llm-resolver-vessel for fleet-level. Both zero-deploy.

## Concept directives land in `concept_directives` envelope field

Not via interpolation into the prompt body. Three reasons:
1. Interpolation requires templates to know about `{{envelope.directives}}` — violates backward-compat.
2. The LLM can be told via system-prompt framing: "the following are operator-authored directives, distinct from the user prompt" — separation prevents directive content being treated as task content.
3. Conflict reporting (`unmet_requirements.conflicting_directives`) requires stable identifiers — needs structured field.

**Pre-flight retrieval at `llm-prompt.ts:85`:** before `interpolate(template, context.variables)`, the resolver issues:
```
GET /concepts/search?shape=prompt_directive
                   &applies_to_template=<current_template_id>
                   &applies_to_goal_class=<envelope.goal_class>
                   &limit=5
```
Query filtered by *both* template id and goal_class — so a single concept can scope to "all boredom probes" OR "this specific template" OR "all top_level_goals on shapes containing X." Results populate `envelope.concept_directives`. **Do NOT split** into directives/evidence/patterns — all three are "things the operator wants the LLM to consider," LLM treats them similarly, single field.

Cβ (post-execution concept-graph augmentation) is unaffected by the envelope; it reads `outcome` + `unmet_requirements` from the response envelope to decide whether to write a new concept ("synthesis-failure on shape X happened N times; promote to operator-visible directive").

## Controversial design choice for adversarial test

**Dropping `parent_execution_id`/`trace_id` from the envelope.** Position taken: opaque ids are noise; provenance belongs in trace metadata.

**Adversarial alternative:** when `goal_class=self_reflection`, the LLM may need to read its own prior traces — without `trace_id` in the envelope, it cannot name what it's reflecting on. Audit should test whether self-reflection prompts degrade measurably under the lean envelope; if so, add a `trace_handles: {parent_execution_id, ancestor_trace_ids}` field gated on `goal_class=self_reflection` only.
