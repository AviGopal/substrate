## Critical Finding: Template Regression Root Cause Identified

**Template count: 2 returned by API, 28 in DB, total=28 in API response.**

Root cause is **NOT** a new regression — it is F-046 expressing via a **Redis stale-SET** mechanism now identified for the first time.

### How it happened (F-065 NEW)

The Redis key `activity:templates:list` is an SMEMBERS SET with **no TTL (indefinite)**. It contains only:
- `activity:⟨forge-vessel-for-shape⟩`
- `activity:⟨evolve-activity-self-contained⟩`

These are the last 2 templates seeded by bootstrap-seeder. The cache was populated with only 2 entries from a prior partial seeding window, and has never been invalidated. Subsequent `POST /v2/activities/templates` calls add individual `activity:template:<id>` keys but do NOT invalidate or update the SET key.

**Bootstrap-seeder ran successfully: 13/13 templates seeded at 09:03:40Z.** The seeder is not broken. The Redis cache is stale.

**Immediate fix:** `docker exec substrate-live redis-cli DEL 'activity:templates:list'`  
This forces a cache miss and repopulates from DB (all 28 templates will be visible).

**Permanent fix:** Add `EXPIRE` to the SET key in activity-api, or have bootstrap-seeder DEL the key before seeding.

### Template regression classification

- **NOT a new finding.** F-046 was already open.
- **NOT a SurrealDB scoping bug** (also investigated — activity table PERMISSIONS use `$auth.org_id` which doesn't work for API-key JWTs, but the LEGACY PATH in activity-api handles API-key auth with application-level filtering that returns all scope=global templates).
- **Root cause: Redis SET stale-population.** F-065 is the mechanism.
