## The pairing mechanism — concept-db `validates` edge

Three options considered; (b) wins:

- (a) **Metadata field `validates_template`** on V_X. Requires `activityTemplate` schema migration.
- (b) **Concept-db `validates` edge.** One ASSERT addition (`001-concept-tables.surql:90-99`). Bidirectional naturally. Free graph traversal: `SELECT ->validates->concept FROM <V_X>` returns X. Multi-validator support free. Symmetric query free.
- (c) **Naming convention `validate-<X_id>`.** Fragile (rename breaks); forces string-prefix-lookup hot path.

(b) is also the cheapest — one line of SQL.

## What V_X actually checks — the load-bearing V0

For X with declared `output_shapes:[Y]`, V_X answers: "given an instance y∈Y produced by X, does y semantically realize what X promised?"

Three layers, all primitives present:

**Structural** (free, already Zod): Y matches schema. `activityTemplate_write` structural validator at write time; `validate_proposal` at template-author time. **V_X work not needed at this layer.**

**Behavioral** (the load-bearing V0): V_X re-runs X under a held-out paraphrased input that should produce the same Y, checks Y_paraphrase ≈ Y_original on a shape-appropriate distance.

**Semantic** (operator-loop or LLM-judge): deferred to V0+1; ship when behavioral signal calibrated.

### The 5-task V0 behavioral V_X template

| # | id | resolver | purpose |
|---|---|---|---|
| 1 | `load_X_outputs` | `impulse-resolve` (`activityExecutionTrace`) | Get Y_original |
| 2 | `paraphrase_input` | `llm` (Haiku-tier, ≤$0.01) | Rewrite X's inputs |
| 3 | `rerun_X` | `activity` (dispatch X with paraphrased input) | Get Y_paraphrase |
| 4 | `compare_outputs` | deterministic shape-specific differ | Emit `validation_result` with passed, confidence, evidence |
| 5 | `emit_summary` | deterministic write | Joins the pool; validator-dispatch picks it up via output_shapes:[validation_result] |

**All existing resolvers from `repos/ias-executor-ts/src/hosts/goal-host.ts:598-673`.** The `compare_outputs` task's differ is the only novel per-shape piece — one differ per shape family (memo: embedding-cosine; code: AST diff; boolean: equality). Amortized across all X's producing that shape family.

Cost per V_X invocation: ≤$0.02 (one Haiku LLM call for paraphrase + one X re-execution).

## Goodhart mitigation by information asymmetry

The LLM call rendering V_X's payload receives ONLY X's `{name, description, input_shapes, output_shapes}` — **NOT X's task graph**. V_X cannot collude with X's internal structure; it can only check the shape contract X promised externally.

Concretely: `extract_companion_validator`'s prompt template receives `{{impulse:extract_template_result.output_shapes}}` and `{{impulse:extract_template_result.name}}` but **NOT `{{impulse:extract_template_result.tasks}}`**.

Plus held-out operator adversarial cases via `goal_verification_labels` (CLAUDE.md migration 101): V_X consumes `test_registration` impulses authored by operator OR hostile-peer vessels. The `audit-test-report` template's witness-presence check enforces this pattern for X=test today; the auto-author path defaults `behavioral_input_source: "held_out_test_registration_or_paraphrase_only"` — LLM can't generate its own test cases.
