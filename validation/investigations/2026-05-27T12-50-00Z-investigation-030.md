## Design summary

### 1. Trigger: operator-triggered via wrapped `/promote` endpoint

Recommend wrapping `activities.ts:3099` so before the flag-flip at `:3299`, the endpoint dispatches `promote-gate-resolver` as an activity execution. Operator intent ("promote this id") triggers automated evaluation; the operator no longer makes the judgment — they request the evaluation.

Rejected: (a) lifecycle-subscribed on every `activityTemplate_write` (recursion + throughput problem — every ribosome-extracted candidate would block the WS loop); (b) boredom-triggered (latency too high for S1→S2 promote responsiveness).

### 2. Similarity metric: Jaccard on `inputShapes ∪ outputShapes`, NOT on `state_space_signature`

`state_space_signature` is a sha256 hex prefix (`state-space-signature/spec.md:13`); the writer at `posterior-update.ts:268-289` stores opaque hex in `context_bucket` and never persists the underlying multiset. **Hash distance is meaningless; the multiset is unrecoverable from the row.** Template `inputShapes`/`outputShapes` ARE recoverable (`activity_template` row fetched at `activities.ts:3124`). Set Jaccard:

```
sim(P, T) = |shapes(P) ∩ shapes(T)| / |shapes(P) ∪ shapes(T)|
```

K=5 highest-similarity templates with `proposed=false` AND `sample_count > 0` (same gating as recommend at `activities.ts:4992`). Cheap (in-memory after one indexed query); aligns with foundation principle (activities operate on shape contracts).

Literal signature-equality falls out naturally as Jaccard=1.0 — the degenerate sub-case. Task-graph similarity deferred to V2.

### 3. Projection: weighted Beta-Binomial conjugate, Jeffreys-baseline-stripped

```
α̂ = 1 + Σ_i (w_i · (α_i − 1)) / Σ_i w_i
β̂ = 1 + Σ_i (w_i · (β_i − 1)) / Σ_i w_i
```

The `−1` strips the Beta(1,1) Jeffreys prior baseline written at `posterior-update.ts:247` and added at `impulses.ts:1374-1375` so the projection averages **evidence**, not double-counted priors. The leading `+1` re-introduces a single Jeffreys prior. Net: an unevidenced template inherits a flat Beta(1,1), not the sum of neighbors' priors.

**K=0 cold-start** (no shape overlap > 0, e.g., a novel output shape introduced by iter-028 C): fail-closed. `promoteGateDecision{decision:'refused', reason:'cold_start_no_similar', K:0}` → surface via decision-impulse audit stream. S2→S3 push-away principle (iter-026 Finding 5).

### 4. Threshold: **projected mean ≥ 0.6 AND projected sample-count ≥ 10**

Two-condition gate. 0.6 (not ribosome's 0.7 at `ribosome-extract.json:23`) because the gates measure different things — ribosome quality is per-trace properties; promote-gate is projected-forward-selection-success. The `≥ 10` floor prevents promoting on K=5 templates that each have Beta(1,1) (mechanical 0.5 mean from no-evidence). Both numbers environment-configurable; calibration via the shadow-mode experiment (closing paragraph).

### 5. Six-task activity template — load-bearing artifact

All resolvers exist in `goal-host.ts:598-673`. No new engine primitives.

| # | id | resolver | inputShapes | outputShapes | tier |
|---|---|---|---|---|---|
| 1 | `fetch_proposed_template` | `impulse-resolve` (constant pointer in config) | `[]` | `activityTemplate` | det |
| 2 | `find_similar_templates` | `impulse-resolve` (new pointer-type case `activityTemplatesByShapeOverlap`) | `activityTemplate` | `similarTemplateSet` | det |
| 3 | `fetch_posteriors` | `iteration` wrapping `impulse-resolve` (`thompson_posterior`) | `similarTemplateSet` | `posteriorBundle` | det |
| 4 | `compute_projection` | `validation` (rule-mode formula) | `posteriorBundle` | `posteriorProjection` | det |
| 5 | `evaluate_threshold` | `validation` | `posteriorProjection` | `promoteGateDecision` | det |
| 6 | `emit_decision` | `impulse-resolve` (write); also signal via `makeActivityResolver` return-value (`goal-host.ts:661-663`) | `promoteGateDecision` | `promoteGateDecision` (audit-mirrored) | det |

**Four new shapes** (each justified by type-safety needs the existing surface doesn't provide):
- `similarTemplateSet`: `{template_ids: string[], similarities: number[]}` — step 3 iteration needs both together.
- `posteriorBundle`: array of `{template_id, similarity, alpha, beta, sample_count}` — projection requires bundled access.
- `posteriorProjection`: `{alpha_hat, beta_hat, mean, total_samples, K}` — step 5's threshold-check is shape-typed.
- `promoteGateDecision`: load-bearing output; wrapping `/promote` endpoint needs typed return.

**One new pointer-type** (not a new shape): `activityTemplatesByShapeOverlap` as a case in `impulses.ts` switch, analogous to `thompson_posterior` (`:1310`) and `shape_producer_inventory` (`:1290`).

### 6. Rejection handling: stay-proposed + emit decision impulse; do NOT auto-deprecate

Three reasons:
- Refusals might be transient (network failure on `thompson_posterior` fetch).
- Auto-deprecation removes operator's ability to inspect *why*.
- Workbench review queue doesn't exist yet — but the `promoteGateDecision` audit-impulse stream IS the queue. Workbench can render a `decision=refused` filtered list whenever the surface lands. No new infra needed now.

### 7. Audit trail

**Minimum**: `promoteGateDecision` output impulse per evaluation (decision, projected α/β, K, similar_template_ids, threshold values used, reason on refusal) + standard `activityExecutionTrace` (the gate IS an activity, so this falls out automatically).

**Nice-to-have**: `lifecycle:promote:evaluated` on the substrate bus (post-Findings 3/4/5 closure). Until then, parallel `activity_template.promoted` (already at `activities.ts:3310`) with a new `activity_template.promote_refused` paralleling the existing refusal bus write at `:3250`.

**Bonus**: Thompson posterior on the gate-resolver itself falls out automatically — the gate IS an activity; its execution emits `activityExecutionTrace` with `success=true|false`; the Phase 18 chain-credit pipeline updates the gate's own α/β. Self-calibrating.

### 8. Failure modes — fail-closed across the board

- `thompson_posterior` errors (vessel restart per Finding 2, network): **fail-closed**. Decision: `refused`, reason: `posterior_fetch_failed`.
- K=0: **fail-closed**. Reason: `cold_start_no_similar`.
- Mid-range projection (0.5–0.6): **fail-closed by threshold** — no special handling.

Structural justification: iter-026 Finding 5's S2→S3 push-away. **Every refusal carries cited evidence** (K template ids, their α/β, the projection, the threshold). The gate IS a push-away mechanism — pushes back on operator promote-requests that lack projected forward-selection success. Fail-closed on uncertainty is the only configuration consistent with the principle.

## The calibration experiment: shadow mode

Run the gate in **shadow mode for one week**: `/promote` endpoint flips `proposed=false` regardless of gate output, but `promoteGateDecision` impulse is emitted on every promote attempt. After the week, join the decision stream against subsequent `variant_performance_metrics`:

| Gate said | Post-hoc 7d success_rate | Calibration verdict |
|-----------|--------------------------|---------------------|
| `promote` | `< 0.4` | over-permissive — gate let in losers |
| `refused` | `> 0.7` | over-strict — gate would have rejected winners |
| `promote` | `≥ 0.4` | calibrated for accept |
| `refused` | `≤ 0.7` | calibrated for reject |

Both rates computable directly from `variant_performance_metrics` against the already-emitted decision audit-stream — **one SQL join, no new instrumentation**. The week's data tunes the threshold (currently 0.6) and K (currently 5) from defaults to substrate-measured values, closing the loop on the gate's own calibration.
