# The seam map — recall and learning, 2026-08-21

**Scope.** 87 seams enumerated across both motions; every one validated against
three independent conditions (agreement / liveness / visibility). Produced with
**no production access**: agreement is settled statically from code, and every
liveness question is written as a runnable probe rather than guessed. The probes
are collected in §5 as a local-stack runbook.

**Why no live access.** An earlier run of this investigation embedded a recipe to
extract an internal production API key and was correctly blocked by the safety
classifier. The recipe was removed rather than worked around. This turned out to
improve the result: liveness claims are now explicit, falsifiable probes instead
of opportunistic reads.

**The one-line finding.** The impulse body stops threading at **hop 4** — the
engine clears its impulse store before the walk reads its outputs back, so the
walk pools a two-field metadata stub `{producedBy, executionId}` in place of the
real content, permanently (first-write-wins, no upgrade path). Everything
downstream — the reach digest, the trace, the signature, the credit, the minted
template — is bookkeeping over a body that was already replaced. **And nothing
observes the substitution:** the walk logs `new_shapes=1` for a stub exactly as
for real content.

## 2. The content-threading narrative — one impulse, end to end

Take a goal that survives intake: **"fetch repos/activity-api/package.json, count its dependencies, and write the number to a memory note."** Three shapes, two stages, a terminal write. It exercises every hop.

**Hop 1 — intake.** Over `/run-goal` the body is parsed at index.ts:14087-14117 and the trigger IIFE stamps provenance. Over the **federation ingress** (R1-intake-01) the body is rebuilt key-by-key with 8 keys and `learning_mode`/`ablation` never cross; over sync `/resolve` (R1-intake-02) seven opts keys are never parsed at all, so an operator's dispatch is graded AUTONOMOUS and carries no `operator:` tag. **First cut: the dispatch's own identity.** The content is fine; the metadata about who asked is already gone.

**Hop 2 — target inference.** `knownShapes` is fetched (R1-vocab-05) and `inferGoalTargetDecision` returns `{shapes:["httpResponse","shellResult","memoryNote_write"], confidence:0.7, alternatives:[…]}`. Two silent truncations live here. If the goal had said "run the test suite and record the pass count in a memory note", the named-shape route at gti.ts:435 returns `["test_suite"]` without consulting `isCompositionAsk` — **the write clause is dropped and the reach gate then grades against the truncated plan, so it greens** (R1-infer-09, reproduced in a local unit harness). And whichever route answers, if it is one of the six `return empty` exits, `remember()` is never called and the persisted `inference_confidence` is `null` for a decision made at 0.6-0.8 (R1-infer-08). Four in-process overrides then rewrite the shape plane without writing back (R1-override-11), so from here **the confidence recorded in `goal_execution_paths` describes a decision that is no longer in force.** The split (R1-split-12) marks `memoryNote_write` terminal; the walk receives a bare `string[]` and cannot tell a 0.8 decision from a 0.4 fallback (R1-walk-13).

**Hop 3 — selection.** The walk POSTs `discover-by-shapes` (R2-select-02). Server-side the candidate rows are drawn from Beta(α,β) and **sorted by that raw global draw** (R2-select-06). The composition blend and ψ are attached to the same objects but never enter the sort, and `scaffoldRank` consults `sampledScore` only as a `> 0.5` boolean and only for hollow scaffolds (R2-select-13). `optional_input_shapes` was never in the SELECT list, so declared-optional inputs gate (R2-select-07), and the walk recurses on them as hard sub-targets (R2-select-01). `composition_score` arrives null on every candidate (L3-edge-11: 35 candidates with up to 320 executions, all null). `successor_value` is dropped by the walk's key-by-key candidate rebuild (L3-psi-09). **So the producer is chosen by the global posterior and nothing else.** Everything the system learned about *this* state and *this* predecessor is either unwritten, unreadable, or unread.

**Hop 4 — binding, and the last place content is real.** The walk seeds the accumulated pool into the engine (R3-execute-01) — `metadata.shape` agrees on both sides and **this is the last hop where the impulse BODY crosses intact.** Then:

- The engine emits `lifecycle:execution:succeeded`, and immediately, because the first walk step has no parent id, `evictExecutionScope` runs `store.impulses.clear()` — the whole store — *before* the walk reads its outputs back (R3-execute-04). Every `store.get()` misses.
- The walk falls through to the stub branch and pools `{producedBy:'<templateId>', executionId:'exec_…'}` (R3-execute-03). `addToPool` is first-write-wins with no upgrade path, so **that stub is permanent for `httpResponse`.** Horizontal fan-out has no real-content branch at all, so any OR-edge bundle threads metadata for the rest of the walk by construction.
- **Nothing observes the substitution.** index.ts:9422 emits `new_shapes=1` for a stub exactly as for real content; `progressed` counts it; the reach digest renders it as `- httpResponse: {"producedBy":…}` and hands it to the LLM judge.

Step 2's prompt asks for `{{httpResponse}}`. `poolVars` published the stub, so the model receives a metadata object where the file contents should be. Had the shape been `obsidian:write_note`, the placeholder would not have matched at all — three interpolators carry `[\w]+` and a colon cannot match (R3-execute-02), producing a literal `{{…}}` in the prompt and a fluent wrong answer. Had the template used a bare `{{first_task}}` key, it would resolve to `undefined` because engine.ts:1104 assigns a field that does not exist (R3-execute-05).

**The impulse dies here.** Everything downstream is bookkeeping over a body that was already replaced by a two-field stub.

**Hop 5 — the trace.** The task record is rebuilt key-by-key onto the wire (R3-trace-09): `actualPrompt` and `response` are unconditionally `""` — no engine site ever sets them — and `failure_mode` is flattened to a bare `{type:'execution_error'}`. At ingest a closed whitelist (R3-trace-10) has no landing key for per-task `error`, the very field the sink designates as where "rich error info travels". `execution_trace_content` is written **after** the 200 was decided, fire-and-forget (R3-trace-12). A 4xx anywhere on this path is classified "fatal" and the spooled trace is `unlink`ed within 60 seconds (X-boundary-01) while the staleness detector, which can only see files that STAY, passes green.

**Hop 6 — signing.** `deriveSignatureShapes` tier 1 needs `input_impulse_shapes`; tier 2 reads `input_impulse_shapes`/`inputShapes` from tasks that were normalized to `input_shapes` — **zero key intersection, so tier 2 is structurally dead** (L1-credit-03). Tier 3 then keys the row on the PRODUCED pool. For light-dispatch, the fleet's highest-volume poster, that is 100% of traces (L1-credit-02). So the same `signature` column carries two incompatible meanings with no provenance marker (R3-trace-11).

**Hop 7 — credit.** `classifyReach` reads the tags. Light-dispatch never calls `/reach`, *and* it hardcodes `resolver_tier:'deterministic'`, which classifies as `all_deterministic` and suppresses **both** the VPM update and the conditional write (L1-credit-06) — ~10,166 root executions per 72h that teach nothing in either direction. For the walk, the verdict is POSTed to `/reach` (R3-reach-15) — but the pool-walk returns no `executionId`, so the whole walk's verdict patches its **last step's row**, and edit-intent dispatches send ids like `feature_compose:<sha>` that name git shas, not executions, so those reaches are discarded with an honest `MATCHED NO ROW` at the producer and no counter at the consumer.

What survives lands in `variant_performance_metrics` — the one store whose read side normalizes both id forms (L1-credit-09) — unless the variant has no row yet, in which case a new arm's first evidence is dropped in full (L1-credit-08). The **conditional** posterior is written to `context_thompson_scores` with a BARE `template_id`, and every reader binds the PREFIXED form (L1-credit-10 leg ii). **10,425 rows, addressable by nobody.** The walk's primary path never queries that table at all.

**Hop 8 — minting structure.** The child trace carries `parent_execution_id` (L2-structure-01), which is projected into a 4-argument call that omits the org, the chain and the execution id (L2-structure-02). The parent lookup reads the frozen AET shadow (L2-structure-03), and the CREATE cannot satisfy two ASSERT-!=-NONE columns it never binds (L2-structure-04). **No execution has ever minted an edge.** The only rows in the graph came from a batch reconciler, and they are read back through a string-vs-record-link comparison that matches nothing (L3-edge-11). The advertised `activityComposition_write` capability has no producer (L2-structure-05).

On the template side, a reached walk builds a composite trace by REBUILDING it — `resolverId` becomes a shape name, `resolvedConfig` is absent entirely (R3-trace-13) — which is the mechanical origin of the measurement in activity-api's own source: 98 of 98 tasks across 26 learned compositions had no arguments, and those compositions completed 6 of 61 runs (execution-traces.ts:257-261). The ribosome's independent trigger dies earlier still: its lifecycle object has no `goalSignature` and the placeholder resolver throws (L2-structure-09), while the producer logs "dispatched" and its rollback trigger counts dispatches.

**Hop 9 — read at the next selection.** ψ needs SF_BLEND (never lands — `writeTuningParam` binds JS null into `option<string>`, L3-tuning-06) **and** `completion_shapes` (never ships — psiInputs refuses all-or-nothing on a signature namespace mismatch, L3-psi-08). Two independent conjuncts, each alone sufficient: **0 blends in 476 recommends** (L3-psi-10). Relevance boosts query with prefixed ids against bare rows (L3-relevance-02). Oracle labels terminate in an in-memory field — 18,005 of them, none reaching anything that selects (L3-gvl-14). And the walk's own record of *how* it chose — candidates, draws, rejection reasons — is never persisted at all, because `POST /deliberation` has no producer (R3-reach-16).

**The honest ending.** Across both motions, **the only learned quantity that provably reorders the next selection is the global Thompson draw over `variant_performance_metrics`.** State-conditioned credit is written to an unaddressable key; composition evidence is written by a masked batch job and read through a type mismatch; ψ is starved at two independent conjuncts; relevance is keyed wrong; the oracle corpus has no consumer that selects. And the content that all of it is *about* stopped being real at hop 4.
