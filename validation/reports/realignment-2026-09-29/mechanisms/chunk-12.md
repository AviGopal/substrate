## How the kept and revived ones become discoverable

None of these is discoverable today except by reading `index.ts`. In priority order:

1. **Reach verdicts as a shape (M3, M4, M7, M8, M13, M32).** Each deterministic verdict is already a stable string (`deterministic:<family>`). Emit it as a `reachVerdict` impulse on the trace, which the spool (M31) already carries. The oracle families then become **ClassRow data rows** (M7), minted by the recipe ratchet (M8b) from agreeing recomputes (M8a), with M9's demand as the input. That gives one loop, and ClassRow rows are data, not code.
2. **Policies are already shapes, but read untraced** (`bodyHonestyPolicy`, `dispatchRatePolicy`, `walkBudget`, `lessonExecutionPolicy`). Route their reads through the traced resolve path so they show up in `execution_trace_content`. `walkBudget` needs a producer: 219 misses in 3d.
3. **Edit-intent routing (M1, M2, M3)** should become one admission decision recorded as a typed impulse (`editIntentDecision`: file, reason, route). The EARLY and post-walk routes then read the same record. This deletes the second copy and the 5×-recurring BUSY fall-through with it.
4. **The middle tier (M5b)** should be the walk's "adapt pathway" step, registered as an activity (law 2) and selected by Thompson. The step is fed by `recommendReachingPath` and keyed on shape signature, not wording.
5. **Human input (M26)** should resolve `human_input` / `solicitationResponse_write` through discovery to the live surface.
6. **The URL join (M33, M16)** should be normalized once, at discovery `/register` (the fixed point), so every caller gets one format. Delete the per-site ternaries after that.
