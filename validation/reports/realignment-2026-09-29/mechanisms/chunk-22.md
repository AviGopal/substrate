## Where the evidence comes from, and a trap in reading it

The substrate holds two copies of ias-executor-ts, and only one of them is live.

- **The live copy is `/vessels/ias-executor-ts`**, the image layer. It has no `.git`. The systemd units run from `/vessels/<vessel>` (for example `ExecStart=… /vessels/goal-host-vessel/src/index.ts`), and every consumer's `node_modules/@avigopal/ias-executor-ts` resolves to it.
  - Its `dist/engine.js` and `dist/adapters/activity-api-trace-sink.js` have mtime **2026-09-28 15:55:40**.
  - That is after the last commit, so line numbers below are valid for both trees.
- **The authoring clone is `/workspace/git/vessels/ias-executor-ts`**, HEAD `700ceff` (2026-09-28 15:50, Substrate Autonomous).
  - Its own `dist/` is **frozen at 2026-08-16 11:20**. That is 34 commits behind: no `.js` file in it is newer than 09-01.
  - The `/workspace/git/vessels/*` `node_modules` symlinks point at this stale dist.

I read the clone first and nearly reported that every ias landing since 08-16 was inert. It is not: the drafter's typecheck runs under `RUNTIME_ROOT = MITOSIS_RUNTIME_DIR ?? "/vessels"` (`development-vessel/src/shape-vocabulary.ts:36`, `feature-compose.ts:195`). Absence in one tree is not absence. Any detector has to read the tree the unit actually executes.

## Cross-cutting observations for this area

- **Fix by addition is the recurring failure here.** A (a second replayer and `_quarantineFile2`) and K (three `interpolateBoundValues`) each took 3–5 autonomous landings, and each landing **added a copy** beside the broken one. The gap was then treated as addressed. The detector should be structural: a landed diff that introduces a symbol name already defined in the same file, or a numbered sibling (`…2`), is refused or at least filed. This is the "same issue recurring for the same reason" the user named.
- **Two collector claims were stale or wrong:** trace-spool "no replayer" (it is drained) and cost/tokens "0" (live). One more was wrong outright: agent_fill "default off" (it is on in production). Read the running tree and the live tables, not the notes.
- **A declared trigger or field is not a live one:** ribosome-extract declares a `postExecution` trigger that nothing emits (C), `materialsConsulted` is written but not stored (M), and 3 of 4 bus events have no reader (B). All three are write-read mismatches. They need a round-trip probe per declared edge, not grep for presence.
- **Delete candidates**, all ias `src`: D (forge and examples), S2 (TOP_K), J (`makeLLMResolver`, after migrating the 9/day), the private `resolveVesselEndpoint` (N), `hosts/__example__` (T), and F as a stand-alone script. Git history is the archive. The `/vessels/*-mitosis-*` directories carry stale copies of several of these and should go with the cutover cleanup.
