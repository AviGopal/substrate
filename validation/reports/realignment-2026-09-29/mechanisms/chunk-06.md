## Where kept and fossil mechanisms go (applies to every row)

- **Kept or revived → discoverable by shape, not by memory file.** Each mechanism either already advertises a
  shape through discovery (for example `attemptLedger` has an `auto-bridge-*` row, and `unaccounted_landing_scan`,
  `docs_align_tick` and `author_producer` run as `satisfier:*`), or it should be minted as an activity whose
  output shape names the mechanism. The satisfier path has no `activity` row: 179 ids, 9,016 runs, 52% ok, per
  live-activities §2. So each kept satisfier also needs an activity row (law 2) to become selectable and retirable.
  A second channel is a class-grain `concept` in concept-db (P260) that names the mechanism, its seam and its
  failure modes, recalled at prompt-build. The concept is reachable over p2p through the hub's concept-db. It is
  not a local file.
- **Fossils.** Code fossils are deleted from `src`, and a `concept` row (type `fossil`) records the commit hash,
  what the mechanism did and why it died, so the history stays recallable without the code. Activity-row fossils
  get the retire primitive (19ae84e) with a `retired_reason`. Volume-only scripts (`/workspace/active-scripts`,
  never pruned by `cp -f`) are removed there. Their history is in the super-repo git log.

   general fix is registration replication (#45) plus routing by shape. It has been specified twice and never built.

   stalled) and #50 (91/91 zero-emission runs) have the same defect as the memory-budget-check `SuccessExitStatus=0 1`.

   but is not applied. The attempt ledger (#36) and failure memory are the kept seams that should absorb retries
   instead of forking.
4. **Stale records.** #2 (bump-submodules was broken on 08-12 and succeeds now) and #28 (probe paths fixed 09-25).
   Other synthesis chunks that cite these as broken should be corrected.
