# Dossier: codebase-bloat-fossils

**One line:** the system (and its operators) create artefacts at many seams: activities, resolvers, drafts, commits, scripts, runtime files, tables and docs. None of those seams asks who reads the thing, and nothing retires an artefact once its reader is gone. So fossils, duplicates and residue build up faster than the occasional operator cleanup removes them. The worst live generator is the rhythm `self-maintenance` goal ("detect drift, then commit and push"). It has committed runtime residue into git at least eleven times. The system graded each of those commits as a success.

Sources: `classes/codebase-bloat-fossils.json` (61 attempts, 56 problems, 7 claims), `classes/_mech_chunks/*`, `raw/git-deployment.md`, `raw/git-super-2.md`, `raw/openspec-{5..10}.md`, `raw/live-*.md`, `raw/transcripts-4.md`, and memory `project-operating-model-route-around-then-encapsulate-2026-09-29.md` and `feedback-search-prior-art-before-building-anything-2026-09-28.md`. ## 3. Why it recurs: the missing shared capability

The ~20 recorded root causes reduce to one missing invariant: **nothing is admitted without a named reader, and nothing is retired when its reader is gone.** Admission can happen at many seams (commit, mint, draft write, runtime write, script add, migration). Retirement exists only as scattered, per-plane special cases. Each is a *specific path*: a script prune, a success-rate sweep, a mitosis pruner, a trace valve, a memory retire. None is a *general resolver at the shared seam* that the walk uses first and the loop grades (operating model 09-29). The system therefore cannot notice that the same fossil keeps coming back for the same reason. Every instance becomes a fresh operator cleanup, and those cleanups are invisible to the learning loop (law 6).

**Shared capability: "reader-proven liveness" (admit-with-reader / retire-without-reader)**, at two seams:

- **Admission seam = the commit/mint chokepoint.** One deterministic, traced resolver that every autonomous commit and every mint passes through. It classifies each path or row as *source with a reader* versus *artefact/runtime/duplicate*. For a commit, it stages only source trees and refuses emit, cache, state, leases, `{{…}}` paths and paths outside `ALLOWED_TOPLEVEL_DIRS`. For a mint, it runs `producerExistsForShape` first. `git-hooks-ledger/post-commit` already runs on every substrate commit on both nodes. That makes it the one seam known to be on the path, and the natural place for the verdict to be *observed* even before it can *refuse*.
- **Retirement seam = `activity.retired` (and its peers for files, scripts, docs and tables).** One reader-check activity (compost) across planes: 0 readers or 0 invocations over a window, with evidence, leads to retire, then archive, then delete. It is graded by traces, and its output is chained into goals (decompose the hub file, delete the orphan script, archive the openspec change). The primitive already exists and is respected: only 3 runs from 2 retired rows in 5 d. What is missing is a driver that reaches it.
