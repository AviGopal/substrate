# Dossier: credential-hygiene

**Class, one line:** credentials are handled by hand at every step of their life: minted, stored, carried, sent, rotated, validated, redacted and retired. Each step has its own ad-hoc path (two env files, inline headers built 447 times, grep and sed "redaction", keys cached at session start, per-route auth). So keys leak into transcripts and files, rotations orphan the keys issued under the old secret, some routes accept no key or any key, and a dead credential reads to the fleet as "nothing there". The class has never had a detector or a gap of its own, so each instance was found by an operator, patched by that operator, and then came back.

Sources: `classes/credential-hygiene.json` (0 attempts, 1 problem, 0 claims; source memory-6; 7 recurrences, 07-24 → 08-07). The class file is thin because round 1 folded the class into `endpoint-routing`, and `raw/critic-2.md:77` asks to split it back out ("leaked keys … are a security-remediation class, not a routing defect"). The timeline below is rebuilt from `raw/memory-{2,3,4,6,7,8,9,10}.md`, `raw/git-small.md` (the `auth-credential-plumbing` and `write-read-mismatch` sections), `raw/git-super-2.md` R7, `raw/transcripts-1.md`, `raw/critic-2.md`, `raw/openspec-9.md`, `raw/validation-other-3.md`, `raw/live-resolvers.md`, records `reports-4/5/6/8.json`, `_mech_chunks`, and super-repo git (`git show` on each hash cited).

## 2. Root causes

1. **No credential seam.** A credential has no single owner for mint → store → carry → attach → validate → rotate → retire. On 09-29:
   - **Store:** two env stores, `/etc/substrate/env` and `/workspace/.substrate-secrets`. The second overrides the first as the later EnvironmentFile. Today they agree on all 14 compared names; historically they diverged 3+ times.
   - **Attach:** 447 inline `ApiKey ${…}` header constructions and 15 inline `Bearer` constructions across vessel src, plus `X-API-Key` in 4 places, and 8 separate `authHeader(s)` helpers. concept-db `X-Api-Key` and `Authorization: ApiKey` land in different scopes (4 vs 13 rows, memory-3:187).
   - **Validate:** per route. Goal-host has none. activity-api and discovery have their own middleware. The libp2p ingress uses the transport's own key.
   - **Rotate:** a manual sequence (bridge, re-issue, drop bridge) whose re-issue step is not bound to the rotation, so 09-10 rotated without re-issuing.
2. **Keys are frozen at process start** (law 1): the MCP cockpit, `SECRET_KEYS` built once at module load (validation.ts:26), and provider keys read at module load. A rotation is invisible to a running holder until a restart, and the holder cannot tell "my key was rotated" from "the peer is gone".
3. **Credential failure is rendered as absence.** A 401 becomes `[]` / "no producer" / "could not find goal-host" / "covered 0/0". Auth traces carry no reason (`error_message:null`, `org_id:unknown`). Rate limiting is reported as revocation. So the class hides inside endpoint-routing, goal-walk-floor and spend-envelope stories. That is why round 1 folded it.
4. **Redaction by text tools, in operator hands.** Leaks happen at the operator/agent boundary: grep, sed and cat of key files, `make -n`, `git add -A`, and printing a freshly minted key. The only machine gate is a commit-time gitleaks hook in the super-repo. It does not cover transcripts, logs, memory, the working tree (untracked files such as the relay key) or the container clone's own commits unless that hook chain is installed there.
5. **Fossil and default secrets stay live.** `FEDERATION_SIGNING_SECRET` is carried by nothing that reads it. The `dev-secret-change-in-production` fallback appears in 6 identity files, and only the CURRENT secret is guarded at boot, not PREVIOUS (the 31-char PREVIOUS is a suspected live instance). The DB root password is passed in argv.

## 3. Why it recurs: the missing shared capability

**Missing capability: a credential lifecycle plane.** Credentials should be a first-class shaped resource with one reader and one writer seam: `credential` / `credentialStatus` shapes served by identity-vessel, where the data lives (law 11), plus a fleet-wide attach/validate path in the shared `VesselDaemon` / `@avigopal/vessel-discovery-client` layer. The plane would provide:

- **(a) attach:** the client asks for "a credential for shape X at peer Y" and gets back a header, a scheme and an issuer. Nobody hand-builds `Authorization`.
- **(b) validate:** every inbound route passes through one middleware, including goal-host and the libp2p ingress, and every rejection carries a typed reason (`revoked | rotated | wrong_issuer | rate_limited | malformed | missing`).
- **(c) rotate as one activity:** mint new → re-issue every holder → verify each holder by effect → drop PREVIOUS. Holders pick up the new key at use time and not only at start.
- **(d) a leak detector activity** that scans the places secrets flow (transcripts, journals, memory store, working tree including untracked files, pool) by fingerprint. Each hit is filed as a gap carrying a rotation step.

Today every instance is found by an operator, patched in one call site or one file, and written up as an operator-memory law that no runtime reads. No gap in the live store names the leak strand. Of 6,285 gaps on node 1, the credential-titled ones (13 matched by title) cover only 401 plumbing. None cover leaks, the relay key, the transcript keys, argv exposure, goal-host's missing auth, the retire-sweep Bearer or the reasonless auth traces. So the system cannot learn a disposition for the class (law 7) or detect it without the operator (law 6).
