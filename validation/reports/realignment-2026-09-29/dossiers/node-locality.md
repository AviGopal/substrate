# Dossier: node-locality

**The class in one line:** state, detectors and measurements are built as *node-local* things: a JSON file at `process.env[X] ?? '/workspace/…'`, a `sql()` call against a local SurrealDB, a loopback `127.0.0.1:82xx` default, or a pool record on one node. As soon as there is a second place (canary vs substrate, hub vs spoke, node 1 vs node 2), that state forks, a detector runs where its data isn't, and a measurement is taken on the node the operator happens to be looking at rather than the one the work ran on. Each fix moves one store or masks one unit, and the next store is born node-local again.

Sources: `classes/node-locality.json` (22 attempts, 38 problems, 8 claims; the collectors' recurrence fields add up to 150, but the shards overlap, so that sum is an upper bound and not a count), `raw/node2-runtime.md`, `raw/git-deployment.md`, `raw/git-super-2.md`, `raw/federation-relay.md`, `raw/live-pool-memory.md`, `raw/concept-db-db.md`, `raw/timers-readers.md`, `raw/transcripts-4.md`, `raw/openspec-7.md`, `raw/openspec-10.md`, `raw/memory-adjacent.md`, `raw/memory-7.md`, `raw/docs-1.md`. I made the live checks myself on 2026-09-29 between 04:56 and 05:10 UTC against `substrate-live` (node 1) and `compose2-live` (node 2). Everything was read-only. Related dossiers: `endpoint-routing.md` (loopback and pinned addresses) and `sync-deploy-drift.md` (pull-sync). ## 2. Root causes

1. **The store-creation idiom is node-local.** New state is created as `process.env[X] ?? '/workspace/…'` JSON files (12 such file defaults in development-vessel src alone), or in pool records and in-process memory. None of these is a shape served by one holder. Examples: gaps.json, memory notes.json, expectation-calibration, gap-class-posteriors, the attempt ledger, reached-commands, goal-host failure memory, policies/*.json, the scenario store, metrics/*.jsonl, and rhythm records including `operator_pause`. With one node, "the file" and "the store" are the same thing. With two, each becomes a fork: learned state diverges (landed_commit false_closes 2,149 vs 31; failure memory 1,772 vs 277; reached-commands 10,624 vs 451; policy rev 25 vs 9).
2. **Writes and reads take different addresses.** Reads route through discovery, while writes use a loopback env default (the concept-db writes; `uiQuestion_write` → :8270). Gap-store writes forward to the holder, but node 2's reads, lifecycle tick and gap-compose watchdog use its own frozen file. The endpoint-routing class shows up here at node grain.
3. **Detectors query storage directly instead of resolving by shape.** joint-liveness (`joint-liveness-tick.ts:53 sql()`), validator-liveness and compose-drift open `SURREALDB_URL` directly, and dev-vessel resolvers read `/workspace/metrics/spectral-gap.jsonl` by a hardcoded path. On a DB-less node they fail, so they get masked, and the signal is discarded.
4. **Unit enablement and placement are profile-blind.** `substrate-pull-sync.sh:290` enables any `disabled` timer. Placement is decided by two inventories that disagree, plus container-layer drop-ins and hand masks. Node 2 therefore cannot be reproduced from image + env + volumes (a law 11 violation).
5. **Measurement and verification are taken on the operator's node.** Examples: hub vs spoke (07-31, 08-05), workstation vs hub (08-17), node 1 rebaseline and pause only (09-26/27), node-2 class2 closes (09-28), and the federation oracle, which is vantage-limited to node 2's own netns.
6. **Production nodes are not on the overlay.** Node 1 has no transport, and node 2's transport is direct-only and undialable. The only cross-node channel is 9 pinned `host.containers.internal:18xxx` HTTP env URLs, and federation carries no replicated state. The capabilities that do exist (trace replication, discovery peer fan-out) cannot engage: the first has no peer, and the second fans out only when there is **no** local producer.
7. **Topology changes are not followed by an audit of single-node assumptions.** class2-resolves-on-localhost had stood since 07-07. The 09-26 split left every such assumption in place, and the forwarder was then applied one pass at a time (transcripts-4 lesson 10).

## 3. Why it recurs (the missing shared capability)

**Missing capability: "one authoritative holder per state shape, placed by data locality, reachable from every node through discovery over the overlay; measurements and verification are taken at the holder, and other nodes abstain."** It would live at the **store seam**: the helper every resolver or script calls to get or put durable state, and the detector-to-data seam. That seam does not exist. Every new store is therefore written with the local-file idiom and is born node-local, whatever was patched before. Each patch (calibration → holder, class2 abstain, spend reader) moves **one** store to the right pattern by hand, and the next store (the attempt ledger, rhythm pause, memory, policies, metrics) repeats the defect. Pull-sync then converges these node-local assumptions onto whatever node exists, which is how the watchdog incident happened.

The general mechanism was built once: `trace-replication-tick.ts`, a libp2p pull with a watermark. It covers one shape, and it runs on the one node that has no transport and so has 0 peers. The only generalizable pattern that works today is the **discovery-summing reader** (`gap-to-feature.ts:4084`: read every producer discovery lists and combine), together with **holder-abstain** (`5d0788b`). Neither has been lifted into a shared helper.

## 7. Retire condition (measurable, checked continuously, from a foreign vantage)

The class is retired when **all** of the following hold for 7 consecutive days, measured by a probe that runs **node 1 → node 2 and node 2 → node 1**. It must not run from inside one node's netns. Each probe needs a positive control: a known-present payload read through the same address.

1. **Cross-node read-your-write per state shape.** For each of `substrateGap`, `memoryNote`, `timeShapedRhythm` (including the pause), expectation-calibration, gap-class-posteriors, `attemptIntent`, the llm model policy, the concept usage/lesson write and `uiQuestion_write`: a write issued on node N can be read through a discovery-routed resolve from node M within one sync interval, for every ordered pair.
2. **No fork.** Node 1 and node 2 agree on the rhythm α/β/pause for every family, the memory note count, the gap count (within the forwarding lag) and the policy revision. Equivalently, node 2 holds none of these as independent files.
3. Node 2's journal shows 0 `Unable to connect` to a loopback `127.0.0.1:82xx/8000` per 24 h, and 0 `recall SKIPPED`.
4. `systemctl --failed` on every node lists no detector unit. Pull-sync logs no `ENABLED` for a timer whose service dependency is masked on that node. No unit is masked by a container-layer symlink, meaning a recreate from image + env + volumes reproduces the node.
5. `git status --short scripts/` is clean in node 2's super-repo clone. Pull-sync reports dirt when it is not.

**Today every clause fails** (§5), so the condition is not vacuous. The first clause is the load-bearing one: it is what the user asked for ("everything reachable from everywhere over p2p"), and the other clauses are what violate it today.
