# Audit — the learning mechanism, the database, the architecture

## Verdict in one paragraph

The substrate learns. Credit and blame reach the graded posterior store, reproducibly, and the store correctly condemns arms that fail (`proposed_pattern_authored_obsidian_assist_active_note`: α 216.8 / β 1265.7 against a 0/22 observed reach rate). What is broken is almost entirely *reporting and transit*: the field the cockpit reads to answer "did this teach anything" (`learning.alphaBetaDelta`) is a hardcoded constant describing a POST to a table nothing reads; the exploitation head of `/recommend` orders on exit-status UCB rather than the graded posterior; the recommend-fallback candidate path strips α/β in transit so two selection gates are inert; the impulse-relevance counterfactual arm is structurally pinned so the pool can only grow; and one declared learning loop (CI outcome → template credit) writes to a table with four readers and zero writers. Separately, none of the three factors in the architecture's own convergence rate (λ₁ · ρ_sample · κ⁻¹) is exposed as a queryable shape, and the one spec-faithful implementation of the stability inequality has no consumer at all. Several of this session's most alarming-sounding hypotheses were refuted on verification, and the refutations are as informative as the confirmations.

## Does it learn? (specifics and evidence)

Yes, on the paths that matter, and the evidence is store-level rather than log-level.

UNTRIED_PRIOR_BETA)` to every row; `:186-189` widens `ADMISSION_CAP` to 200 specifically so SQL truncation cannot pre-empt the draw ("sample-then-truncate, the correct order"); `:403-410` sorts by that draw. goal-host's `readCandidateShapes` (`repos/goal-host-vessel/src/index.ts:5993`) reads `x.sampled_score` first, and its stable `scaffoldRank` sort preserves that order — so the walk's `.find` takes the sampled-best genuine producer. An earlier finding claiming the walk "performs no draw of its own" was refuted on exactly this: the draw is server-side.
- **α credit flows and reproduces.** Bracketed store reads on `satisfier:shellResult`, one deterministically-graded goal each: α +0.7440 / β +0.1890 and α +0.7500 / β +0.2497, n +1, succ +1 both times. ## What is preventing growth

Ranked by how much each attacks the stability condition or a convergence-rate term. Severities are the post-verification corrected ones.

### 1. SEL-3 — the exploitation head ranks on exit status, not the graded posterior (major; attacks λ₁ via mis-ranked reuse, and κ via a mislabelled instrument)

In the default regime (no `expected_output_shapes`, SF_BLEND off — `activities.scoring.ts:126` defaults SF_BLEND to 0), `/recommend`'s exploitation pool sorts on `b._ucb_score - a._ucb_score` alone (`repos/activity-api/src/routes/activities.ts:6836`). `_ucb_score = ucbScore(total_executions, successes)` (`:6305-6309`, `:6611-6613`), and `successes` comes from `v_activity_score`'s `count(success = true) FROM execution` (`sql/schemas/021-paradigm-computed-views-v3.surql:29`) — the template exit status. The paradigm overlay replaces only α and β, which UCB never reads. So the reach grading is bypassed for the exploitation argmax, and the trace still labels the pick `method: 'thompson_sampling'` / `rationale_tier: 'thompson_sample'` (`:6641`, `:7350-7357`) — an audit of the trace records a decision that did not happen.

Scope correction the verifier added, which *broadens* it: even when `expected_output_shapes` IS supplied, the shape re-sort at `:6846-6862` runs on a list already truncated by the UCB-ordered head/tail assembly, so exit-status UCB gates candidate *membership* in every regime. Scope correction that narrows it: the Beta sample is the explicit tiebreak in the exploration pool (`:6819-6822`), and every template lacking a `v_activity_score` row gets an identical constant `_ucb_score`, so Thompson genuinely decides ordering among ungraded candidates.

Smallest fix: make `ucbScore`'s mean come from the overlaid α/(α+β) rather than `scores.successes/total_executions`. One expression.

Not measured: I could not exercise `/recommend` live to confirm top-1 determinism — this box masks activity-api and the reachable sibling substrates rejected the key with `INVALID_API_KEY`.

## Incorrect attribution

- **The transparency field describes a different channel than the one selection reads.** CODE-1 above. `alphaBetaDelta` → `impulse_shape_activity_score` (no reader); `thompson_posterior` → `variant_performance_metrics` (written only by `/reach`). This is precisely how the earlier session contradiction arose — goal-host reporting `alphaBetaDelta: []` while credit demonstrably flowed.
- **A reported constant that is not a measurement.** `dAlpha: res.ok ? 2 : 0` reports an HTTP status; `dBeta: 2` reports intent even when the POST was rejected or threw. The handler's actual increment is 3.
- **A Thompson label on a non-Thompson decision.** SEL-3: `selection_metadata.method: 'thompson_sampling'` and `rationale_tier: 'thompson_sample'` on a pick ordered by exit-status UCB.
- **A nonexistent arm returns a well-formed Beta(1,1).** Resolving `thompson_posterior` for `zzz-nonexistent-arm-qk3x9` returns `{"loaded":true,"alpha":1,"beta":1,"sample_count":0,"scope":"global"}` — byte-identical to a real never-selected arm. The only discriminator is `scope` (fabricated → `global`, real org rows → `org`), documented but easy to miss at `docs/impulse-types/thompson_posterior.md:60`. Any audit that enumerates arm ids from one source and resolves posteriors from another silently scores typos and retired arms as fresh Beta(1,1) cells — inflating exactly the ρ_grow term the stability condition depends on. This trap consumed one confirmed finding in this session (see refutations).
- **The metrics view cannot display health for the arms that run most.** `activityTemplatesByMetrics {limit:400, minExecutions:0, sortBy:'total_executions'}` returns Success Rate `N/A` for every one of the top ~24 rows: `validator-dispatch | N/A | 1286243`, `slot-binding | N/A | 319650`, `create-shape-provider-goal | N/A | 175142`. The same arms resolve concrete counts via `thompson_posterior` (validator-dispatch 223007/1063236 = 17.3%; create-shape-provider-goal 0/175142). `create-shape-provider-goal` has failed 175,142 of 175,142 and shows as N/A rather than 0%.
- **The instrument silently discards its limit.** `activeDispatches` accepts `limit` and hardcodes `slice(0, 50)` (`index.ts:14873-14876`); the backing store is an in-process `Map` trimmed to 100 (`:15306`, `:15443-15445`), and `GET /executions/:id` 404s for anything evicted. Any "fraction of dispatches" statistic taken through this route describes 50 records held by one process. In this window 22 of 50 were one goal text repeating on a ~30-minute rhythm — the frame describes a stuck rhythm as much as it describes grading.

## Intent vs code vs practice

- **Schema says α = successes+1; code makes α a fractional, decayed, reach-gated accumulator.** Four sites: `sql/001-init-schema.surql:173-179`, `sql/060-thompson-sampling-fields.surql:11-12`, `sql/003-goal-execution-paths.surql:54,58`, plus `models/schemas.ts:1812-1814` and `:1855` (`alpha: z.number().int(), // success_count + 1`). Practice: `feature_compose` α 92.87 / β 32.12 against succ 165 / fail 0 — the documented invariant would require β = 1. The correct semantics exist only in a TypeScript comment (`paradigm.ts:2156-2158`).
- **The actual transform (CODE-2, minor).** `computeDeltas` returns `{alphaDelta: y, betaDelta: 1 − y}` where `y = 0.5 + 0.5·(0.5·costScore + 0.5·productivity)`, `costScore = 1/(1+cost/0.02)`, `productivity = min(1, outputs/4)` (`posterior-update.ts:280-315`, defaults `:251-253`, gate `:246` default-on). A trace with cost 0 and no output impulses gives exactly y = 0.75. **β rising on a success is by design**, and decay toward (1,1) with a 3-day half-life is applied *before* the delta (`posterior-aggregator.ts:188, :202-203`; `posterior-update.ts:802-814, :919-920`) — which is why a stale row moves slightly under 0.75/0.25. The defect is that operator-facing docs still say otherwise: `docs/impulse-types/thompson_posterior.md:134` presents weighting as an unimplemented hook, and `openspec/changes/2026-04-26-impulse-activity-loop/design.md:2132` states "the **success** side is unconditional `α += 1`". **Scope**: this rule is *not* global — `context_thompson_scores` on the re-derived-bucket path is still binary (`execution-traces.ts:3177-3178`), as is the repair-signature prior (`repair-signature-consume.ts:34-35`).
- **The type doc omits its own two dominant divergence causes (ATTR-6, minor).** `thompson_posterior.md:65` names only chain-credit fan-out and decay deltas. It never mentions the honest-reach gate (`posterior-update.ts:815-828`; `ungraded → {0,0}`, so counters increment while α/β do not move at all) or graded yield. The payload block `:52-56` puts `success_count`/`failure_count` beside α/β with no note that they are computed on a different success definition. This doc sent an auditor down the wrong branch in this very session. (Note: `grep` silently truncates on `repos/activity-api/src/routes/impulses.ts` because of an embedded NUL byte and reports zero matches for the resolver that plainly exists — use `rg`.)
- **The useful reading of that divergence.** The obsidian arm exits `completed` 1306/1383 = 94% while its graded posterior says 14.6%. The 79-point gap *is* that arm's hollow-completion rate, and the 0/22 reached rate measured here says the graded number is the honest one. Corroborated in-repo: `src/routes/__tests__/proven-failing-paths.test.ts:70-76` records 398 of 2,392 templates reporting `success_rate` 0 while `successful_executions > 0`.
- **Law 1 at the law-3 chokepoint (F5-LAW1, minor — downgraded).** One genuine remaining instance: `SIGNATURE_CLUSTER_N_MIN` (`repos/activity-api/src/routes/activities.ts:188`) is the partial-pooling sample floor deciding whether the selector uses the leaf or the cluster posterior, frozen by `parseInt(process.env... ?? ## Refutations worth keeping (method lessons)

Only those with a recorded rationale, and only where the *method* generalises.

1. **"No shape exists for the spectral gap" was produced by grepping a shape-NAME list.** A shape-name list cannot show field names inside response bodies; the query measured the naming convention and was structurally incapable of returning a hit. A live resolve of `generativeFrontierGapReport` returns `fiedler_lambda2: 0.003, headroom: 0.0023184, star_ratio: 0.2272, components: 11`. Also: `λ₁` is not a separate quantity from the Fiedler value — `spectral-gap.ts:239` is literally `const lambda1 = genuine.fiedler_lambda2`.
2. **"The mint-dedup net catches nothing — 0 of 95" was a code comment re-reported as a measurement.** Every number came from a comment dated 2026-08-11 written by a prior agent — the channel's own reporting about itself, 8 days stale. The gate is `TS_SUFFIX_RE.test(name) || TS_SUFFIX_RE.test(id)`, and `activity-create-variant.ts:565-571` sets `id = ${baseId}-${Date.now()}` at three live call sites including the two highest-volume mint loops (`mitosis-tick` 30,216 executions, `draft-gap-closing-activity` 8,467). The auditor never checked the id disjunct.
3. **"Self-minted arms are starved — all 14 uncredited are learned-*/auto-bridge-*" is the threshold acting as the filter.** The 14 were *selected by* `alpha == 1`. Mean α-residue-per-success by class: core 0.455, **auto-bridge 0.676 (highest)**, gap-closing 0.552, compose- 0.435, learned- 0.064. 16 of 27 `learned-*` arms with successes carry α > 1 (`learned-auto-bridge-problem-detection-1r2k9x` at α 50.73). 4. **"The walk performs no draw of its own" — the grep was scoped to one vessel.** The draw is server-side (`discover-by-shapes.ts:295-299, :403-410`), and its comment names goal-host's `readCandidateShapes` as the consumer. Scoping a grep to `repos/goal-host-vessel/src` guaranteed the miss.
