## Part 9: Critical Safety Checks

### Before Archiving ANY File, Verify:

#### 1. No External References
```bash
# Search for references to file being archived
grep -r "FILENAME.md" *.md repos/*/README.md repos/*/*.md
```

#### 2. No Unique Critical Information
- Read file completely
- Check for design decisions not documented elsewhere
- Check for API contracts or interfaces
- Check for debugging techniques or discoveries

#### 3. Not a Foundational Document
**Never archive:**
- README.md files
- CONTRIBUTING.md
- LICENSE.md
- Architecture overview docs
- API specifications
- User guides

#### 4. Has Clear Superseding Document
- Identify which document replaces it
- Verify replacement has all critical info
- Document the supersession in archive README

### Archive README Template

Each archive directory should have a README explaining:

```markdown
# Archive: [Category Name]

**Archived**: [Date]
**Reason**: [Why these files were archived]
**Superseded by**: [Link to replacement docs]

## Context

[Explanation of what this work accomplished and why it's archived]

## Files

- **file1.md** - [Brief description]
- **file2.md** - [Brief description]

## Key Insights Preserved

[Any critical discoveries or decisions that should be remembered]

## References

[Links to final documentation that incorporates this work]
```

## Part 12: Future Documentation Hygiene

### Recommended Practices

1. **Use `.archive/` for completed work**
   - Move progress snapshots after milestone completion
   - Keep only final/authoritative docs in root

2. **Naming convention for snapshots**
   - Prefix with date: `2026-02-06-session-memory-progress.md`
   - Use suffixes: `-progress`, `-snapshot`, `-draft`
   - Makes it clear when file can be archived

3. **Consolidate aggressively**
   - After completing work, create ONE summary document
   - Archive all intermediate progress docs
   - Link from summary to archive if needed

4. **Regular review cycles**
   - Monthly: Review root docs, archive completed work
   - Quarterly: Review archive structure, consolidate further
   - Yearly: Consider compressing old archives

5. **Documentation lifecycle**
   ```
   Draft → In-Progress → Review → Final → Archive (after 30 days)
   ```
