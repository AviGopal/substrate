# Docker Config Environment Variable Resolution

## Problem

When running metabob-opencode in Docker containers, the wrong config was being loaded because:
1. Workspace configs (from mounted volume) were overriding Docker configs
2. Environment variables in configs weren't being substituted properly
3. The `$schema` field was breaking envsubst

## Solution Implemented

### 1. Entrypoint Config Processing

**File**: `docker/entrypoint.sh`

**Logic**:
```bash
# If OPENCODE_CONFIG is set (from docker-compose), use it
if [ -n "$OPENCODE_CONFIG" ] && [ -f "$OPENCODE_CONFIG" ]; then
    # Back up workspace config that would override Docker config
    mv /workspace/.opencode/opencode.json /workspace/.opencode/opencode.json.host-backup
    
    # Substitute environment variables
    envsubst < "$OPENCODE_CONFIG" > /tmp/opencode-config-$(date +%s).json
    export OPENCODE_CONFIG="/tmp/opencode-config-$(date +%s).json"
fi
```

### 2. Removed `$schema` from Docker Config

**File**: `configs/opencode.devbob.json`

**Problem**: `envsubst` treats `$schema` as an environment variable
```json
"$schema": "https://opencode.ai/config.json"  // envsubst → "": "..."
```

**Solution**: Removed `$schema` field (it's optional)

### 3. Added Template Registration Fields

**Files**: All 3 config files
- `/home/avi/documents/work/exp-repo/metabob-devbob/opencode.json`
- `/home/avi/documents/work/exp-repo/metabob-devbob/.opencode/opencode.json`
- `configs/opencode.devbob.json`

**Added**:
```json
"template_registration": {
  "behavior": "best-effort"  // ONLY field (not enabled, not strategy)
},
"activity_learning": {
  "recommendation_threshold": 0.7,
  "min_executions_for_learning": 1
}
```

### 4. Exposed Dashboard Port

**File**: `docker-compose.devbob-quick.yaml`

```diff
  ports:
    - "3004:3004"  # ACP server
+   - "3100:3100"  # metabob-cli dashboard
```

## Config Loading Flow (Docker)

```
1. docker-compose sets OPENCODE_CONFIG=/config/opencode.devbob.json
2. docker-compose loads env vars from .env.devbob
3. Entrypoint checks if OPENCODE_CONFIG is set ✓
4. Entrypoint backs up /workspace/.opencode/opencode.json
5. Entrypoint runs envsubst on /config/opencode.devbob.json
6. Entrypoint exports OPENCODE_CONFIG=/tmp/opencode-config-XXXXX.json
7. OpenCode loads config from OPENCODE_CONFIG env var
8. Config has correct Docker-internal URLs and API keys
```

## Docker Compose Configuration

**File**: `docker-compose.devbob-quick.yaml`

```yaml
services:
  devbob-opencode:
    env_file:
      - .env.devbob  # ← Loads ALL environment variables
    environment:
      OPENCODE_CONFIG: /config/opencode.devbob.json  # ← Points to Docker config
    volumes:
      - ./repos/metabob-opencode:/workspace  # ← Workspace with code
      - ./configs/opencode.devbob.json:/config/opencode.devbob.json:ro  # ← Docker config
    ports:
      - "3004:3004"  # ACP
      - "3100:3100"  # Dashboard
```

## Environment-Specific URLs

| Environment | Config File | Base URL | Why |
|-------------|-------------|----------|-----|
| Host | `~/.opencode/opencode.json` | `http://localhost:8080` | Docker-exposed port |
| Container (Docker-compose) | `/config/opencode.devbob.json` | `http://api-server-dev:8080` | Internal network hostname |
| Container (standalone) | Generated by entrypoint | `${METABOB_API_URL}` | From environment |

## Common Issues & Solutions

### Issue: Config shows wrong base_url

**Symptom**: Inside container, `base_url` is `localhost:8080` instead of `api-server-dev:8080`

**Cause**: Workspace config overriding Docker config

**Solution**: Entrypoint now backs up `/workspace/.opencode/opencode.json` to `.host-backup`

### Issue: envsubst breaks JSON

**Symptom**: `Unrecognized key: ""`

**Cause**: envsubst replaces `$schema` with empty string

**Solution**: Removed `$schema` from `configs/opencode.devbob.json`

### Issue: API keys not substituted

**Symptom**: Config has literal `${ANTHROPIC_API_KEY}` string

**Cause**: env vars not loaded or envsubst not run

**Solution**: docker-compose uses `env_file: .env.devbob` to load vars automatically

### Issue: Dashboard not accessible from host

**Symptom**: Dashboard running on port 3100 inside container but not reachable

**Cause**: Port not exposed in docker-compose

**Solution**: Added `- "3100:3100"` to ports in docker-compose
