
**Root Cause**: The dashboard needs to **create a session first** before making other API calls. The session creation happens via `createSession` mutation, but it's not being triggered automatically.

**Failed API Calls** (from browser console):

### 3. The Gap: Dashboard Session Management

**Current Flow** (BROKEN):
```
1. Dashboard loads
2. Tries to call V2 APIs immediately
3. APIs fail with 401 (no Bearer token)
4. Dashboard shows error messages
```

**Required Flow** (NEEDS IMPLEMENTATION):
```
1. Dashboard loads
2. Check Redux: Do we have a session token?
   ├── NO → Call POST /v2/session with X-API-Key
   │         Store returned session_token in Redux
   │         Retry failed API calls
   └── YES → Use existing token for API calls
```

**The Missing Piece**: `SessionManager` component or auto-session logic

Looking at the code:
```javascript
// src/common/MetabobRestApi.js

createSession: builder.mutation({
  query: (body) => ({
    url: '/v2/session',
    method: 'POST',
    body,
  }),
  onQueryStarted: async (_, { dispatch, queryFulfilled }) => {
    const { data } = await queryFulfilled;
    const token = data?.metadata?.session_token || data?.session;
    if (token) {
      dispatch({ type: 'USER/setToken', payload: token });
    }
  }
})
```

This mutation exists but **needs to be called** by the app on startup.
