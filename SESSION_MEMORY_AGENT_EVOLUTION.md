# Session Memory Agent Evolution: From Router to Intelligence Layer

## Current State vs. Vision

### What Exists Today

**Backend (metabob-rpc-api):**
- ✅ Template Evolution Service - tracks effectiveness, success rates
- ✅ Activity Outcomes - records execution results  
- ✅ Template Effectiveness - aggregates metrics (success_rate, avg_component_accuracy, avg_cost_delta)
- ✅ Historical tracking - outcomes stored in `activity_outcome` and `template_effectiveness` tables
- ✅ Recommendation system - CTR optimization, Thompson Sampling for A/B testing

**Frontend (metabob-opencode):**
- ✅ Session Memory Agent - analyzes intent, creates impulses
- ✅ Intelligent Context Selector - scores files by task relevance, dependency proximity, code quality, historical usage
- ✅ Impulse system - lazy-loaded pointers with budgets
- ✅ Turn lifecycle hooks - pre/post-turn optimization

### The Gap: Router vs. Intelligence Layer

**Current Session Memory Agent (Lines 14-25 in memory-agent.ts):**
```typescript
/**
 * Design goals:
 * - Fast analysis (<2s target with Claude Haiku)
 * - Transparent to user (background operation)
 * - Zero memory tools exposed to main agent
 * - Complementary to system prompt Metabob injection
 */
```

**Current Role:**
- ❌ **Router only** - points to files/commands based on file tree
- ❌ **No learning** - doesn't query historical effectiveness data
- ❌ **Passive loading** - just loads existing content
- ❌ **No synthesis** - can't generate summaries or distilled context

**Envisioned Role (per user):**
- ✅ **Intelligence layer** - optimizes context based on historical patterns
- ✅ **Learning-driven** - queries activity outcomes to inform decisions
- ✅ **Active gathering** - executes activities/searches to synthesize context
- ✅ **Content generation** - creates bespoke summaries tailored to task

## Architecture Evolution

### Phase 1: Current Implementation (Router)

```
User Message
    ↓
Session Memory Agent
    ├─> Analyze intent (LLM)
    ├─> Suggest file paths (from project tree)
    ├─> Create impulses (file/bash/memo pointers)
    └─> Load high-priority impulses
    ↓
Main Agent (receives raw file content)
```

**Limitations:**
- No historical context about which files were actually useful
- No optimization based on past success/failure
- No synthesis - just dumps files into context
- Token budget allocated uniformly, not learned

### Phase 2: Envisioned Implementation (Intelligence Layer)

```
User Message + Context Hints
    ↓
Session Memory Agent (Enhanced)
    ├─> Analyze intent (LLM)
    ├─> Query historical effectiveness (Backend API)
    │   └─> "Which files helped with similar tasks?"
    │   └─> "What activities succeeded for this component?"
    │   └─> "What context patterns correlated with success?"
    │
    ├─> Intelligent context selection
    │   ├─> Score candidates by:
    │   │   - Task relevance (semantic similarity)
    │   │   - Historical effectiveness (from outcomes)
    │   │   - Dependency proximity (CPG analysis)
    │   │   - Code quality indicators (Metabob)
    │   └─> Optimize token allocation by learned weights
    │
    ├─> Active content gathering
    │   ├─> Execute search activities (grep patterns learned from past)
    │   ├─> Run analysis activities (component summaries)
    │   └─> Query Metabob for targeted insights
    │
    ├─> Content synthesis
    │   ├─> Generate distilled summaries (LLM)
    │   ├─> Extract key patterns from multiple files
    │   └─> Create task-specific views (not raw dumps)
    │
    └─> Create optimized impulses
        - Budget based on historical token usage
        - Priority learned from effectiveness
        - Content pre-processed for relevance
    ↓
Main Agent (receives bespoke, optimized context)
```

```typescript
function learnedBudget(input: {
  file: string
  taskIntent: string
  historicalUsage: { avgTokens: number, successRate: number }
}): number {
  // If high success rate, allocate more tokens
  // If low success rate, reduce budget
  const baselineBudget = 2000
  const successMultiplier = 0.5 + (input.historicalUsage.successRate * 1.5)
  return Math.round(baselineBudget * successMultiplier)
}
```

```typescript
  }): Promise<EffectivenessData> {

    })
    
    return effectiveness.json()
  }
  
  // ENHANCED: Use historical data in intent analysis
  export async function analyzeIntent(input: {
    sessionID: string
    promptText: string
    recentMessages?: MessageV2.WithParts[]
  }): Promise<Intent> {
    // ... existing intent analysis ...
    
    // NEW: Augment with historical effectiveness
    const historical = await getHistoricalContext({
      taskIntent: intent.type,
      targetFiles: suggestedFiles
    })
    
    // Adjust priorities based on success rates
    for (const impulse of intent.suggestedImpulses) {
      const effectiveness = historical.fileEffectiveness[impulse.pointer.path]
      if (effectiveness && effectiveness.successRate > 0.8) {
        impulse.priority = "high"
        impulse.budget = Math.round(impulse.budget * 1.2) // Allocate more
      }
    }
    
    return intent
  }
}
```

```typescript
// NEW: Synthesize multi-file context
async function synthesizeMultiFileContext(input: {
  files: Array<{ path: string, relevance: number }>
  taskIntent: string
  maxTokens: number
}): Promise<string> {
  // Read top files by relevance
  const topFiles = input.files
    .sort((a, b) => b.relevance - a.relevance)
    .slice(0, 5)
  
  const fileContents = await Promise.all(
    topFiles.map(async f => ({
      path: f.path,
      content: await Bun.file(f.path).text()
    }))
  )
  
  // Use LLM to distill
  const model = await Provider.getModel("anthropic", "claude-3-5-haiku-20241022")
  const synthesis = await generateText({
    model: model.language,
    temperature: 0.2,
    messages: [
      {
        role: "system",
        content: `You are a context synthesizer. Create a concise summary that helps with: ${input.taskIntent}`
      },
      {
        role: "user",
        content: fileContents.map(f => 
          `=== ${f.path} ===\n${f.content.slice(0, 3000)}`
        ).join('\n\n')
      }
    ],
    maxTokens: input.maxTokens
  })
  
  return synthesis.text
}
```

```python
# server/routes/session_memory.py

@router.post("/session-memory/effectiveness")
async def get_session_memory_effectiveness(
    request: SessionMemoryEffectivenessRequest,
    db: SurrealDBClient = Depends(get_db)
):
    """
    Query historical effectiveness of files/components for a task intent.
    
    Returns:
    - File effectiveness scores (0-1)
    - Average token usage per file
    - Success rates for similar tasks
    - Recommended context patterns
    """
    query = """
    SELECT 
        file_path,
        count() as usage_count,
        count(outcome = 'success') / count() as success_rate,
        avg(tokens_used) as avg_tokens
    FROM session_memory_outcome
    WHERE task_intent = $intent
    GROUP BY file_path
    ORDER BY success_rate DESC
    """
    
    results = await db.query(query, {"intent": request.task_intent})
    return SessionMemoryEffectivenessResponse(
        file_effectiveness=results,
        recommendations=generate_recommendations(results)
    )


@router.post("/session-memory/outcome")
async def record_session_memory_outcome(
    request: RecordSessionMemoryOutcomeRequest,
    db: SurrealDBClient = Depends(get_db)
):
    """
    Record outcome of session memory usage for learning.
    
    Tracks:
    - Which impulses were loaded
    - Which were actually used (vs. ignored)
    - Task outcome (success/failure)
    - User feedback score
    """
    outcome_data = {
        "session_id": request.session_id,
        "task_intent": request.intent,
        "impulses_loaded": request.impulses,
        "outcome": request.outcome,
        "feedback_score": request.feedback_score,
        "timestamp": datetime.now(timezone.utc)
    }
    
    outcome_id = await db.create("session_memory_outcome", outcome_data)
    
    # Update effectiveness metrics
    await update_effectiveness_cache(db, request.intent, request.impulses)
    
    return {"outcome_id": outcome_id}


@router.post("/session-memory/weights")
async def get_learned_scoring_weights(
    request: GetScoringWeightsRequest,
    db: SurrealDBClient = Depends(get_db)
):
    """
    Get optimized scoring weights based on historical outcomes.
    
    Uses Bayesian optimization to learn which scoring factors
    (task relevance, dependency proximity, etc.) correlate with success.
    """
    # Query outcomes for this intent type
    outcomes = await db.query("""
    SELECT *
    FROM session_memory_outcome
    WHERE task_intent = $intent
    AND outcome = 'success'
    """, {"intent": request.intent})
    
    # Calculate optimal weights using learned optimizer
    weights = calculate_optimal_weights(outcomes)
    
    return LearnedScoringWeightsResponse(
        task_relevance=weights["task_relevance"],
        dependency_proximity=weights["dependency_proximity"],
        code_quality=weights["code_quality"],
        historical_usage=weights["historical_usage"],
        confidence=weights["confidence"]
    )
```

## Key Insights

### 1. Bespoke Agent per Task

Each task gets a "custom agent" through:
- **Historical context** - what worked for similar tasks
- **Synthesized summaries** - task-specific views of code
- **Learned weights** - optimized scoring for this intent
- **Active gathering** - execute activities to prepare context

### 2. Continuous Learning Loop

```
Execute Task
    ↓
Record Outcome (success/failure)
    ↓
Update Effectiveness Metrics
    ↓
Adjust Scoring Weights
    ↓
Optimize Next Task (better context)
    ↓
[Repeat]
```

### 3. Shift from Static to Dynamic

**Static (current):**
- File tree → suggest files → load files
- Same budget for all files
- No learning from outcomes

**Dynamic (envisioned):**
- Intent + history → score candidates → synthesize optimal context
- Learned budgets based on effectiveness
- Continuous improvement from outcomes

## Summary

The session memory agent evolution transforms it from a **passive router** (pointing to files) into an **active intelligence layer** (synthesizing optimal context based on learned patterns). This requires:

1. **Backend integration** - query historical effectiveness
2. **Active gathering** - execute activities for synthesis
3. **Content generation** - create task-specific summaries
4. **Continuous learning** - record outcomes and optimize

The result is a truly **bespoke agent for each task**, optimized through historical interactions and capable of generating the most relevant context for the specific challenge at hand.
