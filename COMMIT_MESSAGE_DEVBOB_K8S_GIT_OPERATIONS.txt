feat(devbob-k8s-git-operations): Enforce complete git operations capabilities across distributed devbob deployment

## Instructional State Change

**Requirement**: All 3 devbob pods in local Kubernetes cluster (docker-desktop context, metabob namespace) must have complete git operations capabilities for autonomous vessel repository management. Each pod must be able to: (1) Pull from vessel repositories, (2) Make commits with proper attribution, (3) Push commits to remote branches, (4) Create pull requests using GitHub CLI, (5) Merge pull requests.

**Before**: Infrastructure deployed but GITHUB_TOKEN was placeholder 'none', blocking PR operations. No validation of token format, no authentication checks before PR operations, no input validation for branch names or commit messages. Silent failures possible.

**After**: Token format validated on startup, authentication checked before PR operations, branch names and commit messages validated/sanitized, fail-fast with clear error messages. Complete git workflow (clone, commit, push, PR create/merge) ready for autonomous operation.

## Functional State Change

### Code Changes Applied (7 components)

1. **entrypoint-self-config.sh** (repos/metabob-opencode/docker/entrypoint-self-config.sh:145-167)
   - Added GITHUB_TOKEN format validation (ghp_* or github_pat_*)
   - Export GH_AUTHENTICATED environment variable
   - Clear error messages for invalid tokens
   - Impact: Container startup validation, affects all 3 pods

2. **checkGhAuthenticated()** (repos/metabob-opencode/packages/opencode/src/session/activity-git.ts:319-329)
   - New helper function to verify gh CLI authentication
   - Runs 'gh auth status' before PR operations
   - Impact: Enables fail-fast behavior

3. **createPR()** (repos/metabob-opencode/packages/opencode/src/session/activity-git.ts:208-215)
   - Integrated checkGhAuthenticated() before gh pr create
   - Throws descriptive error if not authenticated
   - Impact: Prevents HTTP 401 errors at runtime

4. **validateBranchName()** (repos/metabob-opencode/packages/opencode/src/session/activity-git.ts:331-352)
   - Validates git branch naming rules
   - Prevents command injection and git errors
   - Checks: special characters, length (max 255), invalid patterns
   - Impact: Security improvement, prevents git errors

5. **createBranch()** (repos/metabob-opencode/packages/opencode/src/session/activity-git.ts:40-41)
   - Integrated validateBranchName() validation
   - Validates input before any git operations
   - Impact: Fail-fast on invalid branch names

6. **sanitizeCommitMessage()** (repos/metabob-opencode/packages/opencode/src/session/activity-git.ts:354-373)
   - Removes control characters (except newline/tab)
   - Limits message length to 50000 characters
   - Ensures clean git history
   - Impact: Security improvement, prevents metadata injection

7. **commitPromptChanges()** (repos/metabob-opencode/packages/opencode/src/session/activity-git.ts:129-132)
   - Integrated sanitizeCommitMessage() before git commit
   - Sanitizes all commit messages
   - Impact: Clean git history, prevents pollution

### Data Flow Transformations

**Before**:
- User Input → createBranch() → git checkout -b (no validation)
- LLM Output → commitPromptChanges() → git commit (no sanitization)
- PR Options → createPR() → gh pr create (may fail with HTTP 401)
- Container Start → gh auth login || true (silent failure)

**After**:
- User Input → validateBranchName() → createBranch() → git checkout -b
- LLM Output → sanitizeCommitMessage() → commitPromptChanges() → git commit
- PR Options → checkGhAuthenticated() → createPR() → gh pr create
- Container Start → validate token → gh auth login → export GH_AUTHENTICATED
