# Vessel Tag Strategy: Development vs Production

## Overview

This document explains the dual-tag strategy for vessel deployments:
- **Dev tags**: Auto-generated by pre-commit hook for local development
- **Release tags**: Manual semantic versions for production deployments

## Tag Formats

### 1. Git Release Tags (GitHub)

**Format:** `v<major>.<minor>.<patch>`

**Examples:**
```
v1.1.1
v0.1.1
v0.2.0
```

**Usage:**
- Created manually: `git tag -a v1.1.1 -m "Release message"`
- Pushed to GitHub: `git push origin v1.1.1`
- Triggers production Docker builds in deployment CI/CD
- Used for production deployments and changelogs

### 2. Docker Release Tags

**Format:** `<major>.<minor>.<patch>` (no 'v' prefix)

**Examples:**
```
metabobapp/metabob-activity-api:1.1.1
metabobapp/minibob:0.1.3
metabobapp/metabob-cloud-dashboard:0.2.0
```

**Usage:**
- Built from git release tags (strip 'v' prefix)
- Pushed to Docker Hub
- Referenced in Helm production values
- Immutable - never overwritten

### 3. Dev Tags (Pre-Commit Hook)

**Format:** `dev-<version>-<commit>-<timestamp>`

**Examples:**
```
dev-1.1.1-cfb2a7c-1774695755
dev-0.1.3-abc1234-1774695800
```

**Usage:**
- Auto-generated by `.git/hooks/pre-commit`
- Overwrites Helm chart tags on every commit
- Used for local Kubernetes deployments
- Includes commit hash for traceability
- Safe to overwrite (not for production)

## Workflows

### Development Workflow (Local Cluster)

```bash
# 1. Make code changes
vim repos/metabob-activity-api/src/index.ts

# 2. Commit (pre-commit hook runs automatically)
git add -A
git commit -m "feat: add new feature"
# → Pre-commit hook:
#    - Generates dev tag: dev-1.1.1-xyz789-1774695900
#    - Updates helm/charts/*/values.yaml
#    - Builds Docker images (if source changed)
#    - Deploys to local cluster via helmfile

# 3. Test locally
curl http://api.minibob.local/health

# 4. Pre-commit hook results are NOT committed
#    (values.yaml changes are temporary for local dev)
```

**Key Point:** Dev tags are for immediate local testing, not version control.

### Production Release Workflow

```bash
# 1. Finish feature development and testing locally
# ... (multiple dev commits with pre-commit hook)

# 2. Create release tag
cd repos/metabob-activity-api
git tag -a v1.2.0 -m "feat: new feature X"
git push origin main
git push origin v1.2.0

# 3. Update Helm charts for production
cd ../../helm/charts/metabob-activity-api
sed -i 's/tag: "1.1.1"/tag: "1.2.0"/' values.yaml

# 4. Commit Helm chart update (skip pre-commit hook)
git add helm/charts/metabob-activity-api/values.yaml
git commit --no-verify -m "chore(helm): bump metabob-activity-api to 1.2.0"
git push origin main

# 5. Deployment CI/CD triggers automatically
#    - Builds Docker image: metabobapp/metabob-activity-api:1.2.0
#    - Pushes to Docker Hub
#    - Deploys to production GKE cluster
#    - Blue/green deployment with stability monitoring
```

### Why --no-verify for Production Tags?

The pre-commit hook auto-generates dev tags, which would overwrite production release tags:

```bash
# Without --no-verify:
git commit -m "chore: bump to 1.2.0"
# → Pre-commit hook overwrites:
#    tag: "1.2.0" → tag: "dev-1.2.0-abc123-1234567890"

# With --no-verify:
git commit --no-verify -m "chore: bump to 1.2.0"
# → Helm chart keeps: tag: "1.2.0"
# → Production deployment uses correct release tag
```

## Pre-Commit Hook Behavior

**Location:** `.git/hooks/pre-commit`

**What it does:**
1. Generates dev tag: `dev-<version>-<commit>-<timestamp>`
2. Updates ALL Helm chart values.yaml files with dev tags
3. Builds Docker images (if source files changed)
4. Deploys to local cluster via helmfile sync
5. Validates deployments (health checks)

**When it runs:**
- Every `git commit` (unless `--no-verify` flag used)
- Only in monorepo root (not in vessel subdirectories)

**Why it exists:**
- Ensures local cluster always uses latest code
- Provides instant feedback loop during development
- Eliminates manual build/deploy steps
- Enables rapid iteration

**When to skip it:**
- Committing production Helm chart updates (`--no-verify`)
- Documentation-only changes
- When local cluster is not needed
- CI/CD configuration changes

## Docker Image Lifecycle

### Development Images (Local)

```
metabobapp/metabob-activity-api:dev-1.1.1-cfb2a7c-1774695755
                                 │   │    │       └─ timestamp
                                 │   │    └─ commit hash
                                 │   └─ base version
                                 └─ dev prefix
```

**Characteristics:**
- Built locally by pre-commit hook
- Not pushed to Docker Hub (local only)
- Overwritten on every commit
- Used for rapid iteration

### Production Images (Docker Hub)

```
metabobapp/metabob-activity-api:1.1.1
                                 └─ clean semver (matches git tag v1.1.1)
```

**Characteristics:**
- Built by deployment CI/CD
- Pushed to Docker Hub
- Immutable (never overwritten)
- Used for production deployments
- Traceable to git release tag

## Best Practices

### 1. Never Push Dev Tags to Git

```bash
# ❌ DON'T
git add helm/charts/*/values.yaml  # Contains dev tags
git commit -m "update"
git push

# ✅ DO
git commit --no-verify -m "chore: bump production tags"
git push
```

### 2. Use Semantic Versioning

**Major version** (1.0.0 → 2.0.0): Breaking changes
**Minor version** (1.0.0 → 1.1.0): New features, backwards compatible
**Patch version** (1.0.0 → 1.0.1): Bug fixes, backwards compatible

### 3. Tag After Merging to Main

```bash
# ❌ DON'T tag feature branches
git checkout feature/new-thing
git tag v1.2.0  # Wrong!

# ✅ DO tag main/master branch
git checkout main
git pull origin main
git tag -a v1.2.0 -m "Release 1.2.0"
git push origin v1.2.0
```

### 4. Keep Helm Charts in Sync

After tagging a new release:
1. Update corresponding Helm chart values.yaml
2. Commit with `--no-verify`
3. Push to trigger deployment

### 5. Verify Docker Images Exist

Before deploying, ensure Docker images are available:

```bash
# Check Docker Hub
docker pull metabobapp/metabob-activity-api:1.1.1

# Or check via API
curl -s https://hub.docker.com/v2/repositories/metabobapp/metabob-activity-api/tags/1.1.1 | jq
```

## Troubleshooting

### Issue: Helm chart has wrong tag after commit

**Cause:** Pre-commit hook overwrote production tag

**Solution:**
```bash
# Check what changed
git diff HEAD~1 helm/charts/metabob-activity-api/values.yaml

# Restore production tag
git checkout HEAD~1 -- helm/charts/metabob-activity-api/values.yaml

# Commit without hook
git add helm/charts/metabob-activity-api/values.yaml
git commit --no-verify -m "fix: restore production tag"
```

### Issue: Docker image not found during deployment

**Cause:** Release tag created but Docker image not built

**Solution:**
```bash
# Option 1: Wait for CI/CD (if deployment repo configured)
# Check GitHub Actions: https://github.com/metabobproject/metabob-deployment/actions

# Option 2: Build and push manually
cd repos
docker build -f metabob-activity-api/Dockerfile -t metabobapp/metabob-activity-api:1.1.1 .
docker push metabobapp/metabob-activity-api:1.1.1
```

### Issue: Pre-commit hook failing

**Symptoms:** Commit takes forever or fails

**Quick fix:**
```bash
# Skip hook for this commit
git commit --no-verify -m "your message"
```

**Long-term fix:**
```bash
# Check hook logs
tail -100 .git/hooks/logs/pre-commit-*.log

# Disable hook temporarily
chmod -x .git/hooks/pre-commit

# Re-enable later
chmod +x .git/hooks/pre-commit
```

## Summary

**Local Development:**
- Pre-commit hook auto-generates dev tags
- Immediate deployment to local cluster
- Fast iteration without manual steps

**Production Releases:**
- Manual semantic version tags (v1.1.1)
- Clean Docker tags without 'v' prefix (1.1.1)
- Helm charts committed with `--no-verify`
- CI/CD builds and deploys to production

**Key Principle:** Dev tags for development speed, release tags for production stability.
