# Impulse Tagging Pattern for Activity Workflows

**Date**: 2026-02-20  
**Status**: Design Complete, Implementation Pending  
**Context**: Enabling activities to consume outputs from other activities via impulses

---

## Overview

The **impulse tagging pattern** allows activities to reference data that should be resolved by the session memory agent at runtime. Instead of passing raw file paths or data, activities use tagged references like `@impulse:{type}:{id}` which the memory agent resolves automatically.

---

## Pattern Syntax

```
@impulse:{type}:{identifier}
```

### Components

| Component | Description | Examples |
|-----------|-------------|----------|
| `@impulse:` | Prefix indicating impulse resolution required | Required |
| `{type}` | Type of impulse/data source | `file`, `activityOutput`, `component`, `metabobIssue` |
| `{identifier}` | Unique identifier for the data | `assess-documentation-conformity`, `tmp/data.json`, `act_xyz123` |

---

## Impulse Types

### 1. Activity Output (`activityOutput`)

Reference outputs from a previous activity execution.

**Syntax**: `@impulse:activityOutput:{template-id-or-execution-id}`

**Examples**:
```javascript
// By template ID (finds most recent execution)
"@impulse:activityOutput:assess-documentation-conformity"

// By specific execution ID
"@impulse:activityOutput:act_mlvsqd7o_32dca50cbaefef49"
```

**Memory Agent Resolution**:
1. Search activity storage for matching template ID or execution ID
2. Locate artifact directory (e.g., `tmp/activity-assess-documentation-conformity/`)
3. Identify primary artifact (e.g., `required-deltas.json`)
4. Load artifact content
5. Replace tag with loaded content or impulse ID pointing to content

---

### 2. File (`file`)

Reference a file in the repository or filesystem.

**Syntax**: `@impulse:file:{path}`

**Examples**:
```javascript
// Relative to repo root
"@impulse:file:tmp/activity-assess-documentation-conformity/required-deltas.json"

// Absolute path
"@impulse:file:/home/user/data/config.json"
```

**Memory Agent Resolution**:
1. Resolve path (relative to repo root if not absolute)
2. Read file content
3. Create impulse with file content
4. Replace tag with impulse ID

---

### 3. Component (`component`)

Reference a specific code component (function, class, method).

**Syntax**: `@impulse:component:{file}::{component-name}`

**Examples**:
```javascript
"@impulse:component:src/auth.ts::UserValidator"
"@impulse:component:src/utils.ts::formatDate"
```

**Memory Agent Resolution**:
1. Parse file path and component name
2. Extract component source code
3. Create impulse with component content
4. Replace tag with impulse ID

---

### 4. Metabob Issue (`metabobIssue`)

Reference code quality issues from Metabob analysis.

**Syntax**: `@impulse:metabobIssue:{query-or-issue-id}`

**Examples**:
```javascript
// Search query
"@impulse:metabobIssue:authentication bugs"

// Specific issue ID
"@impulse:metabobIssue:issue_abc123"
```

**Memory Agent Resolution**:
1. Query Metabob MCP for matching issues
2. Aggregate issue data
3. Create impulse with issue details
4. Replace tag with impulse ID

## Use Cases

### Use Case 1: Activity Composition Workflow

**Scenario**: Assess documentation conformity, then apply the deltas.

```javascript
// Step 1: Assess documentation
activity({
  templateId: "assess-documentation-conformity",
  variables: {},
  reason: "Generate documentation deltas"
})
// Creates artifacts in tmp/activity-assess-documentation-conformity/

// Step 2: Apply deltas (references Step 1 output)
activity({
  templateId: "apply-documentation-deltas",
  variables: {
    deltaImpulseId: "@impulse:activityOutput:assess-documentation-conformity",
    priorityFilter: "high",
    maxDeltas: 10
  },
  reason: "Apply high priority documentation deltas from assessment"
})
```

**Memory Agent Actions**:
1. Sees `@impulse:activityOutput:assess-documentation-conformity` tag
2. Searches activity storage for recent executions
3. Finds `act_mlvsqd7o_32dca50cbaefef49` (most recent)
4. Locates artifact directory: `tmp/activity-assess-documentation-conformity/`
5. Loads `required-deltas.json` (primary artifact)
6. Creates impulse with delta data
7. Replaces tag with impulse ID in activity variables
8. Activity executes with resolved impulse

---

### Use Case 2: File-Based Data Passing

**Scenario**: Process data generated by previous manual work.

```javascript
activity({
  templateId: "transform-data",
  variables: {
    inputData: "@impulse:file:tmp/raw-data.json",
    outputFormat: "csv"
  },
  reason: "Transform raw JSON data to CSV format"
})
```

**Memory Agent Actions**:
1. Sees `@impulse:file:tmp/raw-data.json` tag
2. Reads file content
3. Creates impulse with JSON data
4. Replaces tag with impulse ID
5. Activity receives loaded data

---

### Use Case 3: Metabob-Driven Workflow

**Scenario**: Fix issues identified by Metabob analysis.

```javascript
activity({
  templateId: "fix-security-issues",
  variables: {
    issues: "@impulse:metabobIssue:security vulnerabilities",
    severity: "high"
  },
  reason: "Fix high-severity security issues found by Metabob"
})
```

**Memory Agent Actions**:
1. Sees `@impulse:metabobIssue:security vulnerabilities` tag
2. Calls `metabob_search_codebase_issues("security vulnerabilities")`
3. Filters by HIGH severity
4. Creates impulse with issue list
5. Replaces tag with impulse ID
6. Activity receives issue data

## Memory Agent Resolution Flow

```
┌─────────────────────────────────────────────────────────────────┐
│ Activity Invocation with Impulse Tags                           │
└─────────────────────────────────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────────┐
│ Pre-Execution Hook: Impulse Tag Detection                       │
│ - Scan all variable values for @impulse: prefix                 │
│ - Extract type and identifier                                   │
└─────────────────────────────────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────────┐
│ Memory Agent: Tag Resolution                                    │
│                                                                  │
│ FOR EACH tagged variable:                                       │
│   1. Parse type and identifier                                  │
│   2. Route to appropriate resolver:                             │
│      - activityOutput → search activity storage                 │
│      - file → read filesystem                                   │
│      - component → extract from source                          │
│      - metabobIssue → query Metabob MCP                         │
│   3. Load/fetch data                                            │
│   4. Create impulse with loaded content                         │
│   5. Replace tag with impulse ID                                │
└─────────────────────────────────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────────┐
│ Activity Execution with Resolved Impulses                       │
│ - Variables now contain impulse IDs                             │
│ - Activity tasks can resolve impulses via impulse tools         │
└─────────────────────────────────────────────────────────────────┘
```

## Implementation Requirements

### Memory Agent Responsibilities

1. **Tag Detection**
   - Pre-execution hook scans activity variables
   - Regex pattern: `/@impulse:(\w+):([^@\s]+)/g`
   - Extract type and identifier

2. **Type-Specific Resolvers**
   ```typescript
   interface ImpulseResolver {
     type: string
     resolve(identifier: string): Promise<ImpulsePointer>
   }
   
   class ActivityOutputResolver implements ImpulseResolver {
     async resolve(identifier: string) {
       // Search activity storage
       const execution = await findActivityExecution(identifier)
       // Locate artifacts
       const artifactDir = execution.metadata.artifactDir || `tmp/activity-${identifier}/`
       // Load primary artifact
       const content = await loadArtifact(artifactDir)
       // Create impulse
       return { type: "activityOutput", path: artifactDir, content }
     }
   }
   ```

3. **Impulse Creation**
   - Auto-create impulses for resolved data
   - Use identifier as impulse ID (or generate unique ID)
   - Set appropriate budget based on content size
   - Add metadata tracking resolution path

4. **Metrics Tracking**
   - Log which tags were resolved
   - Track resolver used (type)
   - Measure resolution time
   - Record content size
   - Link impulse to source activity

### Activity Template Requirements

1. **Variable Documentation**
   ```json
   {
     "variables": [{
       "name": "deltaImpulseId",
       "type": "string",
       "required": true,
       "description": "Impulse ID or @impulse tag for delta artifacts",
       "examples": [
         "@impulse:activityOutput:assess-documentation-conformity",
         "@impulse:file:tmp/deltas.json"
       ]
     }]
   }
   ```

2. **Impulse Resolution in Tasks**
   - Tasks should use impulse tools to load data
   - Handle both direct impulse IDs and resolved tags
   - Graceful fallback if resolution fails

## Error Handling

### Resolution Failures

**Scenario**: Tag references non-existent activity output

```javascript
// Tag: @impulse:activityOutput:non-existent-activity
// Error: Activity execution not found
```

**Handling**:
1. Memory agent logs error
2. Returns clear error message to user
3. Lists available recent activities
4. Suggests corrections
5. Activity execution does NOT start

**Example Error**:
```
Impulse resolution failed for variable 'deltaImpulseId'

Tag: @impulse:activityOutput:non-existent-activity
Error: No recent executions found for template 'non-existent-activity'

Available recent activities:
  - assess-documentation-conformity (act_mlvsqd7o_32dca50cbaefef49, 2 hours ago)
  - test-activity-artifact-system (act_mlvsp8v4_1c195d8f6991520a, 3 hours ago)

Did you mean: @impulse:activityOutput:assess-documentation-conformity?
```
