## The fix-half does NOT exist (the real finding)
An `orphaned_capability` gap is closed by authoring **a new activity that invokes the resolver** — NOT by a code edit. No current loop does this:
- `drain → draft-gap-closing-activity → apply-proposal-as-patch`: authors **surgical code patches**; would reject this as `non_surgical_proposal`.
- `gap-compose → gap_to_feature → feature_compose`: authors **code features**. **Demonstrated live**: dry-run `gap_to_feature category=orphaned_capability` picked the gap, returned *"composer could not produce a verified change."*
- `compose-teacher`: chains **existing** producer→consumer activities; an orphaned resolver has none.
- `draft-activity-from-pattern`: extracts from existing **traces**; orphans have none.

Root cause: authoring a correct bridge needs the resolver's per-invocation contract (e.g. `problem_detection` needs `pointer.filePaths[]`), which trace/pattern drafters can't synthesize without a seed.
