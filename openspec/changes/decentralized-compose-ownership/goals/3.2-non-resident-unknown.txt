In repos/development-vessel/src/resolvers/attempt-checks.ts, give evaluateChecks an optional third parameter `targetVessel?: string`. In the "systemd_units" case, before calling resolveSystemdUnitHealthObserver, when targetVessel is set: run `Bun.spawn(["systemctl", "show", `${targetVessel}.service`, "-p", "LoadState", "--value"], { stdout: "pipe", stderr: "pipe" })` the same way resolveSystemdUnitHealthObserver runs systemctl, read stdout trimmed, and (a) if the spawn throws or stdout is empty return `[{ id: "systemd_units", verdict: "unknown", detail: "systemctl unavailable", definition_version }]`; (b) if it is not "loaded" return `[{ id: "systemd_units", verdict: "unknown", detail: `target not resident on ${process.env["SUBSTRATE_NAME"] ?? "substrate"}`, definition_version }]`; (c) otherwise evaluate as today. Measured: a composer landing a repo whose vessel does not run on its node cannot observe that vessel's units and today would report its own node's units as the target's; an empty systemctl read must never count as resident.
