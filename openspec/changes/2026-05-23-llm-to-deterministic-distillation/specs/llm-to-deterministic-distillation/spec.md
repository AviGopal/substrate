# Capability: llm-to-deterministic-distillation

## Definition

The substrate identifies LLM resolver behavior patterns that are
stable across many traces (high input/output cluster stability, low
output variance), synthesises deterministic equivalents, validates
them on held-out traces, and promotes them as sibling sub-resolvers
under the source shape. Cost-weighted Thompson sampling then routes
matched inputs to the deterministic resolver (~$0 cost), reserving
the LLM resolver for novel inputs. Distilled resolvers accumulating
β faster than α are automatically retired. The entire pipeline is
substrate-resident.

## Pipeline

```
weekly substrate cron
  ↓
pattern-stability-scanner (per LLM resolver)
  ↓
distillationCandidate impulses for stable patterns (τ ≥ 0.85, n ≥ 20)
  ↓
extract-deterministic-resolver activity (LLM, MAB-selected)
  ↓
deterministicResolverProposal impulse
  ↓
verify-distilled-resolver validator (held-out 20% accuracy ≥ 0.95)
  ↓
distillation-promotion via substrate-forge (24h evaluation)
  ↓
forkPromotion → canonical substrate
  ↓
distilled resolver registered as sub-resolver under source shape
  ↓
cost-weighted Thompson routes matched inputs to distilled
  ↓
β-rate monitoring; retire-distilled-resolver on drift
```

## Shapes

- `distillationCandidate` (read) — body
  `{ candidate_id, source_resolver, problem_class, input_signature_pattern, output_pattern, n_supporting_traces, stability_score }`.
- `deterministicResolverProposal` (write) — body
  `{ proposal_id, source_resolver, problem_class, resolver_json, supporting_trace_ids[], held_out_trace_ids[] }`.
- `distilledResolverRetired` (write) — body
  `{ retired_resolver_id, source_resolver, evidence_trace_ids[], beta_rate, retired_at }`.
- `distillationReport` (read, weekly) — body per Phase 7.1.

## Distilled resolver schema

```typescript
{
  resolver_id: string,
  source_resolver: string,
  problem_class: string,
  matchers: Array<{
    input_signature_pattern: string,  // regex / structural pattern
    output_template: string,           // template with placeholder substitution
    confidence: number,
  }>,
  fallback_to: string  // source_resolver id; called when no matcher hits
}
```

The distilled resolver is a small TypeScript file generated by
`extract-deterministic-resolver`. It evaluates matchers in priority
order; on first hit, returns the templated output; on no match,
delegates to fallback (the source LLM resolver).

## Self-application invariants

1. **No new primitive** — distillation is ribosome extracting deterministic
   resolvers from observed traces. Ribosome is a four-primitive operation.
2. **Closure-bound** — every stage of the pipeline is substrate-resident.
   `closure-audit --without=operator-shell` covers it. Operator does not
   author distilled resolvers.
3. **Confidence-weighted** — distilled resolver's initial α is inherited
   from source LLM resolver, scaled by the distillation's
   `signal_confidence_weight` (computed from stability score and supporting
   trace count).
4. **Cost-weighted** — distilled resolvers' value comes from
   cost-weighted Thompson selection. Without cost-weighting, distillation
   has no advantage; with it, distilled resolvers dominate matched inputs.
5. **The extractor is itself distillable** — the LLM resolver used in
   `extract-deterministic-resolver` accumulates traces. Patterns in
   *its* behavior may be distilled to deterministic equivalents. The
   recursion bottoms out at pattern-matching circuitry, which has
   no LLM dependency.
6. **Reversibility** — distilled resolvers can be automatically retired.
   The retirement event is itself a learning signal that feeds back
   into the scanner's threshold tuning.

## Stability metric

For a `(resolver, problem_class)` pair:

1. Group traces by `input_signature` (normalized impulse hash).
2. For each group with n ≥ 20 supporting traces:
   - Compute the dominant output cluster (most common output under
     similarity metric).
   - `stability_score = 1 - (output_variance_in_cluster /
     output_mean_in_cluster)`, range [0, 1].
   - If `stability_score ≥ 0.85` and dominant cluster contains ≥80% of
     the group, emit `distillationCandidate`.

Similarity metric is problem-class-dependent. Default: semantic
similarity via embedding cosine ≥ 0.9. Specialised metrics
(string exact-match for keyword extraction; AST-equivalence for code;
numerical-tolerance for cost estimates) are registered per problem
class.

## Acceptance

1. **Scanner operational**: weekly cron runs; emits candidates for
   stable patterns.
2. **First promoted distilled resolver**: within 4 weeks of
   deployment, at least one distilled resolver is registered as a
   sub-resolver and routing live traffic.
3. **Cost reduction (12 weeks)**: ≥20% of LLM resolver calls
   intercepted; ≥40% reduction in average LLM cost per substrate-hour.
4. **Accuracy maintained**: distilled-resolver-intercepted calls show
   ≥0.95 accuracy against LLM resolver outputs on held-out trace
   samples.
5. **Reversibility**: deliberate-drift test triggers automatic
   retirement within 7 days.
6. **Self-distillation observed**: within 12 weeks, at least one
   distillation candidate from the
   `extract-deterministic-resolver` activity's own traces.
7. **Closure**: `closure-audit --without=operator-shell` zero
   failures for distillation pipeline.

## Status

Coordinated with substrate-forge-vessel, cost-weighted-posteriors,
llm-resolver-model-mab, and substrate-self-deployment. Distillation
is the slowest-running of the five acceleration mechanisms (depends
on trace accumulation); first promoted distilled resolver ~4 weeks
after deployment. Full benefit realises over 12+ weeks.
