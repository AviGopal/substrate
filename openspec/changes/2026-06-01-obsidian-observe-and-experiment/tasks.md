# Tasks — Phase 1 Obsidian observation layer

Goal: ship deterministic infrastructure so Phase 2 and Phase 3 have an event substrate and a reserved failure-mode slot. No LLM authoring in this phase.

- [ ] **1.1** — Register shapes `obsidianEvent`, `obsidianEpisode`, `actionEffectModel` in concept-db at `repos/concept-db/src/shapes/obsidian.ts` (new file). `obsidianEvent` SHALL be `bridge_eligibility: "deny"`; the other two SHALL be `"allow"`. **Acceptance:** `bun test` on concept-db registry passes; the three shapes are queryable by name.

- [ ] **1.2** — Seed `observe-obsidian-events` in `repos/development-vessel/src/seed/observe-obsidian-events.ts`. Subscribes to `workspace.on('active-leaf-change' | 'file-open' | ...)` and `vault.on('create' | 'modify' | 'delete' | 'rename')` and the command palette `executeCommandById` hook. Emits one `obsidianEvent` per event with `payload_hash` only. **Acceptance:** with the plugin loaded against a probe vault, each editor/file/command event emits ≥ 1 `obsidianEvent` with `bridge_eligibility: "deny"` and no raw text.

- [ ] **1.3** — Seed `group-interaction-episodes` in `repos/development-vessel/src/seed/group-interaction-episodes.ts`. Windowing resolver (idle-gap or workspace-boundary close). Emits `obsidianEpisode` with ordered `event_ids` and a sorted-unique `class_signature`. **Acceptance:** given a fixture of 12 events spanning two idle gaps, the resolver emits 2 episodes; signatures are sorted and deduplicated.

- [ ] **1.4** — Seed `probe-obsidian-action-effects` in `repos/development-vessel/src/seed/probe-obsidian-action-effects.ts`. Iterates the Obsidian command catalog against a probe vault, captures `(pre_signature, command_id, post_signature)` triples, accumulates per-command distributions, classifies reversibility heuristically (`text-edit → reversible`, `file-delete → soft_irreversible`, `plugin-disable → hard_irreversible`, default `unknown`). Refuses to dispatch against the operator's vault path. **Acceptance:** non-empty `actionEffectModel` catalog with `observation_count ≥ 1` per probed command; sum of `post_signature_distribution[].probability` is within 1e-6 of 1.0.

- [ ] **1.5** — Extend `FailureModeSchema` in `repos/metabob-activity-api/src/models/schemas.ts` to include `prediction_disagreement` as a top-level `type` value alongside the existing five. Add the three discriminated sub-cases (`intent_inconsistency`, `trajectory_divergence`, `action_no_effect`) as part of the `context` union. Reserve the SurrealDB columns as `OPTIONAL` via a new migration so Phase 3 can populate them without further schema work. **Acceptance:** migration applies cleanly on a fresh DB; `INFO FOR TABLE activity_execution_traces` shows the new optional fields; the schema parser accepts traces carrying `failure_mode.type = "prediction_disagreement"` with any of the three sub-cases.

- [ ] **1.6** — Wire the three Phase 1 activities into `bun run cli seed-templates` and verify they register cleanly against the local substrate. **Acceptance:** `make -C scripts/substrate substrate-restart-development-vessel` followed by `curl localhost:18080/v2/activities/templates?id=observe-obsidian-events` returns the registered template; same for the other two.
