Add a name dimension to the maintenance lease in repos/development-vessel/src/resolvers/maintenance-lease.ts (openspec 2026-09-24-resumable-landings task 3.1, spec change-window-names). All changes in this one file:
(1) Add optional `name?: string` to both MaintenanceLeaseReadPointer and MaintenanceLeaseWritePointer.
(2) Add `export function namedLeasePath(name?: string): string` — no name returns leasePath() unchanged; a name returns join(dirname(leasePath()), `maintenance-${safe}.json`) where safe = name.replace(/[^a-z0-9_-]/gi, "_"). readLease/writeLease/deleteLease take an optional `name` and use namedLeasePath(name).
(3) Add `async function listHolds()` that readdir()s dirname(leasePath()), reads every file matching /^maintenance(-.+)?\.json$/ (never .tmp), and returns the unexpired leases each tagged with `name` (null for maintenance.json).
(4) acquire: a NAMED acquire is refused ({acquired:false, held_by, expires_at, name}) if the same name is held by a different holder OR the unnamed maintenance.json is held (unexpired) by a different holder; an UNNAMED acquire is refused if ANY unexpired hold (unnamed or named) has a different holder. On success write namedLeasePath(name) and include `name` in the result body.
(5) renew/release: with a name, operate on that name's file. Release WITHOUT a name stays backward compatible: if maintenance.json does not carry the token, search the named holds from listHolds() for the token and delete that file; report token_mismatch only if no file carries it; `already_absent` when no lease file exists at all.
(6) resolveMaintenanceLease: with pointer.name answer held:true when THAT name is held OR the unnamed maintenance.json is held (an unnamed hold means everything, for readers as for acquirers — services/gap-drain-observer.ts already reads with name "trace_store" and name "change_window" and must keep seeing the global hold), reporting the matching hold's holder/expires_at plus `name`; without a name answer for the UNION — held:true if any hold exists, keep top-level holder/acquired_at/expires_at from the first hold (unnamed first) so existing readers keep working, and add `holds: [{name, holder, acquired_at, expires_at}]`.
Callers passing no name must behave exactly as today; the maintenance.json file format is unchanged (activity-api's db-admin route reads that file directly). Falsifier: named `trace_store` and named `cutover` acquires by different holders both succeed and the unnamed read lists both in `holds`; an unnamed hold makes a named acquire return acquired:false with held_by = the unnamed holder.
