# Tasks — Phase 2 substrate permissive activity authoring

Goal: an operator-triggered `draft-activity-from-pattern` call takes a hand-built `recurringPatternCluster` and produces a passing template. Pattern auto-detection is Phase 3.

- [ ] **2.1** — Implement `draft-activity-from-pattern` in `repos/development-vessel/src/seed/draft-activity-from-pattern.ts`. Iterative two-step prompt: (a) prune-vocabulary task selects a subset of the resolver + activity vocabularies given the pattern cluster, (b) draft task produces an `authoredActivityCandidate` against the pruned set. Inputs per umbrella design §7.5: `recurringPatternCluster`, `actionEffectModel`, `resolverVocabulary`, `activityVocabulary`. **Acceptance:** given a hand-built `recurringPatternCluster` for "open file → make small edit → save", the drafter produces a candidate that (a) declares its own `inputShapes`/`outputShapes`, (b) carries non-empty `authored_from_pattern.pattern_id` and `observation_window`, (c) cites ≥ 1 concept id when the pattern carries `n_concept_citations_available > 0`.

- [ ] **2.2** — Implement `comprehensibility_check` resolver in `repos/metabob-activity-api/src/resolvers/comprehensibility-check.ts` as a sibling of `convergent_validity_check`. Procedure: send the template body **without** its self-description to an evaluator LLM (second provider where available), ask "what does this do; why might it have been authored; what would have to be true for it to be useful"; compare semantically against the template's self-description; emit a `comprehensibilityScore` impulse with `score ∈ [0, 1]`, `evaluator_model_id`, and `reasoning_diff`. **Acceptance:** for the Phase 2.1 candidate, the resolver returns a `comprehensibilityScore` with `score ≥ 0.6` using a different model provider from the drafter; templates below floor are refused promotion and `verifier_negative.comprehensibility_below_floor` is emitted.

- [ ] **2.3** — Install registration-time invariants in the template registration path at `repos/metabob-activity-api/src/routes/activities.ts`: (a) every declared `inputShape` has a known producer or is marked `seedable: true`, (b) every compose-dispatch reference resolves to an existing activity, (c) `max_composition_depth ≤ 16`, (d) every compose-dispatch task carries a `composition_rationale` entry with `rationale_class` ∈ `{essential, replaceable, accidental}` and non-empty `rationale_text`, (e) `authored_from_pattern.pattern_id` resolves to a stored `recurringPatternCluster`. All five emit `verifier_negative.activity_registration_invariant` on failure. **Acceptance:** five unit-test fixtures (one per invariant) each trigger the expected rejection; one positive fixture passes all five.

- [ ] **2.4** — Enforce the comprehensibility discipline inside the drafter prompt body with worked examples for each of the five rules (self-describing names, substantive descriptions, citations, composition rationales, provenance markers). Reference citation form: `service_oom_cascade_scan` cites `concept_RYl73llSCGfc`, `concept_6RwK5H5F28hT`. **Acceptance:** the drafter refuses to emit a candidate that violates any of the five rules and instead writes `verifier_negative.authoring_discipline_violation`; a positive fixture demonstrating all five rules satisfied emits cleanly.

- [ ] **2.5** — Periodic re-check schedule: `comprehensibility_check` re-runs each authored template every 7 days using a second model provider where configured. Configurable via env (`COMPREHENSIBILITY_RECHECK_INTERVAL_DAYS`, `COMPREHENSIBILITY_RECHECK_PROVIDERS`); default enabled with `7` and the providers configured in `~/.metabob/config.json`. **Acceptance:** integration test simulates two consecutive re-checks; the second selects a provider different from the previous `evaluator_model_id` when an alternative is available; writes a fresh `comprehensibilityScore` on each pass.
