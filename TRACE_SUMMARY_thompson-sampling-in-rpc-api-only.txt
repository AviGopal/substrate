DATA FLOW (CURRENT vs DESIRED)
================================================================================

CURRENT (Violates Boundary):
1. Activity tool → TemplateSelector.select()
2. Load template from repository
3. IF candidates exist:
   a. performThompsonSampling()  ← VIOLATION
   b. Fetch alpha/beta from metrics  ← VIOLATION
   c. For each variant: betaSample(alpha, beta)  ← VIOLATION
   d. Select highest sample  ← VIOLATION
4. Load selected template

DESIRED (Clean Separation):
1. Activity tool receives activity_id
2. HTTP POST /v2/activities/templates/{activity_id}/select  ← CORRECT
3. RPC API performs Thompson Sampling (already implemented)
4. RPC API returns selected template + metadata
5. OpenCode receives template from API
6. OpenCode executes activity

Benefits:
- Clean separation: ML in rpc-api, execution in opencode
- Single source of truth for selection algorithm
- No need to expose raw metrics to opencode
- Easier to update sampling algorithm
- Reduced complexity in OpenCode
