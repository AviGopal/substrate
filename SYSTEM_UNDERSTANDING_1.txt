  Current Schema State

  1. Core Schema (metabob-proto/surrealdb/core/)

  Multi-tenant foundation with three auth mechanisms:

  - organizations - tenant isolation root
  - users - dashboard/web users
  - api_keys - IDE integrations, CLI tools (RECORD auth)
  - minibob_instance - autonomous vessels (RECORD auth)
  - projects - project-level isolation
  - subscriptions, connection_slots - billing/resource limits

  Auth ACCESS definitions:
  - jwt_external - HS256 JWT for dashboard users (15min tokens)
  - minibob_record - RECORD auth for autonomous instances (24h tokens)
  - apikey_record - RECORD auth for API keys (15min auto-refresh)

  2. Activity Schema (metabob-activity-api/sql/001-init-schema.surql)

  Learning system tables:

  - activity_template - template variants with task_steps, hierarchical tags
  - variant_performance_metrics - Thompson Sampling (alpha/beta), success rates
  - activity_executions - execution traces with impulses, state transitions

  Key insight: All activity tables have PERMISSIONS clauses that enforce WHERE 
  org_id = $auth.org_id - database-level RBAC.

  3. Learning System - Thompson Sampling, pattern matching, ribosome extraction
  4. Multi-tenant Isolation - all queries scoped by JWT claims via PERMISSIONS

  Core Responsibilities

  The vessel should:

  1. Manage connections with proper auth context propagation
  2. Provide resolvers for activity-related impulse types
  3. Expose MCP tools for query execution, not REST endpoints
  4. Handle migrations idempotently via schema_version table
  5. Enforce RBAC through authenticated clients, never root

  The vessel should NOT:

  - Be a universal resolver (only activity-related impulses)
  - Provide REST endpoints (use MCP tools instead)
  - Store business logic (keep it thin, database-focused)
  - Bypass PERMISSIONS (always use authenticated clients)

  Key Design Patterns

  1. Auth-Aware Client Factory

  // src/auth/client-factory.ts
  export class AuthClientFactory {
    async createClient(authToken: string): Promise<Surreal> {
      const db = new Surreal();
      await db.connect(config.url);
      await db.use({ namespace: config.namespace, database: config.database });
      await db.authenticate(authToken); // Populates $auth for PERMISSIONS
      return db;
    }

    // For root operations ONLY (migrations, health checks)
    async createRootClient(): Promise<Surreal> {
      const db = new Surreal();
      await db.connect(config.url);
      await db.signin({ username: 'root', password: config.rootPassword });
      await db.use({ namespace: config.namespace, database: config.database });
      return db;
    }
  }

  2. MCP Tools (not REST endpoints)

  // src/tools/query.ts
  export const queryTool = {
    name: 'surreal_query',
    description: 'Execute authenticated SurrealQL query',
    inputSchema: {
      type: 'object',
      properties: {
        sql: { type: 'string' },
        params: { type: 'object' },
        authToken: { type: 'string' } // JWT from caller
      },
      required: ['sql', 'authToken']
    },
    async execute({ sql, params, authToken }) {
      const client = await authClientFactory.createClient(authToken);
      try {
        const result = await client.query(sql, params);
        return { success: true, data: result[0] };
      } finally {
        await client.close();
      }
    }
  };

  3. Impulse Resolvers

  // src/resolvers/activity-template.ts
  export async function resolveActivityTemplate(
    impulse: Impulse,
    authToken: string
  ): Promise<ResolvedImpulse> {
    const { variant_id } = impulse.pointer;

    const client = await authClientFactory.createClient(authToken);
    try {
      // PERMISSIONS automatically filter by $auth.org_id
      const result = await client.query(
        'SELECT * FROM activity_template WHERE variant_id = $variant_id',
        { variant_id }
      );

      return {
        ...impulse,
        content: formatTemplate(result[0]),
        loaded: true
      };
    } finally {
      await client.close();
    }
  }

  4. Schema Migration Tool

  // src/tools/migrate.ts
  export const migrateTool = {
    name: 'surreal_migrate',
    description: 'Apply schema migrations idempotently',
    async execute() {
      const rootClient = await authClientFactory.createRootClient();
      try {
        // Check schema_version table
        const applied = await rootClient.query(
          'SELECT version FROM schema_version WHERE migration_type = $type',
          { type: 'activity' }
        );

        // Apply unapplied migrations
        for (const migration of migrations) {
          if (!applied.includes(migration.version)) {
            await rootClient.query(migration.sql);
            await rootClient.query(
              'CREATE schema_version CONTENT $content',
              { content: { version: migration.version, ... } }
            );
          }
        }
      } finally {
        await rootClient.close();
      }
    }
  };

  4. SurrealDB 3.x Schema Patterns

  DEFINE TABLE example SCHEMAFULL
    PERMISSIONS
      FOR select WHERE org_id = $auth.org_id
      FOR create WHERE $auth != NONE

      FOR delete WHERE org_id = $auth.org_id AND $auth.role = 'admin';

    VALUE $value OR $auth.org_id;  -- Auto-populate from JWT

  Computed Views with GROUP BY:
  -- Event-based materialized view (SurrealDB 3.x)
  DEFINE TABLE view AS
    SELECT
      activity_id,
      COUNT() AS executions,
      SUM(success) AS successes,
      AVG(duration_ms) AS avg_duration
    FROM activity_executions
    GROUP BY activity_id;

  Graph Relationships:
  -- Relation tables (easier queries)
  DEFINE TABLE impact_relations SCHEMAFULL;
  DEFINE FIELD from_component_id ON impact_relations TYPE string;
  DEFINE FIELD to_component_id ON impact_relations TYPE string;

  -- Graph edges (idiomatic SurrealDB)
  DEFINE TABLE depends_on SCHEMAFULL TYPE RELATION
    FROM code_components
    TO code_components;

  Decision: Start with relation tables, migrate to graph edges if performance
  requires.

  async function resolveActivityRecommendation(
    pointer: any,
    metadata: any,
    authToken: string
  ): Promise<ResolvedImpulse> {
    const db = await createAuthenticatedClient(authToken);

    try {
      // Step 1: Query activities matching available shapes
      const matchingActivities = await db.query(`
        SELECT * FROM activity
        WHERE input_shapes ALLINSIDE $available_shapes
          AND org_id = $auth.org_id
        LIMIT 50
      `, {
        available_shapes: pointer.available_impulse_shapes
      });

      // Step 2: Get scores from learning view
      const scores = await db.query(`
        SELECT * FROM v_activity_score
        WHERE activity_id IN $activity_ids
      `, {
        activity_ids: matchingActivities.map(a => a.activity_id)
      });

      // Step 3: Thompson Sampling selection
      const recommendations = thompsonSample(
        matchingActivities,
        scores,
        metadata.exploration_weight,
        metadata.limit
      );

      // Step 4: Return resolved impulse
      return {
        ...impulse,
        loaded: true,
        content: {
          recommendations: recommendations.map(r => ({
            activity_id: r.activity_id,
            variant_id: r.variant_id,
            variant_name: r.variant_name,
            score: r.score,
            confidence: r.confidence,
            reasoning: r.reasoning,
            input_shapes: r.input_shapes,
            output_shapes: r.output_shapes
          })),
          selection_metadata: {
            total_candidates: matchingActivities.length,
            exploration_count: recommendations.filter(r =>
  r.exploratory).length,
            exploitation_count: recommendations.filter(r =>
  !r.exploratory).length,
            timestamp: new Date().toISOString()
          }
        }
      };
    } finally {
      await db.close();
    }

      for (const [id, lastAccess] of this.lastAccessed) {

          if (impulse?.priority === 'low') {

      const vessel = vesselRegistry.find(v =>
        v.resolves.includes(impulse.shape)
      );

      if (!vessel) {
        throw new Error(`No vessel can resolve shape: ${impulse.shape}`);
      }

      // Delegate to vessel
      return await this.mcpClient.callTool(
        vessel.mcp_endpoint,
        'impulse_resolve',
        { impulse, authToken: this.getToken() }
      );
    }
  }

  Benefits:
  - Decoupled: MiniBob doesn't know vessel URLs
  - Dynamic: New vessels can register new shapes
  - Declarative: "I need this shape" vs "Call this URL"
  - Evolvable: Can add vessels without changing client code

  class ActivityComposer {

      const availableShapes = this.stateSpace.getShapes();
      const activities = await this.getActivitiesByShapes(availableShapes);

      // Step 2: Execute selected activity
      const result = await this.execute(activities[0]);

      // Step 3: If failed, output shapes automatically trigger next activity
      if (!result.success) {

        const traceImpulse = this.createTraceImpulse(result);
        this.stateSpace.add(traceImpulse);

        // Automatically matches debugFailureActivity!

        // Get activities matching NEW shape set
        const nextActivities = await this.getActivitiesByShapes(
          this.stateSpace.getShapes()  // Now includes trace shape
        );

        // debugFailureActivity will be in recommendations
        // because it matches input_shapes: ["activityExecutionTrace"]
        await this.execute(nextActivities[0]);
      }
    }
  }

  Characteristics:
  - Emergent workflows (shape matching determines flow)
  - Activities declare what they need, not how to get it
  - Backend aware of composition (can optimize)
  - Learning improves composition over time

  Vessel/Impulse: Graceful Degradation

  async function resolveWithFallback(impulse: Impulse): Promise<Impulse> {
    try {
      // Try primary vessel
      return await vesselResolver.resolve(impulse, { timeout: 5000 });
    } catch (error) {
      // Vessel 1 failed, try alternative resolver
      logger.warn('Primary vessel failed, trying fallback', { error });

      try {
        // Try secondary vessel
        return await fallbackResolver.resolve(impulse);
      } catch (fallbackError) {
        // All remote resolvers failed
        logger.error('All vessels failed, using local fallback');

        // Option 1: Use cached content
        const cached = this.cache.get(impulse.id);
        if (cached) {
          return { ...impulse, loaded: true, content: cached, stale: true };
        }

        // Option 2: Use bootstrap/default activity
        if (impulse.shape === 'activityRecommendationRequest') {
          return {
            ...impulse,
            loaded: true,
            content: {
              recommendations: [getBootstrapActivity()],
              fallback: true,
              warning: 'Using default activity due to vessel unavailability'
            }
          };
        }

        // Option 3: Return unloaded impulse with error metadata
        return {
          ...impulse,
          loaded: false,
          error: {
            message: 'All resolvers failed',
            retriable: true,
            fallback_available: false
          }
        };
      }
    }
  }

  Benefits:
  - Multiple resolution strategies
  - Partial success possible (stale cache better than nothing)
  - Explicit error metadata
  - Client can decide how to handle unloaded impulses

  ---
  Key Insight: From Services to Capabilities

  REST thinking: "The backend is a service I call to get work done"

  Vessel thinking: "Vessels provide capabilities to resolve specific shapes of
  data I need"

  This shift enables:
  - Distributed resolution: Multiple vessels, each expert in different shapes
  - Emergent composition: Activities find each other via shape matching
  - Transparent learning: Selection rationale visible in impulse metadata
  - Graceful evolution: Add new shapes/vessels without breaking existing ones

  The vessel/impulse architecture treats data (impulses) as first-class citizens
   that flow through a network of specialized resolvers (vessels), rather than
  treating the backend as a central orchestrator that clients must call.

  Version-Aware Resolution

  class ImpulseResolver {
    async resolve(impulse: Impulse): Promise<Impulse> {
      const shapeVersion = impulse.shape_version || "1.0";

      // Find vessel that supports this shape + version
      const vessel = vesselRegistry.find(v =>
        v.capabilities.some(c =>
          c.shape === impulse.shape &&
          c.shape_version === shapeVersion
        )
      );

      if (!vessel) {
        // Try to find vessel with backward compatibility
        const legacyVessel = vesselRegistry.find(v =>
          v.capabilities.some(c =>
            c.shape === impulse.shape &&
            c.deprecated !== true
          )
        );

        if (legacyVessel) {
          logger.warn('Using legacy resolver', {
            shape: impulse.shape,
            requested_version: shapeVersion,
            vessel_version: legacyVessel.version
          });
          return await this.resolveViaVessel(legacyVessel, impulse);
        }

        throw new Error(
          `No vessel can resolve ${impulse.shape}:${shapeVersion}`
        );
      }

      return await this.resolveViaVessel(vessel, impulse);
    }
  }

  2. Primary Interaction: Vessel Executes Activity

  Step-by-Step Execution Flow

  // MiniBob Vessel executing an Activity Template

  class MiniBobVessel {
    // Vessel's execution engine
    async executeActivity(
      template: ActivityTemplate,
      impulseStateSpace: ImpulseStateSpace
    ): Promise<ExecutionResult> {

      // STEP 1: Vessel prepares execution environment
      const executionContext = {
        session_id: this.sessionId,
        working_directory: this.workingDir,
        available_tools: this.getAvailableTools(),
        impulse_state_space: impulseStateSpace
      };

      // STEP 2: Load input impulses (resolve pointers)
      const inputImpulses = await this.loadInputImpulses(
        template.input_shapes,
        impulseStateSpace
      );

      // STEP 3: Execute each task in sequence
      const taskResults = [];
      for (const task of template.task_steps) {

        // STEP 3a: Vessel formats prompt with impulse content
        const prompt = this.formatPrompt(task.prompt, inputImpulses);

        // STEP 3b: Vessel calls LLM (if needed for this task)
        const llmResponse = await this.llm.complete(prompt, {
          tools: this.getToolsForTask(task)
        });

        // STEP 3c: Vessel executes tool calls requested by LLM
        const toolResults = [];
        for (const toolCall of llmResponse.tool_calls) {
          const result = await this.executeTool(toolCall);
          toolResults.push(result);
        }

        // STEP 3d: Collect task result
        taskResults.push({
          task_id: task.id,
          tool_calls: toolResults,
          success: this.validateTask(task, toolResults)
        });

        // STEP 3e: Update impulse state space (activity creates impulses)
        const newImpulses = this.extractImpulsesFromToolCalls(toolResults);
        impulseStateSpace.addAll(newImpulses);
      }

      // STEP 4: Create output impulses
      const outputImpulses = this.createOutputImpulses(
        template.output_shapes,
        taskResults
      );

      // STEP 5: Vessel stores execution trace
      await this.storeExecutionTrace({
        activity_id: template.activity_id,
        variant_id: template.variant_id,
        input_impulses: inputImpulses.map(i => i.id),
        output_impulses: outputImpulses.map(i => i.id),
        tasks: taskResults,
        success: taskResults.every(t => t.success),
        duration_ms: Date.now() - startTime
      });

      return {
        success: taskResults.every(t => t.success),
        output_impulses: outputImpulses,
        trace: taskResults
      };
    }
  }

  Pattern 3: Retry as Impulse Evolution

  // Traditional retry with exponential backoff
  async function retryWithBackoff(operation, maxAttempts = 3) {
    for (let attempt = 1; attempt <= maxAttempts; attempt++) {
      try {
        return await operation();
      } catch (error) {
        if (attempt === maxAttempts) throw error;
        await sleep(Math.pow(2, attempt) * 1000);
      }
    }
  }

  // Impulse architecture: Retry creates new impulse with metadata
  async function resolveWithRetry(impulse: Impulse, maxAttempts = 3): 
  Promise<Impulse> {
    const attempts = [];

    for (let attempt = 1; attempt <= maxAttempts; attempt++) {
      try {
        const resolved = await vessel.resolveImpulse(impulse);

        // Success - return with attempt metadata
        return {
          ...resolved,
          metadata: {
            ...resolved.metadata,
            resolution_attempts: attempts.length + 1,
            retry_history: attempts
          }
        };

      } catch (error) {
        // Record attempt
        attempts.push({
          attempt_number: attempt,
          error_type: error.name,
          error_message: error.message,
          attempted_at: new Date().toISOString()
        });

        if (attempt < maxAttempts) {
          // Create retry impulse (visible in state space)
          const retryImpulse = {
            id: `${impulse.id}-retry-${attempt}`,
            shape: "retry",
            pointer: {
              type: "retry",
              original_impulse_id: impulse.id,
              attempt_number: attempt,
              next_attempt_delay_ms: Math.pow(2, attempt) * 1000
            }
          };

          stateSpace.add(retryImpulse);
          await sleep(Math.pow(2, attempt) * 1000);
        } else {
          // All retries exhausted - create error impulse
          const errorImpulse = {
            shape: "error",
            pointer: {
              error_type: "RetryExhausted",
              original_impulse_id: impulse.id,
              attempts: attempts
            }
          };

          stateSpace.add(errorImpulse);

          // Return unloaded impulse with error metadata
          return {
            ...impulse,
            loaded: false,
            error: {
              message: "All retry attempts failed",
              attempts: attempts
            }
          };
        }
      }
    }
  }

  // Resolver implements the strategy
  async function resolveWithFallbackChain(impulse: Impulse): Promise<Impulse> {
    const strategy = impulse.metadata.resolution_strategy;
    const attempts = [];

    // Try primary
    try {
      return await resolveVia(strategy.primary, impulse);
    } catch (primaryError) {
      attempts.push({ resolver: strategy.primary.resolver, error: primaryError
  });

      // Try fallbacks in order
      for (const fallback of strategy.fallbacks) {
        // Check if this error triggers this fallback
        if (shouldTriggerFallback(primaryError, fallback.trigger_on)) {
          try {
            const resolved = await resolveVia(fallback, impulse);

            // Success with fallback - add metadata
            return {
              ...resolved,
              metadata: {
                ...resolved.metadata,
                resolved_via: fallback.resolver,
                fallback_used: true,
                primary_failure: primaryError.message,
                stale: fallback.stale_ok
              },
              warnings: fallback.warning ? [fallback.warning] : []
            };

          } catch (fallbackError) {
            attempts.push({ resolver: fallback.resolver, error: fallbackError
  });
            continue;
          }
        }
      }

      // All resolvers failed - create error impulse
      const errorImpulse = {
        shape: "error",
        pointer: {
          error_type: "AllResolversFailed",
          original_impulse_id: impulse.id,
          attempts: attempts
        }
      };

      stateSpace.add(errorImpulse);

      return {
        ...impulse,
        loaded: false,
        error: { message: "All resolvers failed", attempts }
      };
    }
  }

  Summary: Error Handling Philosophy

  Traditional Paradigm: Errors Are Exceptions

  Normal Flow: A → B → C → D → Success
  Error Flow:  A → B → X → ERROR
               (B threw exception, C and D never execute)

  Characteristics:
  - Errors interrupt control flow
  - Context is lost
  - Recovery is separate from main logic
  - No learning from failures

  Impulse Paradigm: Errors Are Data

  Flow with Error:
    Goal → Activity1 → File ✓ → Activity2 → Error ✗
                                                ↓
    State Space: [Goal, File, Error]
                                                ↓
    Activity Matching finds: ErrorRecoveryActivity
                                                ↓
    ErrorRecoveryActivity → Alternative File ✓ → Success

  Characteristics:
  - Errors are impulses in state space
  - Full provenance maintained (error references original impulse)
  - Recovery is activity matching (same mechanism as normal flow)
  - Learning from errors (create better activities)
  - Non-determinism is recorded (Thompson Sampling samples are logged)
  - Retry/fallback strategies are data (not hard-coded)

  Key Advantages

  1. Composability: Error handling activities compose like any other activity
  2. Observability: Error impulses visible in state space, full trace available
  3. Learning: Failed executions improve future attempts
  4. Flexibility: Resolution strategies configurable via metadata
  5. Graceful Degradation: Fallback chains enable partial success
  6. Reproducibility: Non-deterministic choices logged for replay

  The impulse architecture treats errors as first-class citizens that
  participate in the same activity/impulse/vessel flow as success cases,
  enabling emergent error handling through shape matching rather than explicit
  try/catch blocks.
