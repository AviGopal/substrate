Type:       Service Boundary
Location:   api/activity-client.ts | Metabob RPC API
Contract:   REST API (activity execution, task tracking)
Coupling:   Loose (non-blocking, graceful degradation)
Resilience: Good (3 retries, exponential backoff)
Status:     ✅ Healthy

Endpoints:

  POST   /api/v1/activity-execution/tasks    - Start task
  PATCH  /api/v1/activity-execution/tasks/:id - Update task

Resilience:

  ✅ 3 retries with exponential backoff (1s, 2s, 4s)
  ✅ Graceful degradation (logs warning, continues)

Concerns:
  - No timeout configuration
  - No circuit breaker (keeps retrying every activity)

COUPLING ANALYSIS
================================================================================

Tight Coupling (High Risk):
  - Bun runtime ($ template)
  - gh CLI (system dependency)
  - Instance.directory (implicit context)

Medium Coupling (Acceptable):
  - Session → ActivityGit (one-way, clear API)
  - K8s → Container (env vars, secrets)

Loose Coupling (Good):
  - Storage → Filesystem (abstract interface)
  - Metabob API (graceful degradation)

❌ Missing Patterns:

  - Shell commands: No timeout
